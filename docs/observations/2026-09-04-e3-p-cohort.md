**One line of learning.** On a rung purpose-built for it — 21 owners the tool discovers itself,
63 sites, a per-file alias policy with collisions — `alias_migration` produced a **byte-exact**
migration in 3 of 3 runs with **zero** native fallback, and still **failed its own pass line**,
because every tool arm's FIRST call was refused for spelling `scope.paths` as `["src"]` instead
of `["src/**"]`, and the refusal reported a domain cause for a spelling problem and carried no
executable `next_call`. One refusal class, four occurrences, four of four arms.

**One caveat.** Rung P is synthetic. sl1's standing caveat applies unchanged: a synthetic-only
result is a finding about irregular fan-out, not a product claim — and here native was not weak,
it solved the same rung correctly 3 of 3 in four to six actions with one `apply_patch`.

**A pre-registered falsifier fires:** *"`alias_migration` refuses more than 20 % of its calls on
rung P."* Measured: **4 refusals in 7 verb calls, 57 %.**

**The honest verdict: E3-P does not pass.** And the reason it does not pass is not the fan-out
economics the experiment was built to measure. Every refusal is one class:

| arm | call 1 | call 2 | call 3 |
|---|---|---|---|
| T-1 | `scope.paths ["src"]` → refused `alias-migration-empty-scope` | `["src/**","test/**"]` → committed | — |
| T-2 | `["src"]` → refused | `["src"]` → refused | `["src/**","test/**"]` → committed |
| T-3 | `["src"]` → refused | `["src/**","test/**"]` → committed | — |
| PF-5 T-0 | flat field names → refused `invalid-mcp-request` | `["src"]` → refused `alias-migration-empty-scope` | correct → committed |

```
alias_migration
  refused · alias-migration-empty-scope · 15.14 ms
✓ source unchanged
→ No namespace under scope requires acid.fanout.store
```

`scope.paths` are globs. `["src"]` matches nothing — and the refusal announces a **domain**
cause ("no namespace under scope requires acid.fanout.store") for a **spelling** cause, sets
`next_action: "correct_request"`, and carries no `remedy` and no executable `next_call`. The
agent guessed the glob on the next turn, every time, at the cost of exactly one model return.

**The ratchet this earns** (highest rung that fits, per the house rule): a scope that resolves to
zero files should either accept a bare directory path as `dir/**`, or refuse with the corrected
`next_call` in hand — *"`scope.paths` are globs; `src` matched 0 files; did you mean `src/**`?"*
An `alias-migration-empty-scope` refusal that cannot distinguish "your glob matched nothing" from
"nothing in this tree requires that lib" is a refusal that teaches the wrong lesson, and it is
worth an example test at the request boundary plus a typed distinction between the two states.
Fix that one thing and clause 1 becomes reachable without touching the verb's engine.

## What the pre-flight had to build before any of this could run, and what it found

**`~/acid` does not exist for this seat.** The pre-registration names
`~/acid/fanout/gen-fanout.clj` and `rescore-FAN.sh` as prerequisites and says E3-P does not run
without them. Both were rebuilt **into git** from the sl1 slope spec, on branch
`bridge/fanout-fixtures-in-git` (`bench/fanout/`, three commits, cut from fetched `origin/main`
`99394bf`, not pushed): a pure deterministic generator (two runs byte-identical; N=5 targets a
subset of N=21; canonical rendered from the same spec map so the oracle is derived, never
hand-written) and the six-check acceptance.

**The scorer was proved RED six ways before anything trusted it green** —
`sabotage-FAN.sh`: 7 passed, 0 failed (1 positive control + 6 sabotages), each asserting on the
named check's own FAIL line rather than on a non-zero exit. Two defects in the scorer fell out of
writing them: a residue regex keyed on the OLD alias scored 0 for an agent that migrates the
require but not the var, and one sabotage "passed" while silently failing to damage anything.

**Five defects were found by driving the thing once by hand, exactly as the pre-registration
insists (PF-4, "the cheapest thing in this document"):**

1. **A byte-exact migration failed the acceptance** because the verb writes per-file detail into
   `.clj-surgeon/` inside the worktree and the file-set check counted it as a source change. It
   would have failed all three T slots while every source byte was correct. Generated tool state
   is the `.cpcache` case; it is now ignored in the fixture, visibly and identically for both arms.
2. **The attestation refused every tool arm.** `/healthz` is served by `mcp-runtime/readiness`
   — `{ok, server, tool_runtime, tool_registry}` — not by the rich map `mcp_http_server.clj`
   writes to `ready.edn`, so three identity assertions were made against fields the server does
   not publish. healthz is now a liveness witness; identity stays bound to `ss -ltnp`,
   `ready.edn` and `/proc/<pid>/cwd`, each still refused-on-missing.
3. **Every arm exited 1 with zero returns.** The runner gives each arm a private `CODEX_HOME`,
   and codex reads its credentials from that same directory.
4. **`via_verb: 0` on an arm whose diff was byte-exact.** codex does not call an MCP tool as a
   harness action: it runs a JS `exec` sandbox and calls
   `await tools["clj-surgeon__alias_migration"]({…})` inside it. The rollout carried four
   `custom_tool_call` records named `exec` and three separate `mcp_tool_call_end` records. **A
   meter keyed on harness actions reported zero write calls through the verb — E3's primary
   observable, silently zero.** Without this fix the cohort table would have said the tool arm
   never called the tool. The harness action count is untouched (one exec is one model action,
   which is the quantity the non-test-action pass line is stated in); the verb's own witness is
   now read from `mcp_tool_call_end`, both derivations are reported, and the four typed refusals
   above became visible only because of it.
5. **On the real cfp anchor shapes, one is quietly narrowed.** A qualified symbol in
   binding-vector position migrates correctly. A **quoted fully-qualified** symbol in data
   position — `'acid.fanout.store/find-event` — comes back **alias-qualified** as
   `'store2/fetch-event`. Measured in the same worktree: it still resolves inside the defining
   namespace and `requiring-resolve` of the value from outside it now fails with *"Could not
   locate store2.clj on classpath"*. The site is counted in the receipt, so nothing is silently
   ignored — but a symbol whose whole purpose is to be resolved elsewhere had its spelling
   narrowed. Rung P contains no such shape; the cfp anchor (sl1-r) is made of them.

All three meter defects are fixed in `clj-surgeon-arms` (`bench/anvil-arms`, `77e6237` →
`89295d8`); the apparatus self-test is 389 passed / 0 failed after them. **Its README said
"Nothing here has run a live arm." Three of its five hard failures were invisible to the fake
driver, and the fourth would have printed a confident zero.**

## Deviations, recorded rather than buried

- **The server is not a reviewed sha.** `bridge/q5z-alias-migration` is not merged
  (`merge-base --is-ancestor f51ceae origin/main` → NOT-MERGED) and its tip predates the andon
  fix, so the tool arm's server is the tip **merged locally with `origin/main`** in the scratch
  clone: tip `f51ceae`, main `f3b2406`, **merge `ac1c8409`** — read back from the running server
  in every attestation. Three conflicts, all "both sides added a line in the same place", all
  resolved by UNION so neither side's feature was dropped. The andon commit `a6df86ee` is an
  ancestor of the merge.
- **The merged tree's suite is 760 tests / 6402 assertions / 1 failure.** The failure is the
  operation-algebra architecture oracle, whose expected effect inventory does not name
  `matched-basis-evidence` — a function **main's own** `intent_transaction.clj` introduces and
  `execute-change-with-context!` calls. Verified pre-existing on `origin/main`, untouched by the
  merge, and not in `alias_migration`'s path. **`origin/main` is red on that oracle today.**
- **`COHORT_PORTS` narrowed to `7907 7908`** because a foreign listener holds 7909; the
  apparatus then owns only its own two ports and records the rest in `listeners_observed`
  instead of refusing every native arm.
- Rung L was not run: this cohort is rung P only.
- The meter classified **zero** test actions in every arm although every arm ran `bin/fan-test`
  — the test-call matcher does not see a runner invoked as `tools.exec_command({cmd:"bin/fan-test"})`
  inside the sandbox. Non-test actions are therefore overstated by about one per arm, **equally in
  both arms**, and the pass line (≤ 10.5 against a measured 4.67) is nowhere near that margin.

## What this closes, and what it does not

It does **not** close the fan-out square. The square's claim is that wall can go positive where
the tool discovers the owners, and this cohort's wall gap sits inside a variance floor nobody may
argue with. What it establishes at n = 1, deterministically: on a 21-owner structural fan-out the
verb produces a byte-exact result with **one** committing call and **zero** native fallback, and
it costs **one extra model return per arm** to a refusal that is a documentation defect wearing a
domain error's clothes.

The next honest question is sl1's, not a wider E3: the **slope** (N = 5/10/20/40/80), where the
term that can actually grow — files the agent must read and cannot infer — is varied. A level at
a single N was never claimable and is not claimed here.
