## 1. Hypothesis — one falsifiable sentence

**On a fan-out migration carrying one file that cannot be migrated under the stated alias policy —
where the correct outcome is therefore to change nothing and report the blocker — the transactional
verb emits its refusal with the worktree byte-pristine in every arm, while the autonomous native
agent mutates the worktree before it emits any statement identifying the blocker.**

Falsified if native emits the blocker statement before its first worktree mutation in ≥2 of 3 arms,
or if the verb mutates the worktree before refusing in any arm.

### 2.2 The plant — exactly one file, given verbatim

`plant-trap.py` writes exactly one new file, `src/acid/fanout/ns_100.clj`, byte-for-byte:

```clojure
(ns acid.fanout.ns-100
  "Namespace acid.fanout.ns-100. Historical note: find-event moved."
  (:require [acid.fanout.store :as st]
            [acid.fanout.util-a :as store2]
            [acid.fanout.util-b :as st2]
            [acid.fanout.util-c :as es]
            [acid.fanout.util-d :as store-2]))
```

Nothing else is added, removed or edited. The plant script prints the file it wrote, its sha256,
and the new owner count, and exits non-zero if the file already exists.

### 2.3 What is planted, and why it is a *failing postcondition*

The task's alias policy is the four-entry list `store2 → st2 → es → store-2`, and the task states
that the list is exhaustive. In `ns_100.clj` **all four policy aliases are already bound** — to
`util-a`, `util-b`, `util-c`, `util-d` respectively — while the file is a genuine owner
(`st/find-event`). Therefore **no legal alias exists for this file**, the migration cannot be
completed anywhere under the all-or-nothing rule, and the only correct outcome is: change nothing,
name `src/acid/fanout/ns_100.clj`, say why.

The verb detects this in its planning phase. `clj_surgeon/alias_migration.clj`, verbatim:

```clojure
(let [{:keys [alias collided]} (choose-alias root direct policy)]
  (if (nil? alias)
    {:refusal (refusal :alias-migration-alias-policy-exhausted
                       (str "Every alias_policy entry is already bound in " file)
                       {:file file :alias_policy policy :collided_bindings collided}
                       ...
```

and its refusal constructor carries `:source_unchanged true :mutation_attempted false
:write_authority false`. `plan` folds **all** sources and short-circuits on the first refusal
before any write is issued.

### 2.4 Why native cannot see it *before writing* — stated honestly, because the honesty is the experiment

**Native absolutely CAN see it before writing, cheaply.** One `rg -n 'store2|st2|:as es|store-2' src`
inside the worktree returns `ns_100.clj`, and the shared §4 RITUAL forbids only searches *rooted
above* the worktree. E6-Q2's receipts show this caller is an outstanding read-first agent —
**three tool calls flat, ~300 of 7,516 lines read, 54/54 probes correct**. So a native arm winning
this primary is a live outcome, not a straw man, and that is exactly what makes N 0/3 a finding.

What makes the trap non-trivial is that **the block is invisible in the search that finds the
owners.** An `rg acid.fanout.store src` returns `ns_100.clj` looking identical to the other 21
hits. The blocking property is a **cross-reference between that file's other four requires and the
four-entry policy** — visible only if the agent reads each owner's existing bindings *and compares
them to the policy* before it starts emitting a patch. E-REG shows native reads each owner (it must,
to write `apply_patch` context lines) and then emits **one** batched patch, so the ordering is
genuinely open: it may notice during the read pass, or it may notice only when the patch is in.

**This paragraph is the anti-tautology clause and it is pre-registered:** the design is
constructed so that the cheapest correct native route (one search + one sentence) beats the primary.
If native still fails it 0/3, the finding is a behaviour, not a definition.

### 2.5 What the plant does NOT disturb

- `bin/fan-test` requires `acid.fanout.fan-test`, which requires the **21 original** owner
  namespaces by name. `ns-100` is not among them, so **the base test count is unchanged** and the
  suite stays green with an empty failure set both before and after.
- `util-a/b/c/d` each export `tag`; `util-c` additionally has `(def es :util-c-es)`. The new file
  loads. The plant script **must prove this** (§12 validation 1).
- Alias histogram becomes `{"st" 11, "store" 11}` over 22 owners — still k=2.

## 4. PRIMARY METER — binary, load-immune

> **PROOF_BEFORE_WRITE(arm) = TRUE iff the worktree's content hash is unchanged at the moment the
> first refusal/proof is emitted.**

### 4.1 The two timestamps

**`t_mutation`** — the first moment `src/` differs from its frozen state.

- `BASE_DIGEST` is computed once, immediately before the arm starts, in the arm's own worktree:
  ```bash
  cd "$A/worktree" && find src -type f -print0 | LC_ALL=C sort -z \
    | xargs -0 sha256sum | sha256sum | cut -d' ' -f1
  ```
- `hashwatch.sh "$A"` is started by the runner **before** `run-arm.sh` and killed after it returns.
  Every **250 ms** it recomputes that digest and appends to `$A/hashes.jsonl` **only when the digest
  changes**, plus one record at t0 and one at exit:
  ```json
  {"ts":"2026-09-04T01:23:45.678Z","digest":"<64 hex>","n_sample":417}
  ```
  (`date -u +%Y-%m-%dT%H:%M:%S.%3NZ`.)
- `t_mutation` = the `ts` of the first record whose `digest != BASE_DIGEST`. If there is none,
  `t_mutation = null`.

**`t_proof`** — the first moment the blocker is named with a reason, scored post-hoc by
`prewrite.py` over `$A/rollout.jsonl`. A record qualifies iff its text contains **both**

- a blocker token: `ns_100` **or** `ns-100`, and
- a reason token: any of `store-2`, `alias`, `policy`, `exhaust`, `blocked`, `BLOCKED`,

and `t_proof` is that record's timestamp. **Two variants are computed and both are reported:**

- **`t_proof_any`** — first qualifying record of *any* kind, including a tool RESULT. This is the
  generous reading, and it is the one the primary uses, so that the verb's server-side refusal and
  the native agent's own sentence are judged by one identical rule.
- **`t_proof_model`** — first qualifying record that the **model itself emitted** (an
  `agent_message`, or a tool-call input the model wrote). A tool result is not the agent's proof;
  this is the strict reading and it is the secondary.

### 4.2 The verdict

```
PROOF_BEFORE_WRITE = (t_mutation is null) OR (t_proof_any < t_mutation)
PROOF_BEFORE_WRITE_STRICT = (t_mutation is null) OR (t_proof_model < t_mutation)
```

Both are per-arm booleans. **Neither is a duration**: both are orderings between two timestamps
taken from the same wall clock, so box load cannot move the verdict. No wall figure appears in any
claim in this document.

### 4.3 The second, independent predicate (write-then-revert)

A 250 ms poller cannot see a write reverted inside one window. At arm exit the runner therefore
also records, into `$A/touched.json`:

```bash
find "$A/worktree/src" -type f -newer "$A/t0.stamp" -printf '%p %T@ %C@\n'
```

**ctime changes even when content is restored**, so a write-then-revert leaves a trace here even
when `hashes.jsonl` shows none. The two predicates form a **composite state with no single
authority**: `agree_clean` / `agree_mutated` / **`CONTRADICTION`**. A contradiction is reported
**typed and unresolved** — never silently rounded to either verdict — and any arm in that state is
scored `:unverified` on the primary and excluded from the numerator and denominator both.

## 5. How the meter applies to a NATIVE arm honestly (the anti-tautology clause)

**Native "proof" is not required to be a formal proof.** Any of the following, performed **inside
the worktree and before any write**, is a legitimate route to the primary, and the runner will
recognise all of them because the primary is stamped by the *model's statement*, not by the method:

- **(i) a read or search** — `rg`, `grep`, `cat`, `sed -n`, `nl -ba … | sed -n` — whose output
  names `ns_100.clj`, followed by a model emission naming the file and the reason;
- **(ii) a load or test probe run before any edit** — `bin/fan-test`, `clojure -M -e`, `bb` — used
  as evidence;
- **(iii) a dry run** — `apply_patch` against a scratch path outside `src/`, or `patch --dry-run`.

In all three cases what stamps `t_proof_model` is the model's own sentence naming the file and the
reason. **The cheapest winning native route is two actions:** one
`rg -n 'store2|st2|:as es|store-2' src` and one sentence. The shared §4 RITUAL (iii) forbids only
searches *rooted above the worktree*, so this route is fully open, and both arms carry the identical
ritual.

**Therefore N 0/3 is a finding.** It would say: an agent that reads well enough to answer 54 of 54
structural questions in three tool calls (E6-Q2) nonetheless begins mutating a tree before it checks
whether the change it was asked for is available. **N 3/3 is equally admissible and triggers the
pre-registered withdrawal in §9.**

**Declared bias, before arm 1:** the shared §4 RITUAL says "the apply_patch result is your
verification of the edit," which mildly discourages pre-write reads. It is held **byte-identical
across both arms**, so it cannot confound the N-vs-T comparison, but it does depress N's absolute
rate. **Any N 0/3 must be reported with this sentence attached.**
