## What the agent would have got if it had called it (PF-4, hand-driven)

PF-4 drove `inspect_clojure mode="ls-tree"` by hand against a rung-Lb worktree before any arm
ran. Two things it found, both worth carrying:

- **The refusal contract is honest.** At the default limit the receipt is bounded
  (`2 of 10 files`, `read_complete=false`, `→ raise_limit_or_narrow_scope`); at the maximum
  limit 16384 it emits `→ narrow_scope` and **does not serve back the call just made**, which
  is what `MCP-OP-STUDY-007` requires and what a loop here would have cost an arm-run.
- **The text a client renders is a 3-line header; the table of contents is not in it.** The
  `content[0].text` block is 146 characters — a header and a truncation notice, with zero
  rows. The actual tree (namespace, requires, every top-level form with arglist and line
  span) is in `structuredContent.tree`. Any client that surfaces only the text block hands
  the agent a header with no content. That is a candidate mechanism for the decline, and it
  is a cheap fix to test: render rows into the text block, or spend the payload budget on
  rows rather than on a header the caller already knows.

## One line of learning, and one caveat

**Learning:** an agent that already knows what to do does not shop for a table of contents.
Rung Lb removed the owner map, and Sol still closed the task in **3–5 model returns and 7–8
tool calls** by going straight to `rg` — the discovery the exposure was built to make cheap
was already cheap enough that a second route was not worth one turn. The ritual-strip block is
doing more work here than any tool could: 157 s and 8 actions for a 21-site, 11-namespace
refactor across ten files, correct on the first try, in both arms.

**Caveat:** rung Lb is not a blind rung. C.2 keeps clauses 3 and 4 byte-identical, and those
clauses still name eight of the ten owner namespaces in prose — so the removed discovery was
the exact `file:line` map, not the fact that `auth`, `channel`, `sse-registry`,
`reducer-session`, `bridge3-new`, `director-control`, `reducer.shadow` and `reducer-lab` are
involved. Only `blob` and `codex-app-server` were genuinely unnamed. A rung that actually
required workspace-wide discovery would be a different and fairer test of `ls-tree`, and this
cohort does not rule on it. What it does rule on is the pre-registered question: on this rung,
with this caller, offered neutrally, the tool was **declined 3 of 3**.
