## Schedule and meter

Fresh serial subjects: six native variance controls per model, alternating model
order, followed by six native/tool pairs per model in mirrored order. Exact schedule
is frozen in `schedule.json` and hashed in `frozen.json` before the first timed run.
Models are requested as gpt-5.6-sol and gpt-6-astra, high effort, Codex 0.153.3.
The adapted existing adapter binds resolved model and session to the full rollout;
the existing watcher counts returns and calls, not the model's self-report.

Headline clock starts before server startup and adapter dispatch and ends after
independent acceptance and frozen artifact identity. Fixture provisioning and external
resource queue are preparation, recorded separately; server startup is charged.
One-second load samples cover each interval. A sample above load 10 marks a row
contaminated, retained and ineligible for a clean timing claim. Startup-excluded
time, if reported, is descriptive. Same CPU affinity in both arms.

Prompt, runner, watcher, scorer, oracle and schedule hashes are frozen; server ready
map, listener PID/cwd, source SHA and health bind the tool subject. Full rollouts,
service events, all-file diff, source/protected hashes and terminal acceptance stay
retained. Instrument failure stops further subjects. Task refusals/failures stay in
the denominator; do not relabel them as wins or replace them silently.

No ratio from a partial cohort. Report per-model paired medians, individual rows,
sample SD of the six floors, and p90 by nearest rank (`ceil(.9*n)-1`). Require an
effect beyond two floor SDs; report overlap/parity honestly. Disputed artifacts need
blind judging before any quality claim. This epoch does not establish optional
