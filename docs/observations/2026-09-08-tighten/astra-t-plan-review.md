# Astra: reduce request-to-landed wall

Elevate this work: it shortens every subsequent fix. Keep the two builders, but change the design from five chained commands to one prepared candidate with reusable proof and a final publication step. Prioritize eliminating repeated gates and handoffs before optimizing work already hidden behind review. These are proposals, not measured gains.

## Concrete replacement: prepare once, prove once, publish once

Create one run identity before preparation: request timestamp, pushed tip, destination `MCP/main`, fetched base, final merge commit C (including final parents/title/trailers), tree digest, brief/scope hash, required reviewers, gate manifest and tool/environment identities. Never target frozen `main`. Resolve conflicts before sealing C; conflict repair creates a new candidate.

Launch review, receipt battery and independent landing checks from C at preparation completion. Use separate disposable worktrees and per-job output/temp/port/event paths. Share immutable dependency/build artifacts only with a complete cache key; keep review probes and cold tests in separate processes. A reviewer may mutate its scratch copy to attack a bug; those mutated bytes cannot supply candidate gate proof or become the published tree.

Bind every result to full C, exact gate invocation, input/runner/toolchain hashes, exit, coverage, required preconditions, start/end and job identity. The aggregator must require all named checks and reviewers. Changed C or relevant environment invalidates reuse; ancestry or “44 versus 30 commits” never substitutes for identical-candidate proof.

Keep proof outside C: immutable per-run artifacts plus a records-lane entry, filed before queue admission as required. Do not commit the battery ledger into the candidate and then pretend its new SHA was tested. A commit cannot contain a receipt naming its own final SHA. Let the freshness checker consume the external C-bound receipt; preserve the legacy ledger adapter during migration.

Publish the already-created merge C, without another merge or suite, only if the destination still equals the recorded base. Coordinate destination writers through one queue; records continue on their own branch while this candidate is active. Builders and rows keep working. A short publication lock alone cannot stop base drift during review: any unexpected remote advance returns STALE_BASE, never a force-push or silent docs re-merge. Prepare a new candidate and re-establish proof; measure that lost wall.

Finish only on confirmed remote publication of C (or explicitly recorded subsequent advancement containing C). A network-ambiguous push requires reconciliation before retry; a local checkout sync failure is a separate warning after publication. Keep the candidate and receipts on failure so a restart resumes completed work rather than rerunning it.

## Correct the five moves and their risks

**land-auto:** retain as the immediate bridge. Retry once only for a typed missing/aged/distance-stale receipt, with no failing battery, red audit or other failed gate. Installed code matches any `battery-fresh: REFUSED` string; that is broader than a demonstrated stale-only condition. Refusal classification must name the current run, prerequisite failure and all other outcomes. Never turn a failed newest battery into a refresh attempt. Concurrent identical invocations coalesce under an ownership lock; no mutable shared receipt worktree.

**Prewarm:** start at candidate-ready/review launch, not GO. A NO-GO may waste one battery; cancel only owned jobs and retain their status. Prewarming the branch tip while receipt-chain independently merges current trunk does not give one reviewed/tested subject. One sealed C does. Check foreground and child exits; a READY substring or living/reused PID is not completion evidence.

**Code-only freshness:** ship as a bounded compatibility improvement, not a proof-equivalence rule. Use a versioned path classifier: execution/gate inputs include src, test, resources, scripts/bin, Makefile, dependency/build files, CI, analyzer/runner configuration, fixtures, skills/routing rules and gate-consumed intent docs. Ignore only explicitly registered inert records; unknown paths count as relevant. Check rename source and destination, deletions, modes and symlinks, including scripts placed inside docs/observations. Hash external installed gate scripts separately. Keep age, ancestry and failed-newest checks. Records churn should not spend the distance budget; any proof-input change still invalidates exact reuse.

**Parallel battery:** today's receipt enumerates 35 namespaces, not eleven, with 743 tests / 13,756 assertions and ONE skipped recovery precondition despite PASS. Eleven names a historical cold-launcher subset, not the complete current inventory. Derive and freeze the full membership and per-namespace witness set; prove disjoint, complete assignment, no duplicate/omitted test, all workers ended, union isolation and exactly one durable aggregate receipt. Ledger publication failure must fail the run.

Separate JVMs can hide shared-state/order failures even when the union inventory is perfect. Preserve order-sensitive/unqualified groups in a serial lane; qualify extraction with serial-vs-parallel verdict comparison, reversed/seeded order probes and planted cross-namespace leaks. Keep cold launches cold. Union isolation must include child-process ownership, files, ports, global artifacts and time budgets; a missing/crashed/timed-out lane is RED. Do not replace a known serial witness with a nightly promise before equivalent detection is demonstrated.

Assign bounded lanes/heap/CPU through the existing resource scheduler, respecting rows' quiet windows. Eleven JVMs at once is not eleven free lanes. Measure longest lane plus aggregation AND scheduler wait. Parallel B helps the critical path only when B exceeds R, the review becomes shorter, or queued battery work blocks another landing; under a twenty-minute review, moving B from 13.5 to 5 minutes mostly buys capacity.

**ship:** freeze the required-reviewer set before launch. Installed fence-run kills a prior reviewer in a shared worktree and appends its END receipt asynchronously after process exit. A second review can be killed or still be writing when a caller sees GO. Use unique run worktrees or explicit exclusive queue admission; await each supervisor's process-group completion and atomically published final result. Require all required GO verdicts, end bindings and outstanding conditions closed. GO-WITH-FIX, timeout, absent/truncated output and unfinished second review all HOLD. Never parse a GO substring from prose.

The installed land also prints LANDED after a push/sync command chain without making that print conditional on push success; its docs-only late-merge test covers only src/test/Makefile/deps.edn. Fix these publication conditions before delegating authority to ship. They matter more than a shorter stopwatch.

## Cut review and remove the larger duplicate

Make review delta-first: base→C diff, conflict resolutions, named entry points/callers, applicable intent, previous findings and exact regression/adversarial probes. Supply a short decision brief with linked evidence, not a history dump. Review the dependency/security closure reached by the delta; “diff only” must not forbid reading unchanged code that determines behavior. Required executed adversarial review remains.

Use a typed ten-minute review class only for bounded deltas with an explicit probe manifest. Outcome is GO, NO_GO or NEEDS_EXPANDED_REVIEW; deadline is HOLD, never automatic approval. Require closure of every old blocker before exploring extras. New public surfaces, fence changes or scope expansion route to a separately timed broader review. Compare escaped defects and planted-defect detection, not just elapsed minutes.

Review once per coherent ready batch against one C, with per-fix scope and findings. Do not wait to fill a batch or combine unrelated risky fixes: batching may improve throughput while worsening the oldest fix's t. Subsequent fix review can reuse unaffected findings only with an explicit impact check; changed interactions require new probes. Two builders can share one integration review for a genuinely coupled mechanism.

The largest remaining predictable removal is G≈8 minutes: execute all required landing checks during the fence interval, then consume their receipts. Make repository gate membership authoritative. Express a dependency graph: recovery prerequisites before their consumers; independent checks may start before battery-fresh, but final admission waits for battery proof. This requires a reviewed runner contract change, not manually bypassing today's ordered target. If safe resource overlap is unavailable, report B+G honestly.

Skipping another make test is sound only if the identical C already passed EVERY required landing check with equivalent invocation/environment/isolation and fulfilled prerequisites. Today's test-battery is not make test or test-full; the receipt's skipped recovery proof rules out that inference. Generate a coverage manifest and run only genuinely missing obligations, including affected batteries, hygiene and audit. A reviewer saying “tests pass” cannot discharge an unnamed gate. Reuse immutable build outputs; never replace a required cold witness with the reviewer's warm JVM.

## One SHIP line, with honest arithmetic

Proposed format (placeholders, not observations):

SHIP status=LANDED run=<id> candidate=<full-sha> landed=<sha> t_request_s=<n|unknown> t_push_s=<n|unknown> t_go_s=<n|unknown> prepush_s=<n|unknown> queue_s=<n> prepare_s=<n> active_s=<n> publish_s=<n> idle_s=<n> rework_s=<n> review_s=<n> battery_s=<n> gates_s=<n> critical=<phase> attempts=<n> reviews=<done/required> gates=<passed/required> receipt=<path>

Use process/supervisor timestamps, monotonic durations and UTC event times; capture the original request/push events upstream, never infer them from author dates or ship launch. Additive, nonoverlapping buckets are prepush+queue+prepare+active+publish+idle+rework=t_request. Review/battery/gates are overlapping service durations within attempts, not extra summands. Rework includes retired attempts, avoiding a reset at the successful attempt. Unknown stays unknown. On HOLD/RED print the same line with elapsed-to-status and no landed claim. Artifact intervals must reconstruct every number and concurrent critical-path dependency.

Removes up to ≈10 review minutes, the next dominant term. **Witness:** same representative/seeded defects found and required probes completed, timeout→HOLD, no increased batch wait for oldest fix; then consecutive real rows with complete first-attempt request/push/GO→land clocks. Seek GO→land near publication time and push→land ≈max(review,battery,gates)+overhead; retain all refusals and regressions. Use six same-input baseline runs before claiming a controlled speed gain; real canaries establish operation, not that comparison.
