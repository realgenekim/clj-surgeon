# Tighten — say `tighten` to make this so

> Gene, verbatim, 2026-09-08: "Let's strive to make this part all sublime. And you and Astra do what it takes to make it recursively self improving (please make skill for that, and what we call this? Say ___ to make this so.) Time budget: 4 hours."

`tighten` makes fast, scrutinized feedback part of daily work: observe a hand-paid obstruction, preserve its real counterexample, repair the smallest responsible entrance, enforce the promise, deliver it, and watch it work again. It owns the daily loop around **clojure-fast-feedback**; use that skill for the actual probe, oracle, proof and JVM lifecycle. The test is the **SECOND ENCOUNTER**: a later eligible task, preferably another seat/repository, avoids the original obstruction with equal independent acceptance and intact evidence. Construction is not transfer; no later opportunity means `transfer=untested`. When the obstruction was in capture, repair, verification or delivery, that second encounter proves the recursion.

- Use the published seat binding: full seat identity, package/epoch, records destination, duty owner, instrument steward, and command paths/arguments. See [SEAT-RECEIPT.md](SEAT-RECEIPT.md).
- The four new daily jobs below have a **draft no-argument contract**: resolve the registered seat/day/task schedule, perform their one job, and emit a structured receipt plus exact next action. The operator must wire and exercise it; do not guess flags.
- Missing command, unsupported repository, absent binding or unqualified observer: record `unknown`/owned blocker, use the existing safe task entrance, and withhold the affected loop claim. Do not improvise another harness.
- Boot/resume, package change and landing trigger identity/delivery checks as well as the daily close. A cached session must consume the new instructions or restart before claiming delivery.

## Daily unit — in order, preserve unfinished work

1. **Enter and attest.** Run `seat-receipt`. It records actual package resolutions/hashes, effective prompt, observation coverage, job heartbeat and stop scopes; read its discrepancies before using affected authority. Opening evidence is an append-only checkpoint, not the day's final behavioral verdict.
2. **Open the bounded work block.** Use the registered values below, supplied before work; `tick` is tool-perfecting and `tock` is frontier work (retained block-ledger rows, 2026-09-06). Continue an existing block instead of opening a duplicate.

   ```bash
   ~/bin/block-ledger current --seat "$TIGHTEN_BLOCK_SEAT"
   ~/bin/block-ledger open --seat "$TIGHTEN_BLOCK_SEAT" --kind "$TIGHTEN_KIND" \
     --id "$TIGHTEN_BLOCK_ID" --deadline "$TIGHTEN_DEADLINE" \
     --hypothesis "$TIGHTEN_HYPOTHESIS" --falsifier "$TIGHTEN_FALSIFIER"
   ```

   The 2026-09-08 executable accepts only `fable|astra`; another seat needs an operator-provided compatible entrance, never impersonation. Block time is not task-acceptance time.
3. **Do assigned useful work through the existing entrance.** The repo owner supplies the fast probe; the launcher owns the image; the builder uses the parent skill. The external recorder retains every assignment and attempt. Native edits remain default outside admitted contracts.
4. **Capture friction as it happens.** Preserve call, expectation, refusal/deviation verbatim, return-tax, context privilege, trace, owner and trigger. Include native workarounds. Classify expected protection, caller repair, false refusal, unavailable capability and unknown execution. Deduplicate the class, never its occurrences or cost.
5. **Run the fresh daily canary when scheduled:** `canary-cell`. One fresh cold-start cell on the current frozen package per active repository/day, rotating registered seat/runner/model coverage. A changed seat/package needs its own fresh delivery cell before verification; another seat's canary is not its proof. Read actual red, probe, final proof and observer coverage.
6. **Freeze the day's actionable inbox selection:** `ledger-to-findings`. It emits round's findings file from existing friction IDs with evidence, violated intent, owner, trigger and acceptance. Expected protection need not become a fix. Preserve deferred items and a short judgment field; never write a second brief.
7. **Repair one earned batch.** Use the emitted paths and unique run name; this existing signature is program-specific, so the binding must name a supported round profile.

   ```bash
   round "$TIGHTEN_WORKTREE" "$TIGHTEN_FINDINGS" "$TIGHTEN_ROUND_NAME"
   ```

   Keep the builder session; a continuation uses that round's explicit saved session and documented `--resume`, never an unrelated last session. The reviewer's faithful red test is the builder's witness. Follow applicable linked intent and required phase reviews. Every load-bearing fix carries its ratchet; an oracle that missed it is itself a finding, qualified under the CHANGE RULE.
8. **Read the terminal batch evidence.** The runner grades the frozen final candidate with retained positives/negatives; commit state, printed PASS or a pending proof is insufficient. Inspect named checks, actual exits, candidate binding and coverage. Run outstanding required proof. Scrutiny belongs in executable witnesses; independent review and landing battery run once per ready final batch, not every inner repair.
9. **Land a ready, authorized batch; zero-change days are legal.** The designated landing owner runs the bound entrance, with independent review GO and required battery evidence:

   ```bash
   land "$TIGHTEN_TIP" "$TIGHTEN_MERGE_TITLE"
   ```

   On this program the target is `MCP/main`; public `main` is frozen (Gene, 2026-09-04). Other repositories use their authorized working branch. Verify actual durable delivery and current-session uptake on affected seats, not just a pointer or a merge message. No daily landing quota.
10. **Close evidence and the block.** Run `seat-receipt` again after terminal events; it appends the daily close to records. Retain pending tasks and proof. Update the tree and log from receipts at phase changes. Close the block with measured values or `none`, never estimates disguised as clocks:

    ```bash
    ~/bin/block-ledger close --id "$TIGHTEN_BLOCK_ID" --outcome "$TIGHTEN_OUTCOME" \
      --native-wall "$TIGHTEN_NATIVE_WALL" --tool-wall "$TIGHTEN_TOOL_WALL" \
      --receipt "$TIGHTEN_CLOSE_RECEIPT" --prep-wall "$TIGHTEN_PREP_WALL" \
      --attempts "$TIGHTEN_ATTEMPTS"
    ~/bin/block-ledger show --hours 6
    ```

    Record `done|parked|killed` honestly. A block deadline never passes an unfinished gate; retries keep the original task clock. Preserve actual frontier/tool-perfecting time at the registered 50/50 balance per paired blocks.
11. **At the weekly boundary:** `verb-sentinel`. Run one frozen matched native/tool pair per active admitted verb on its exact admitted contract, equal acceptance, retained attempts, registered noise and counterbalanced order across weeks. Check saved positives/negatives first; retain an independently selected challenge. Check alert delivery and retention too. This is a drift sentinel, not admission or a speed certification.
12. **Schedule the second encounter prospectively.** Link finding → real red/green → ratchet → deployment → later task. The independent acceptor confirms equal acceptance; a different seat supplies transfer when the claim crosses seats. Keep recurrence and maintenance cost visible; retire redundant apparatus only while its promise remains enforced.

## CHANGE RULE — the fixed point

Read [CHANGE-RULE.md](CHANGE-RULE.md) before changing any block, oracle, harness, classifier, recorder or this rule.
The builder proposes an isolated candidate; the current trusted package remains reference.
A **named independent instrument steward** verifies frozen positive AND negative cases at the production entrance.
Acceptance, routing admission, exclusions, clock boundaries and boot-block meaning require **Gene's explicit ruling**.
Publish an old/new verdict matrix with each changed verdict explained; issue a new instrument epoch.
Regrades append, never overwrite; missing observations cannot be recovered by regrading. Changed instruments need fresh matched timing controls.
The loop may improve its meter's implementation; it cannot award itself authority or weaken the meaning it is measured against.

## Protected denominator and tripwires

Protect **request-to-independently-accepted completion on a prospectively assigned task set, every attempt counted**.
An independent recorder assigns IDs before workers see tasks; intent, task membership and acceptance are frozen before optimization.
Retain failures, refusals, timeouts, abandonment, retries, pending and unknown outcomes; pending tasks keep aging.
Publish completed/assigned counts and latency distributions with censored outcomes visible, not successful durations alone.
Include setup, recovery, waits and required acceptance in the clock; separately retain review/landing tails and Gene's intervention time, identifying any overlap.
Apparatus share and refusal rate are diagnostics with frozen classifiers, full coverage and raw-event sampling. Neither can replace acceptance or native controls.

| Tripwire | What it summons |
|---|---|
| Apparatus **>50%** in the registered action window | Repo/tool owner: name the dominant hand-paid obstruction and select a bounded ratchet. Withdraw “sublime”; exactly 50% also fails the tree's strict `<50%` perfect gate. |
| **Two missed hourly audits** | External duty supervisor → named deployment/job owner and rung-2 duty officer; mark stale/unknown, withhold unattended-health claims and affected admission until fresh evidence. Offline seats remain rows. |
| Performance drift beyond **registered noise** | Instrument steward + verb owner investigate against that route's controls; no promotion. One noisy pair is not a measured loss. Missing telemetry means unknown performance and native fallback pending investigation. |
| Correctness loss | Suspend the affected route immediately; summon its owner. Pull scoped Andon for shared/shipped wrong-state risk or a gate that could falsely authorize release; isolated safe failures stay with their candidate owner. |
| Undelivered alarm or missing acknowledgment | External duty supervisor escalates through the verified alternate channel to rung 2, Gene, then the named second human as required. No delivery receipt means escalation, never consent by timeout. |

Package drift, unknown execution and missing proof are owned discrepancies immediately; two audits is not a grace period for using wrong authority.
For Andon: stop the implicated release/mutation scope, preserve diagnosis and isolated repair, retain incident/evidence ID, and summon help directly through the registered cord.
Mayor acknowledgment is due within **5 minutes** under house rules; use an already verified direct path when the file watch is silent. No rung-2 officer means the scope stays closed. Resume needs explicit owner and evidence; irreversible scope reaches Gene.

## First two weeks — order, not automatic deadlines

- **Days 1–2:** inventory seats/repos/entrances/records and name independent owners; freeze a natural task and package; obtain rulings on boot/proof contradictions before changing their meaning.
- **Days 3–4:** one real Claude seat and one Codex seat complete finding → red → repair → proof → review → branch landing → fresh delivery → second encounter. Exercise wrong-root, pending-proof, missing-observer, stale-block and failed-worker negatives beside positives.
- **Days 5–7:** extend actual skiff/bridge/anvil delivery, including remote bindings; start hourly audit, daily close/canary and weekly sentinel. Prove an absent heartbeat and an alarm reach an owner. Gene prunes/rules.
- **Days 8–10:** spend capacity on useful work; follow the tree's descend-at-low order, row **1 → 5 → 2**, and its bounded frontier lane. Remove an observed recurring obstruction for another seat.
- **Days 11–14:** complete a cycle without Gene relaying; retain unsuccessful assignments, test escalation, sample acceptance, repeat the sentinel within its epoch, publish gaps and the smallest stable package.

A failed prerequisite stays pending with its clock intact. Two weeks cannot confer “perfect”: the tree still requires complete cohorts, every-seat delivery and a calendar month of eligible regression-free dogfood.
Use the tree's existing columns: `# | move | vs native and endpoint | phase / status | evidence and limit | next action`; phase is the highest fully evidenced gate. Keep inbox findings authoritative and project the tree from receipts, not another hand-synchronized queue.
