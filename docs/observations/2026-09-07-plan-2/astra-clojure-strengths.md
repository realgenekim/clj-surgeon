Gene asked: “Bigger question. How do we take maximal advantage of clojure unique strengths. Ask Astra too.”

**My commitment: build a programmable, lossless candidate compiler with an evidence service. Make the whole refactor a value, let the model write the policy, and make verification reusable. Keep static source analysis authoritative for source occurrences; use an attested live image as additional evidence. Do not make a shared live image the universal semantic oracle or the isolation boundary.**

I rank the investments: **(1) one snapshot and reusable reference graph; (2) whole-candidate construction, with a model-program entrance and a concise mapping entrance sharing the same kernel; (3) warm feedback followed by exact-candidate cold acceptance; (4) runtime enrichment where it answers a specific unresolved question; (5) controlled reload delivery.** The first two remove work that dominated today. The third removes repeated feedback cost. The fourth and fifth are conditional advantages, not prerequisites for every refactor.

This ranking concerns large refactors by capable models. It is not a ranking of language features for application development. The productive combination is source facts as values, model-written functions over those facts, and the real compiler as an inexpensive critic. The romance is expecting the word “Lisp,” an open REPL, or an S-expression printer to supply semantic correctness and lower total wall automatically.

**Fable's five claims, argued both ways.**

**1. “Code is data; never text.”** The strongest version is right: discover meaning structurally, transform by node/definition/reference identities, and preserve exact source instead of asking the model to invent token boundaries. But “never text” is wrong literally and dangerous if interpreted as `read → postwalk → pr-str` over whole files. Comments, discards, original reader spelling, attachment, and formatting are part of the artifact. Symbols inside syntax quote and auto-resolved keywords depend on reading context. Clojure's reader explicitly skips `#_` forms and resolves syntax-quoted symbols in context. A plain value cannot preserve information it never retained. [Clojure reader reference](https://clojure.org/reference/reader).

Use a lossless concrete syntax tree, a derived semantic view, and original text together. Unchanged nodes carry original spelling; moved nodes retain their attached trivia; changed leaves or newly built nodes render intentionally. Guarded string splicing is an acceptable final lowering of a structurally decided change. Banning that implementation would have no economic justification. Also, do not turn node moves into whole-file pretty-printing that changes every untouched owner.

**2. “The runtime knows the truth.”** It knows the state of that runtime. It can answer whether `views/edit-form` is interned there and what metadata that Var currently carries. It cannot answer whether a particular `edit-form` token in `(let [edit-form ...] ... edit-form ...)` refers to that Var merely by calling `resolve`, `ns-resolve` or `ns-publics`. The compiler resolves local bindings before namespace Vars; occurrence analysis needs that lexical environment. Supplying an environment to resolution presupposes obtaining it. Reflecting on a loaded function does not recover the original source's complete binding/use graph. [Clojure evaluation reference](https://clojure.org/reference/evaluation).

Thus the false edge from today is evidence for scope-aware analysis, which N1 and both R implementations eventually obtained from kondo. It is not evidence that loading the application replaces kondo. A compiler/analyzer hosted in a live image could produce richer facts, but that is an analysis service with macro execution and source-mapping problems, not a free consequence of `ns-publics`. A bare Var lookup would reproduce the false inference in this example. Runtime absence is equally weak: perhaps the file was never loaded. I reject the universal claim and retain the targeted evidence service.

**3. “Construct the whole candidate; load fresh namespaces in the same JVM; prove warm before writing.”** Whole-candidate construction is the most important proposal here. It allows final-graph validation, simultaneous caller migration and one proof obligation rather than twenty temporary states. The candidate need not compile after each intermediate move.

Fresh namespaces, however, are not general isolation. Giving a candidate a new namespace name changes qualified symbol/keyword identities, class names, multimethod registrations and potentially resources or strings used by the application. Loading the actual destination names can affect globally registered namespaces and shared dependencies. `remove-ns` does not reverse arbitrary load effects or revoke references already held elsewhere. A new ordinary classloader is not, by itself, a new Clojure world when it shares the parent runtime's registries.

I would provide a candidate loader with explicit isolation levels. Renamed scratch namespaces are useful for admitted, namespace-insensitive pure probes, with that limitation in the receipt. For ordinary application proof, prefer a dedicated project worker using real namespace names and an explicit reset/reload closure. Recycle it when identity or state makes reuse unreliable. Final cold acceptance loads the exact materialized candidate in a separate process. “Before writing” means before publishing to the user's worktree; writing an isolated candidate tree for the compiler is entirely acceptable.

**4. “The model writes Clojure; accept a program instead of growing verbs.”** This is the direction I back, with an important contract boundary. Let the model submit a bounded pure function or equivalent data plan. Give it reusable structural and semantic facts and composable transformations. The runtime owns confinement, candidate validation, independent verification and publication. Do not give the submitted function unrestricted access to the serving JVM and then ask it to testify that it was pure or successful.

The opposing case is strong on today's exact task. A fixed `namespace_split` can express a mapping more cheaply than a newly authored program and can accumulate excellent diagnostics. It will probably beat a generic program on a familiar split. The program route wins when the model must combine policies that the verb does not express, and it avoids months of extending a growing request grammar. This is compatible with stronger models; today's experiment is not an empirical test of the bitter lesson or a guarantee that models write reliable transformers. Use one kernel and library, with both entrances. Judge the cost of expressing the whole task, including program debugging and library discovery.

**5. “Reload as delivery; prove in the process that serves the code.”** For an explicitly managed development application, validating the actual new handler after reload closes a real deployment gap. Surgeon itself already has reloadable handler Vars and live tool-registry synchronization. That is a useful existing Clojure advantage. [Server registry implementation](/home/forge/src/clj-surgeon-astra-consult/src/clj_surgeon/mcp_server.clj:237).

But a large source refactor is usually delivered as files or a branch, not as a secretly mutated application image. Passing in a long-lived process cannot prove clean startup, and tests may disrupt the process's state. Separate candidate acceptance from an optional, authorized reload transition. After reload, attest the serving generation and perform a real request there; also retain the clean-start gate. Rolling back source and reloading old forms is not proof that external effects were undone.

The kernel should expose a small set of reusable operations: `snapshot`, `references`, `project-graph`, `transform-candidate`, `verify-candidate`, and `publish-candidate`. These are conceptual names, not claims about current callable APIs. Within a transformation, library functions should move existing owner nodes, rewrite resolved occurrence nodes, derive headers and declarations, and preserve attached source. Ordinary Clojure can filter, group and compose those values. Architectural decisions stay with the caller; mechanical consequences should be computed once.

A snapshot needs canonical source roots, original bytes, content hashes, parser coordinates with a declared convention, platform/reader context, owner IDs and an analysis identity. Names alone are insufficient identities: a declaration and its definition, multiple defmethod dispatches, reader branches and real duplicate definitions need distinction. Offsets must explicitly distinguish UTF-8 byte positions from JVM string/line-column positions. Nodes retain their origin after movement; new destination positions are computed during rendering.

The reference relation should identify each occurrence's owner, exact source node, resolved target or local binding, syntactic context, provider and coverage. Runtime observations carry their own image generation and loaded-source/configuration identities. Contradictory evidence becomes a named disagreement; an image never silently overrides a changed file. Test impact follows reverse dependencies, including macro consumers and relevant load dependencies, with a full-suite fallback where the impact closure is incomplete. This is not a promise of complete dynamic call-graph discovery.

Proof proceeds from cheap structural checks and mapping conservation, through analysis/graph constraints, to eligible warm reload and focused tests, then cold acceptance on exact candidate bytes. Test names, nonzero expected execution where applicable, assertions, instrumentation and environment are evidence, not just a zero error count. Candidate rendering/formatting happens before its proof hash is finalized. Publication rechecks base hashes and destination absence under the write authority; stale evidence refuses. No formatting after acceptance without rebinding proof to the resulting bytes. Multi-file recovery is not invisible atomic publication to unrelated readers; describe that limit accurately or publish by an actually isolated tree switch.

**A concrete model-submitted transformation contract.**

The following is a proposed contract, not executable against the present tool:

```clojure
{:contract-version 1
 :snapshot-id "sha256:..."
 :mapping {:definition->destination {"owner-id" 'app.views.shell}}
 :scope {:write-roots ["src" "test"]
         :delete-files ["src/app/views.clj"]}
 :policy {:visibility :promote-required
          :unresolved :refuse-owned-change
          :preserve :lossless}
 :program {:language :clojure-sci
           :source "(fn [{:keys [snapshot mapping]}] ...)"}
 :proof-profile :view-split-acceptance
 :mode :candidate}
```

A full mapping covers the admitted owner set; the tiny mapping above only illustrates its shape. The snapshot is a server-retained immutable value passed in-process, with bounded projections available to the model; do not resend every source body through the model to call the program. A serialized function source is compiled against a versioned pure library. It does not import a closure from an arbitrary REPL session. The equivalent data DSL describes the same candidate effects and lowers through the same validator.

For example, a program could group owners by the supplied destination, apply an explicit visibility exception, move the owner nodes, rewrite the already resolved cross-boundary occurrences, derive namespace headers, and return the final file/node map. It may use ordinary `reduce`, `group-by`, `assoc` and library functions for lossless nodes. It does not rediscover token coordinates, call `spit`, open a socket, choose a shell test command, or mutate loaded application Vars. Reusable node operations make this more than “write your own compiler in our sandbox.” Conversely, if the only allowed operation is `(namespace-split mapping)`, we have exposed a fixed verb under a program-shaped wrapper, not gained useful programmability.

The program returns candidate data and proposed obligations, not a trusted success claim:

```clojure
{:candidate {:files {"src/app/views/shell.clj" {:root-node "node-id"}}
             :deleted #{"src/app/views.clj"}}
 :decisions {:promotions #{"owner-id"}}
 :requested-checks [:mapping-conserved :final-graph-acyclic]}
```

This is schematic: unchanged files are inherited from the snapshot; root IDs refer to validated nodes in the candidate arena. The runtime validates ownership, node provenance, allowed paths, conflicts, protected syntax and size before rendering. A trusted profile supplies the mandatory checks; a program can add checks but cannot remove them or redefine the independent acceptance tests. Tests that are legitimate refactor targets remain writable within scope, while the external acceptance oracle stays frozen.

The service then produces an attributable receipt containing: base and candidate hashes; program/library/analyzer hashes; mapping and policy identity; created/changed/deleted files; owner conservation and caller-site counts; promotions; graph witnesses and unknowns; actual warm/cold checks with outcomes, durations and environment; commit state; and unresolved obligations. `:candidate-ready`, `:warm-passed`, `:cold-passed`, `:committed`, `:refused` and `:recovery-required` are different states. Missing cold proof must remain missing. Detailed manifests can live behind a compact receipt reference. Receipts come from the host and verifiers, never from whatever map the submitted function chooses to call a receipt.

Confinement is two separate problems. The transformation executor handles pure, bounded source computation; SCI is a useful existing starting point, but an allowlist alone does not guarantee termination or bound a realized collection. Enforce input/output limits, CPU/wall/memory limits, and use a disposable process for reliable termination when necessary. Do not rely on interrupting a thread as universal cancellation. The application verifier executes real Clojure, including macros and load effects, in a separately controlled worker. Never solve purity by adding `eval`, interop or `require` to the shared server's model-program allowlist.

Why this can beat `namespace_split`: policy composition and a new combination of transformations need no new transport schema, while trusted parsing, resolution, preservation and proof stay reusable. Why it can lose: the model may spend longer learning helper APIs and debugging its function than supplying a mapping; genericity widens the failure surface; a fixed compiler can generate better diagnostics. My commitment is **a programmable core plus a few compact standard programs**, not an ever-growing verb set and not unrestricted evaluation. Keep native patch admission as a first-class entrance to the same proof service. If a stronger model already produced good bytes, the service should accept them without a ceremonial translation back into a DSL.

These constraints argue against making “the live image knows” the foundational abstraction. The foundation should be an immutable source candidate with evidence about several environments. A live image is one of those environments.

**The one experiment I would run in a day.**

Run a bounded **whole-candidate crossover on Cell A**, with a held-out policy variation, using one shared analysis/render/proof kernel. Its question is: *does a reusable source-data runtime remove enough model work to beat native scripting, and can a model program express a nearby change without extending the fixed verb?* It is not a test of universal same-JVM isolation, and it must not award programmability the gains of a warmer test harness than its control receives.

Use three entrances: N, unrestricted native scripting/patching; D, a whole-split mapping compiler; P, a model-submitted pure Clojure program over the same snapshot graph and lossless node library as D. Give all three the same supplied prose plan, source base and acceptance obligations. Let N use kondo and the same candidate verification service, including the warm worker; it may choose Python, Clojure or Babashka. D must compile the final mapping in one pass, not call existing extraction twenty times. P and D must share resolution, rendering, proof, transaction code and capability documentation. Give N access to the common snapshot facts as well, so its positive control can exploit the best available infrastructure rather than being artificially forced to rebuild a parser.

Use the original split first, then one preregistered held-out variation requiring a small source transformation in addition to movement—for example, preserve explicitly named compatibility entry points while applying a specified arity-preserving wrapper to a bounded set of moved functions. Freeze the exact function set, semantics and independent behavioral assertions before any caller sees them. D may compose native work when the fixed entrance cannot express it; count that work and preserve its best-case option. P must express it using the existing library and ordinary Clojure, with no new server primitive added after the variation is revealed. This makes the hypothesis falsifiable instead of choosing an extension the evaluator was built to recognize.
