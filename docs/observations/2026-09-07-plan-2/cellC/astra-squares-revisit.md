**Where Fable is right, wrong, or ahead of the evidence.**

The strongest case for Fable is unusually concrete: native received the same machine-ready mapping and still rebuilt reference analysis and an emitter. The compiler consumed that mapping and owned the consequences. This is strong evidence that retiring whole pieces of caller work matters much more than making subsecond edits faster.

The strongest objection is causal identification. Cell C changes the compiler, reference authority, completeness of the mutation, proof integration, diagnostics, and caller interaction together. It does not isolate four independent causes named “decisions,” “plan as data,” “static authority,” and “oracle-first.” Those are a good mechanism hypothesis, not four separately measured effects. A reusable native library consuming exactly the same facts might capture much of the benefit.

My more precise rule is: **caller work should scale with unresolved policy choices; the compiler should derive mechanical consequences from the complete intent and current evidence.** A 141-owner mapping still has size. File scanning and proof still cost time. The important distinction is whether the caller must author a second reference graph, counter, emitter, or migration table. A one-call wrapper around twenty incomplete operations would not satisfy this rule.

**The candidate ranking, with numbers that can be challenged.** I use exactly the requested product:

`priority = expected complete native seconds per eligible task × eligible tasks per month across the five repos × probability of a meaningful correct speed win from the split mechanism`.

Complete wall includes normal repository acceptance; it excludes researching what the requested behavior should be. The score is **opportunity, not saved time**. A costly suite inflates native wall but may be impossible to remove. A better investment calculation is `frequency × (native wall − tool wall including fallback) − amortized build/maintenance time`. These candidates overlap: an upgrade can contain an API migration, and a route split can contain a form move. Do not sum the rows as independent demand. Their raw product totals only about three hours per month even before subtracting remaining work. High reuse, reliability, and Gene’s teaching/chronicle value may justify development; multiplying one ninefold demo by every Clojure edit will not.

This ranking commits me to a small extraction extension first, a bounded API-migration policy second, and deferring a generic dependency-upgrade or test-authoring system. Shared owner/reference/projection/emission components are the reusable asset. A thin route-split manifest can follow when an actual route task supplies the additional behavioral contract.

**One next experiment: partial extraction through the shared split compiler, with a facts-only ablation.** This is a proposed preregistration to freeze before building the experiment; no cohort has been launched.

The hypothesis is: on a supplied extraction intent with unknown caller sites, reusable reference projection plus complete candidate emission removes enough reconstruction and repair to beat native through identical final acceptance. The ablation asks whether most benefit belongs to reusable facts or also requires tool-owned emission. It avoids spending the next experiment on a larger version of the same full split.
