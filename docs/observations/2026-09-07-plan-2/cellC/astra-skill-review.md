The draft has the right center: make iteration cheap, preserve acceptance, and turn recurring failures into executable machinery. I would revise it before distribution. The two-line REPL example is particularly misleading in a testing skill: reloading `app.thing` does not load or refresh `app.thing-test`. A newly written red witness can remain absent while an old test passes. `clojure.test/test-vars` applies namespace fixtures, while invoking a test function or bare `test-var` does not provide the same fixture wrapper; namespace hooks and Kaocha plugin semantics still need the repo runner. This is why selection should be a function the agent calls, not an expression it reconstructs. [clojure.test API](https://clojure.github.io/clojure/clojure.test-api.html#clojure.test/test-vars).

Likewise, plain reload also executes top-level forms. `refresh` adds unloading and dependency-aware reloading; it does not invent resource cleanup. Configure refresh roots and a stop/start lifecycle. A failed load can leave a partly changed image, even if source files are restored. [tools.namespace guidance](https://github.com/clojure/tools.namespace#reloading-code-usage).

**`make test-probe`: keep the entrance, complete the contract.**

Yes: a separate probe target is the right shape. It keeps `make test` meaningful and works after native or structural edits. No: `NS=app.thing` plus `{:tests n :failures n :oracle n}` is not sufficient. `NS` must mean a source namespace or a test namespace, not whichever the caller guessed. Use a declared source-to-tests mapping, and an optional explicit focus selector for the direct witness. Missing mappings are typed unknowns; do not guess “append -test.”

The repository’s verifier owns the following transaction: validate request and profile; acquire the image lease; attest session, environment and source basis; compute reload and test selection; apply the eligible reload/reset; execute fixture-aware tests and applicable oracles; check cleanup and source stability; return one bounded structured receipt. All clients that mutate the authoritative image must honor that lease. A separate write/snapshot guard protects source identity; an image lock does not stop another process editing files. The supervisor owns the JVM lifetime, the verifier owns leases and check execution, and completion admission owns acceptance of receipts. A worker never has to invent a lock path or decide whether printed “0 failures” counts.

Cache readiness by environment/generation. Per probe, validate what can have changed; do not require and scan every namespace again. The process reports complete wall and phase times, including lease wait. The source tree remains untouched by a probe; fixture effects and image changes are reported separately. The optional output oracle is `:not-applicable` only by profile decision with a reason, never an ambiguous `:oracle 0`.

Illustrative receipt, not an implemented schema:

```clojure
{:status :probe-passed
 :request-id "..." :basis "source+tests+resources+config digest"
 :environment "classpath+JVM flags+fixture+runner identity"
 :image {:session "..." :generation 12 :owner "..." :state :ready}
 :reload {:status :passed :namespaces [app.thing app.thing-test]}
 :selection {:test-ids [...] :coverage :declared :unknowns []}
 :tests {:status :passed :test 18 :pass 132 :fail 0 :error 0}
 :oracle {:status :passed :id "..." :baseline "..." :introduced 0}
 :source-state :unchanged :cleanup :passed
 :timing {:wall-ms 410 :lease-wait-ms 0 :reload-ms 40 :tests-ms 360}
 :verification_complete false
 :proof_pending [:repo-cold-suite :required-platform-check]}
```

The illustrative numbers do not claim a new measurement. `:pass` counts assertions, not tests. The actual checks and pending gates must come from the trusted profile, not from an arbitrary request. Detailed IDs/manifests can live behind a receipt reference. A successful probe should exit zero—scripts need a useful success state—while completion still refuses its incomplete proof. Reserve nonzero results for test failure, refusal, infrastructure error or unknown execution; do not encode every failure as a misleading green map. The structured result remains authoritative even when logs are verbose.

No automatic cold suite should follow an ordinary failed warm probe. That is different from banning cold diagnostics: when the subject is classpath, startup, AOT/direct linking, process-global state, an unsupported reload, or a different platform, an isolated focused run is the relevant early experiment. “Cold last” is a default scheduling optimization, not a command to debug a new JVM defect in an old JVM.

Before calling a future target implemented, test its public Make entrance with a fake client/verifier for wrong port, no tests, test errors, timeout, dirty oracle, stale basis, missing proof and nonzero exit after a success-looking log. Assert that warm failure starts no cold child. Add a small real managed-JVM witness for changed test reload, deletion/stale-Var detection, fixture restoration and competing clients. These tests exercise the apparatus’s decisions; they should not benchmark JVM startup on every unit-test invocation. Run the repo’s own acceptance on the apparatus change. **`round` is a useful scar collection, not yet the reference implementation of this contract.**

Its phase structure, branch-build grading and closure of inherited lock descriptors are valuable. The inspected code nevertheless has specific evidence gaps:

- At [line 481](/home/forge/bin/round:481), `committed*` sets the unit oracle to pass. A commit state proves neither named checks nor `verification_complete=true`; it could accept a probe-only state. Parse EDN and inspect the exact gate results and candidate identity.
- `CALL_RC` and `WRC` are captured but not required by the final success predicate. Oracle and guard success are scraped from text; a process can print a success line and subsequently fail. Require terminal statuses/exits as well as structured results and execution counts.
- Adopt mode takes `.round.adopt.lock` instead of `.round.lock`. The normal path does not consult the adopt marker. Once the adopted builder exits, a normal round can acquire its distinct lock while the adopter is still grading.
