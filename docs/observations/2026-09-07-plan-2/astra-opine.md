My commitment: **Fable's reading is incomplete, with the practical direction mostly right.** The durable rule is: let the model supply irreducible decisions in one program or compact mapping; let the tool derive reusable facts and mechanical consequences, compile them against one snapshot, and return evidence sufficient to stop doing that work elsewhere. **What would win this cell.** I would implement the following narrow contract over reusable analysis and transaction machinery. The public name could be `namespace_split` or a batch mode of extraction; the naming is secondary.

Inputs: canonical `workspace_root`; source `{file, lib}`; a full destination array `{lib, file, forms, alias_policy}`; explicit policy for required promotions; source retirement policy; bounded discovery/write roots; optional architectural constraints; and a configured verification profile. The mapping must account for all 141 definition identities, with explicit decisions for the two unmapped names and the malformed historical placeholders. Names select actual definitions; an associated declare is a forward-reference fact, not automatically a second competing definition. Genuine duplicate definitions or unowned top-level effects require an explicit decision. Destination lib is authoritative and checked against the path relative to the workspace's source root. Never infer it by searching an absolute filesystem path for the first string `src`.

A normal authorized request needs no caller-file list, precomputed reference counts, extraction order, per-owner replacement strings, preflight inspect, or intermediate namespace fixes. The payload is O(mapping size), which is entirely reasonable; it is not O(number of downstream caller sites). Under an explicit `promote-required` policy, the tool derives the minimal promotion set and reports every promotion with a reason. If the user instead authorizes only a named set, missing promotions refuse as one grouped decision set. An alias policy must cover collisions against external aliases such as the existing `portal`, using a deterministic declared fallback.

One-call semantics: freeze the source set and mapping once; resolve references once; construct the **final** namespace graph from all destinations simultaneously; derive imports, required libspecs, aliases, promotions and caller rewrites; preserve source text except owned edits; handle forward references within each destination; stage the source deletion, twenty files, and all discovered caller changes together; validate all future files and the final graph; run required acceptance at that snapshot; then publish one failure-atomic result with guarded undo. No twenty calls hidden behind one transport call, no repeated whole-workspace scanning or fresh proof process per destination, and no requirement that temporary partially split programs compile. A failed later destination must not leave nineteen earlier destinations standing. Failure-atomic multi-file writing should be described accurately; do not imply that unrelated filesystem readers can never observe an intermediate write unless isolation actually enforces that guarantee.

The reference contract must cover this fixture's aliases, fully qualified symbols, bare source-local references, first-class values and quoted Vars; distinguish local `edit-form` from the actual Var; retain necessary imports and namespace load dependencies; and treat metadata, declarations, comments and namespace-sensitive syntax deliberately. Rewriting `::keyword`, syntax quotes, macros or dynamic resolution beyond the admitted grammar must either have a faithful witness or return bounded unsupported evidence before writing. “Acyclic” means acyclic for the stated final static graph and evidence coverage, with explicit unknowns. A successful static scan is not a proof that arbitrary runtime behavior is preserved.

The receipt must lead with committed/refused/rolled-back/recovery-required, source-retired status, destination/form/caller/site counts, map and snapshot identity, correct destination namespace set, actual promotions, final graph result and unknown count, and named check outcomes with exit status and duration. Include before/after hashes and guarded inverse/details references. `verification_complete` must say which obligations are complete; independent acceptance remains outstanding unless it was actually run against those bytes. A refusal must distinguish mutation not attempted from restored and restore failed. Return all independent decision blockers together, with an actually usable continuation when one exists. Never promise a missing `next_call` or require ignoring every file to get through a compiler mismatch. The concise receipt can point to a complete manifest; graph details need not be crammed into a misleading O(1) summary.

The analysis read should be a nonmutating projection of **the same compiler**. Given source plus mapping, return definition-to-definition edges with exact source witnesses, projected namespace edges, required promotions with cross-boundary callers, external requires/imports, forward-reference groups, static caller inventory/counts, unmapped/duplicate owners, cycle paths or SCCs, architectural-rule violations, and unresolved cases with coverage bounds. Return a snapshot/map-bound basis reusable for apply. It should support unresolved mappings by returning owner facts and grouped mapping decisions without guessing the architecture. Once the mapping and promotion policy are already authorized, direct mutation invokes this internally; a preliminary read is optional. Requiring analyze→review→apply on every simple eligible call would recreate avoidable turns. A caller that has already computed a candidate program should also be able to submit it through the existing general transaction/admission route with equivalent meaningful verification, rather than reverse-engineering a bespoke DSL.
