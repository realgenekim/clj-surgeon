The worker verifies its PID and original receipt hash, inherits the configured temp directory, and runs pending commands sequentially with fail-fast behavior. It writes an atomic `<id>-closure.edn`, recording commands, actual argv, exits, timestamps, wall time, output evidence and source-inventory hashes before and after each command. A moved source snapshot refuses closure as stale. There is no late rollback of caller changes. This avoids a JVM future whose lifetime depends on the caller and avoids requiring the caller to remember a printed one-shot command.

The original receipt stays `verification_complete=false` forever. CLI `:op :proof-status :receipt ORIGINAL` reads original and closure, validates identities and the current candidate hash, and reports complete/pending/failed/stale. Failed and stale CLI status exits nonzero; a dead worker without closure is a named failure. All-zero substantive commands are required for completion; an empty or true-only gate cannot manufacture proof.
