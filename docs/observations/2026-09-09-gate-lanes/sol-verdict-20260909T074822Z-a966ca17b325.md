## Blocking finding

### GATE-LANES-FENCE-001-R3 — a second independent coordinator still recreates a removed root and splits the box semaphore

The repair closes the round-2 reproduction only when the next actor is a
worker under the original coordinator. `try_acquire` now correctly refuses a
missing or replaced root and does not create the root itself. The coordinator
entrance still calls `open_root`, however, and `open_root` executes
`root.mkdir(parents=True, exist_ok=True)` before opening the directory. An
independent coordinator has no inherited `GATE_SLOT_ROOT_ID`, so it has no way
to know that another live coordinator owns the now-unlinked predecessor inode.

I executed the width-one attack using the production `open_root`,
`published_identity`, and `try_acquire` functions:

```text
{'coordinator_a_inode': '2049:7370976',
 'coordinator_b_inode': '2049:7370977',
 'different_roots': True,
 'first_held': True,
 'second_admitted': True,
 'derived_width': 1,
 'bound_violated': True}
```

Coordinator A opened the root, published its identity, and admitted the first
worker. I removed the path while both descriptors remained live. Coordinator B
then ran the same coordinator entrance; `open_root` recreated the path and
published the new inode. A worker using B's published identity was admitted
while A's worker still held the old slot. This is the two-independent-ship case
the box-wide admission mechanism must cover.

The new `test_removed_slot_root_refuses_and_never_splits_the_semaphore` stops
after calling `try_acquire` again. It never starts a second holder/coordinator.
Likewise, `test_two_coordinators_share_one_bound_over_one_root_inode` creates
one root descriptor and three worker processes; despite its name, it does not
execute two coordinator entrances. Its `admitted/admitted/refused` result at
width two is valid evidence for workers sharing one intact inode, but it cannot
witness the failure above.

This is not an eligible bounded self-fix in the fence. It requires a stable
cross-process identity or admission authority that remains discoverable when
the slot-root pathname is removed, plus an oracle that actually starts two
independent coordinators across removal. That changes the gate implementation
under `test/`; repairing the existing code cleanly would delete lines under
`test/`, which the ship-fix contract classifies as
`HOLD reason=oracle-changed` rather than an auto-closeable fix.
