# The +50-point prepared-request routing screen did not replicate at n=10/arm

**Date:** 2026-08-30 Pacific

**Caller:** Codex CLI 0.147.0, `gpt-5.6-sol`, high reasoning, ChatGPT Pro subscription on Anvil `dev-a`; no metered API key

**Decision:** The prepared-request routing effect is not a foundation for the product surface. The registered replication gate failed. Preserve the strong recovery/output signal as a separate hypothesis, not as rescue evidence for routing.

## Answer

The sweep-2 screen moved Surgeon-first routing from 2/4 to 4/4 when an exact guarded request was embedded in the prompt. This fresh-fixture product-result replication did not reproduce that movement:

| Arm | Surgeon-first | 95% Wilson | Environment valid | Exact + verifier | Wrong-subject |
|---|---:|---:|---:|---:|---:|
| U — ordinary inspect result | **10/10** | 72.25%–100% | 10/10 | 10/10 | 0/10 |
| P — result plus prepared request | **10/10** | 72.25%–100% | 10/10 | 10/10 | 0/10 |

The observed `P-U` routing difference is **0 percentage points**. Its 95% Newcombe interval is **−27.75 to +27.75 points**. The preregistered non-replication criterion was an observed difference below +20 points at n=10/arm, so the verdict is **screen-does-not-replicate**.

This is not an equivalence result. The interval still contains materially positive and negative population effects. The bounded conclusion is that the observed +50-point screen did not transfer to this fresh multi-file, forced-inspection, product-returned setting at the registered sample and gate.

## Frozen design

The design, schedule, magnitudes, kill criterion, fixture, proxy, scorer, and replay commands were frozen and pushed before the first measured process. The schedule was:

`U P P U / P U U P / U P P U / P U U P / U P P U`

Every attempt used a fresh committed synthetic repository with three production namespaces. The coherent edit spanned two existing checkout files: two timeout changes, one public Var rename plus its cross-file caller, and three profile-literal changes. A third same-shaped analytics namespace was the wrong-subject distractor.

Both arms were required to call one identical batched `inspect_clojure` request before mutation. U emitted the untouched production result. P appended the exact ready-to-submit seven-edit `edit_clojure` argument object with workspace, files, owner guards, old forms, replacements, and counts prefilled. Production `edit_clojure` and native patch were both preflighted to the same byte oracle. P and U exposed identical schemas and server instructions.

The original remote preflight correctly refused the structural write because the shared service runs as `surgeon` while disposable clones were writable only by `dev-a`. Before any model process, a disclosed addendum made only the synthetic clone files/directories cross-user writable, retained the superseded freeze, refroze the harness, and reran every preflight gate in a new path. No shared install, source tree, or service was changed or reloaded.

## Secondary outcomes

The routing null hides a large assembly/recovery difference, but it remains secondary:

| Outcome | U | P | Registered result |
|---|---:|---:|---|
| Median turns-to-success | 2.0 | 2.0 | **Failed** the predicted ≥1-turn reduction |
| Median output tokens | 1,711.5 | 899.5 | **47.4% lower**, clearing the registered ≥15% prediction |
| Total output tokens | 23,122 | 9,152 | 60.4% lower, descriptive |
| Median complete wall | 45.388 s | 27.123 s | 40.2% lower, descriptive |
| Audited runs with a refused edit | 4/10 | 0/10 | Descriptive recovery-tail evidence |
| Audited route adherence | 6/10 | 10/10 | Descriptive; see scorer audit |

Prepared requests eliminated six guarded-request construction refusals across four U runs. Those runs guessed the caller qualifier incorrectly, received exact count-mismatch refusals with source unchanged, then recovered and completed through Surgeon. This explains why routing remained 10/10 in both arms while U emitted more tokens and had a longer tail.

The frozen scorer initially understated refusals because production MCP failures encode `status=failed`, `structured_content.ok=false`, and `error=null`. A post-cohort audit applied the preregistered definition directly to immutable raw events. It corrected only refusal totals and U route adherence from 9/10 to 6/10. Primary route, turns-to-success, correctness, tokens, safety, interval, and verdict are unchanged; frozen scores and aggregate were not rewritten.

## Interpretation

The registered adoption claim is killed for this build decision: returning the prepared request did not raise Surgeon-first routing because the ordinary inspect result plus the fresh multi-file task already saturated routing at 10/10. That ceiling is itself useful geometry evidence. The treatment's transferable value, if any, is now a different claim: reducing guarded-request assembly errors, recovery output, and wall time after routing has already occurred.

That efficiency claim needs its own primary, powered replication before it supports a product promise. The current cohort cannot promote it merely because the routing prediction failed. Exact correctness and wrong-subject safety passed cleanly in both arms.
