# Label-addressed writes: “think, bang!” over the 1,284× asymmetry

Date: 2026-08-30

Status: design ideation only; no mechanism below is product intent and no experiment was run

Branch: `docs/acejump-designs-20260830`

## Executive answer

The opportunity is not to make the model write terse code. It is to make the
server spend cheap read-side bytes proving and naming everything except the
irreducible decision, then let the model emit only that decision.

The target interaction is:

```text
THINK: read returns a complete, snapshot-fenced label basis, prepared holes,
       candidate effects, structural gaps, copyable slices, and verifier choices

BANG:  model emits {basis + a few labels + novel values}

DONE:  server expands the labels, validates the frozen identity, commits once,
       verifies once, and returns the resolved identities in the receipt
```

This extends the prepared-request first slice at `b445a8c`; it does not create
another preparation path. That slice already proves whole-owner identity,
prefills file/owner/old-source/count guards, and leaves only non-executable null
replacement holes. Its retained limitation is decisive: the final mutation
arguments were still 217 bytes / 69 proxy tokens, essentially identical to the
217 bytes / 68 tokens assembled from scratch. The next slice should stop making
the model serialize the server-generated half of the prepared request.

The portfolio below has 16 mechanisms. The first four deserve the earliest
screens because they attack repeated retries, copied content, prepared-request
re-emission, and whole follow-up turns. Shortening file or owner spellings alone
is not the hill: explicit locator strings were only 4.3% of measured write
traffic, while copied bytes were 73.0%, old-text anchors were 28.5%, and one
avoidable turn costs roughly 222 or more output tokens.

## What is measured, what is estimated

Measured evidence used here:

- input ran at 72,529 tokens/s and output at 56.5 tokens/s: 1,284×;
- write emission fit 3.5237 ms/byte with `R²=0.9807` over a 76× byte spread;
- 195 writes contained 630,138 canonical request bytes: 46.2% new-content
  fields, 42.6% subject fields, and 9.5% JSON structure;
- 73.0% of leaf bytes were copied from prior reads or the refused write, 10.4%
  were rule-generated, and 16.7% were genuinely decided;
- on the immediately addressable population, copied plus rule-generated bytes
  were 91.1% of leaf bytes;
- median retry overlap with the refused write was 99.6%; 62.0% of write-bearing
  missions contained a write refusal;
- prepared-request proxy evidence reduced median output by 30.0% in one cohort
  and 47.4% in its sibling, but the shipped first slice did not shrink the final
  request;
- the external corpus exposed repeated file identity, but only 13.3% repeated
  owner-visible subjects in the covered subset; and
- insertions were 32.19% of changed hunks and 40.55% of changed bytes in that
  external corpus.

Every per-mechanism token number below is a planning estimate, not a new
measurement. Estimates count caller-emitted tool arguments, use the retained
69-token one-form edit as the small-call anchor, and use approximately four
compact JSON bytes per proxy token when no retained exact count exists. Ranges
are deliberately broad. A later preregistration must freeze the exact
tokenizer, catalog, task, baseline, and complete-turn denominator before
claiming a saving.

## The common legal basis

The old mnemonic-label experiment failed correctly. A free-floating `mn/s02`
could be paired with the valid guard for `beta`, mutate `beta`, and return
`ok=true` even when the prose intent named `alpha`. A content checksum did not
repair the authority defect. Naked numeric positions remain forbidden for the
same reason.

The ratified resolution is narrower than “labels are safe.” A label is legal
only as a pointer into identity already proved and retained by the server. The
complete contract is:

1. One successful read captures one immutable `basis` with canonical workspace
   identity and complete file hashes.
2. The read declares one closed label universe for that snapshot. The universe
   may be narrow—for example, the exact objects returned by one read mission—
   but the server labels every eligible member across every advertised kind or
   emits no label basis at all. There is no partial or selectively flattering
   table.
3. Each label maps injectively to one typed record containing the operation
   kind, project-relative file, independently proved owner token/range, exact
   before bytes or hash, and allowed lowering. `b445a8c` is the minimum owner
   proof: the server-owned source-anchor producer supplies outer geometry and
   an independent parse proves exactly one structural owner token.
4. A label write is all-or-none. Every referential value comes from one basis;
   the request cannot mix raw positions, another basis, or an unlabeled target.
   New caller-authored code is not referential and remains literal.
5. Resolution is exact. Unknown, expired, stale, cross-workspace, cross-kind,
   duplicate, omitted, or mixed-basis labels refuse before write. There is no
   prefix, fuzzy, nearest, index fallback, or silent rebase.
6. The ordinary compiler still owns schema validation, disjointness, snapshot
   capture, parse, formatting, atomicity, verification, and rollback.
7. The success receipt echoes every submitted label beside its complete
   resolved file, owner, operation, before hash, result hash, and canonical
   effect identity. The receipt never returns counts or hashes alone.

A common wire envelope could look like this:

```json
READ -> {
  "basis": "B7K",
  "snapshot": {"src/demo.clj": "sha256:old"},
  "labels_complete": true,
  "label_universe": {"kinds": ["replace", "gap", "slice"], "members": 2},
  "labels": {
    "R1": {"kind": "replace", "file": "src/demo.clj", "owner": "render", "owner_token": [4, 10], "before_sha256": "sha256:leaf"},
    "G1": {"kind": "gap", "file": "src/demo.clj", "owner": "render", "between": ["binding:x", "body:0"]}
  }
}

WRITE -> {"basis": "B7K", "fill": {"R1": "(new-form)"}}

RECEIPT -> {
  "committed": true,
  "basis": "B7K",
  "resolved_effects": [
    {"label": "R1", "file": "src/demo.clj", "owner": "render", "operation": "replace", "before_sha256": "sha256:leaf", "result_sha256": "sha256:new"}
  ],
  "canonical_effect_identity": {"version": 1, "sha256": "sha256:effect", "files": 1, "effects": 1}
}
```

This makes reference drift structurally impossible: `R1` cannot resolve to a
subject other than the one recorded for `R1`. A caller can still deliberately
choose a different valid label, just as it can deliberately type the wrong
fully qualified owner. That is semantic choice, not hidden pointer drift; the
receipt makes the choice fully legible. If product intent ever requires the
server to infer private prose intent and reject a coherent but unintended
member, every label mechanism below is dead—the server has no such authority.

## Ranking method

The requested ranking is `(emission saved × plausible frequency) / risk`.
Because the mechanisms have not run, the table uses coarse preregistration
inputs rather than fake precision:

- `E` emission saved: 1 = under 20 tokens, 3 = 50–200, 5 = 500+ or a whole turn;
- `F` plausible frequency: 1 = rare specialist operation, 5 = common measured recovery path;
- `R` risk: 1 = pure closed replay, 5 = new expressive language or semantic planner;
- priority index = `E × F / R`.

The index orders screens, not implementation. A wrong-subject path, a new
model/tool turn, or a correctness loss kills a mechanism regardless of score.

| Rank | Mechanism | E | F | R | Index | Estimated paid-output change |
|---:|---|---:|---:|---:|---:|---|
| 1 | Refusal delta replay | 5 | 5 | 2 | 12.5 | retry 200–2,000+ T -> 12–40 T |
| 2 | Copy-slice composition | 5 | 4 | 2 | 10.0 | copied content/anchors -> 15–35% of current call |
| 3 | Prepared-hole bang | 4 | 4 | 2 | 8.0 | 69 T small edit -> 12–25 T plus novel code |
| 4 | Managed bang with verification | 5 | 4 | 3 | 6.7 | add 3–8 T; delete a 222–620+ T follow-up turn |
| 5 | Structural leaf/range patch | 4 | 4 | 3 | 5.3 | 69–300 T -> 10–40 T plus replacement |
| 6 | Preview accept | 5 | 2 | 2 | 5.0 | full reviewed request replay -> 5–12 T |
| 7 | Namespace delta card | 3 | 3 | 2 | 4.5 | 50–200 T -> 12–35 T |
| 8 | Structural insertion gap | 4 | 3 | 3 | 4.0 | 50–250 T -> 10–25 T plus inserted code |
| 9 | Closed candidate choice | 5 | 2 | 3 | 3.3 | 100–1,000 T -> 6–20 T |
| 10 | Relation skeleton fill | 5 | 2 | 3 | 3.3 | 300–1,500 T -> 20–100 T plus novel values |
| 11 | Whole-owner delete set | 3 | 2 | 2 | 3.0 | 30–150 T -> 8–25 T |

## 1. Refusal delta replay

**Design.** Treat a write refusal as the next rich read. The server retains the
fully parsed, snapshot-fenced request and returns a repair basis containing only
mechanically caller-owned holes. The repair grammar cannot add, remove, or
change a target; it can only replace fields the refusal already proved invalid.

```json
READ/REFUSAL -> {"repair_basis":"X4","reason":"expect-count-mismatch","fixed":{"targets":"locked"},"holes":{"H1":{"path":"edits[2].matches","allowed":"positive-int"}}}
WRITE -> {"repair_basis":"X4","fill":{"H1":2}}
RECEIPT -> {"repair_basis":"X4","resolved_effects":[{"label":"E2","file":"src/a.clj","owner":"f","operation":"replace"}],"committed":true}
```

**Emission.** A retry currently overlaps the refused call by a median 99.6%.
Replacing a 200–2,000+ token replay with basis plus one or two values should
cost 12–40 tokens, often saving 90–99% and one construction-recovery turn.

**Wrong-subject defense.** Target fields are absent from the repair language.
They remain the exact resolved targets from the refused request. Any target,
basis, or operation drift refuses; the receipt echoes those locked identities.

**Cheapest screen and kill.** Zero-model replay every retained refusal whose
retry changed at most one mechanically classifiable field. Compile the delta
and compare canonical future or canonical refusal. Kill if any repair can
change a subject/effect kind, if exact parity is below 100%, or if the eligible
share is below 20% of write refusals.

**Support/threat.** Strongly supported by the 99.6% overlap and 62.0% refusal
incidence in `935cc0d`. Threatened by the non-executable retry-template laws and
Option C boundary in the prepared-request LLD: this needs its own correction
algebra and cannot silently upgrade existing refusal authority.

## 2. Copy-slice composition

**Design.** A read labels every complete source slice that can be copied into a
future value. The model constructs new content as a short sequence of literal
fragments and exact slice labels. Target labels and content labels are typed
separately.

```json
READ -> {"basis":"B7K","slices":{"S1":"(assoc state :status","S2":":complete)"},"slices_complete":true}
WRITE -> {"basis":"B7K","fill":{"R1":[{"copy":"S1"},{"literal":" :at now "},{"copy":"S2"}]}}
RECEIPT -> {"resolved_effects":[{"label":"R1","file":"src/demo.clj","owner":"advance","operation":"replace"}],"rendered_result_sha256":"sha256:new"}
```

**Emission.** Copied and rule-generated data were 83.4% of all leaf bytes and
91.1% on the addressable population. A realistic first gate is to reduce
eligible calls to 15–35% of current emitted arguments; a 400-token replacement
with 80% copy coverage becomes roughly 80 novel tokens plus 10–30 recipe
tokens.

**Wrong-subject defense.** Copy labels carry content only; they never select a
mutation target. `R1` independently proves the target. Every copied slice is
exactly snapshot-bound, ordered, rendered server-side, reparsed, and hashed in
the receipt.

**Cheapest screen and kill.** Greedily encode the retained addressable corpus
against only slices present in its preceding read, then exact-round-trip every
result. Kill if any byte differs, median saving is under 40%, recipe tokens
exceed literal tokens, or comments/reader forms cannot be preserved exactly.

**Support/threat.** Supported by the 73.0% copied-byte result in `935cc0d` and
the 1,284× input license. Threatened by the wrapped-EDN no-go `d0c11a5`: fewer
bytes can still mean more tokens, so tokenizer scoring is mandatory.

## 3. Prepared-hole bang

**Design.** Keep the existing successful-read `prepared_request`, but retain
its guarded arguments under a basis and label each null hole. The model submits
only hole values. There is no second prepare tool and no duplicate public edit
object.

```json
READ -> {"basis":"P9","prepared_request":{"executable":false,"write_authority":false,"holes":{"H1":{"target":"src/demo.clj#render","kind":"replacement"}}}}
WRITE -> {"basis":"P9","fill":{"H1":"(defn render [x] (view x))"}}
RECEIPT -> {"basis":"P9","resolved_effects":[{"label":"H1","file":"src/demo.clj","owner":"render","operation":"replace"}],"verification_complete":true}
```

**Emission.** The measured small final edit was 69 argument tokens after hole
fill. Basis plus one hole should be 12–25 tokens plus the novel replacement,
saving roughly 45–60 tokens on a small edit and hundreds across six prepared
forms. Unlike the current slice, this is an actual final-call compression
claim.

**Wrong-subject defense.** `H1` is minted only after the complete `b445a8c`
owner-token proof. It is typed as a replacement hole for exactly one prepared
edit; the caller cannot replace its file, owner, old source, count, or
operation. Stale current bytes refuse before write.

**Cheapest screen and kill.** Extend the existing one- and six-form live-route
fixture without model calls. Fill labels, expand through the ordinary public
compiler, and require byte-identical future source and canonical effect
identity. Kill if final argument tokens fall by under 30%, any old public
guard is bypassed, or basis retention creates a second executor.

**Support/threat.** Directly supported by `b445a8c`, the recovery results, and
the cheap +147/+344 token read-side costs in `9f2b1ba`. Threatened by
`MCP-OP-PREP-REQ-003`, which currently forbids opaque references; this is a
future ratified slice, not a compatible implementation detail.

## 4. Managed bang with verification

**Design.** The read publishes closed project-owned verification cards. Any
label write may add one verifier label. The server expands the mutation, runs
the formatter/linter/exact tests inside the same managed transaction, and
returns a terminal receipt. The model does not narrate or schedule those steps.

```json
READ -> {"basis":"B7K","verify":{"V1":{"name":"affected-clojure","commands":"server-owned","rollback":true}}}
WRITE -> {"basis":"B7K","fill":{"R1":"(new)"},"verify":"V1"}
RECEIPT -> {"resolved_effects":[{"label":"R1","file":"src/demo.clj","owner":"render","operation":"replace"}],"verification":{"label":"V1","complete":true},"next_action":"none"}
```

**Emission.** The write pays about 3–8 extra tokens for `verify:"V1"` but can
delete a 222–620+ token formatting/testing/finalization turn. This is the first
proposal whose main prize is turn deletion, not request bytes.

**Wrong-subject defense.** Verifier selection never changes the effect set.
The verifier is repository-owned, closed, and resolved only after the same
label basis expands to explicit identities. The receipt binds verifier outcome
and effects to one transaction.

**Cheapest screen and kill.** Zero-model classify post-write command sequences
whose complete arguments are determined before the write. Compare them to
registered verifier profiles. Kill if fewer than 30% of write turns have a
fully deterministic deletable suffix, if the profile needs caller judgment,
or if verification can run outside rollback.

**Support/threat.** Supported by the 5,499 post-decision actions in `935cc0d`
and the existing managed verifier architecture. Threatened by the ceremony
audit `7682abf`: a terminal flag alone did not delete behavior, so the server
must execute the work and return terminal evidence, not merely suggest stopping.

## 5. Structural leaf/range patch

**Design.** A read labels exact structural leaves and exact contiguous sibling
ranges inside independently proved owners. The label fixes both range and
operation; the write supplies only replacement bytes.

```json
READ -> {"basis":"B7K","ranges":{"R4":{"file":"src/demo.clj","owner":"transition","kind":"replace-range","source":"[:finish (assoc state :status :complete)]"}}}
WRITE -> {"basis":"B7K","replace":{"R4":"[:finish (finish state)]"}}
RECEIPT -> {"resolved_effects":[{"label":"R4","file":"src/demo.clj","owner":"transition","operation":"replace-range","before_sha256":"sha256:old"}]}
```

**Emission.** The retained 69-token small edit becomes roughly 10–20 envelope
tokens plus replacement. Larger old anchors disappear, attacking the 28.5% of
leaf bytes spent on `find` and `from`; 40–80% savings is plausible on eligible
local edits.

**Wrong-subject defense.** A range label is not a line or preorder. It points
to a frozen structural address inside one named owner, includes exact old
bytes/hash, and admits only replacement of that range. Duplicate source in
another owner is irrelevant.

**Cheapest screen and kill.** Encode every retained `edit_clojure` call whose
preceding read returned the exact old subtree. Expand and compare canonical
effects. Kill on any ambiguous range, any comment/metadata loss, less than 25%
eligible-call coverage, or less than 30% median token saving.

**Support/threat.** Supported by the existing `replace-subform` plan contract
and the unmeasured old-anchor opportunity named by `935cc0d`. Threatened by the
positional wrong-owner witness `5347ad8`; raw lines/preorders must never enter
the write grammar.

## 6. Preview accept

**Design.** When the caller already requested a non-mutating preview and the
server produced one exact effect candidate, the result retains that candidate
under an accept label. The next write is only acceptance; it cannot alter the
candidate.

```json
READ/PREVIEW -> {"basis":"Q2","candidate":{"C1":{"resolved_effects":[{"file":"src/demo.clj","owner":"transition","operation":"replace"}],"future_sha256":"sha256:new"}},"write_authority":false}
WRITE -> {"basis":"Q2","accept":"C1"}
RECEIPT -> {"accepted":"C1","resolved_effects":[{"file":"src/demo.clj","owner":"transition","operation":"replace"}],"result_sha256":"sha256:new"}
```

**Emission.** Replaying a 100–1,000 token reviewed request becomes 5–12 tokens.
It does not add a preview turn: it only applies where that turn already exists.

**Wrong-subject defense.** Acceptance has no editable fields. Candidate `C1`
contains the complete already-reviewed effect identity and future hash. Current
source must still match the frozen basis; otherwise acceptance refuses.

**Cheapest screen and kill.** Replay retained preview/apply pairs. Require exact
candidate/final canonical effect identity and future hashes. Kill if fewer than
90% of existing preview paths can bind exact identity, if acceptance permits a
field override, or if an extra preview is needed to create eligibility.

**Support/threat.** Supported by hash-fenced saved-plan precedents and the law
that an opaque ID may consume previously proved identity. Threatened by the
discovery crossover `f6ac0b5`: adding preview to a supplied-decision task is a
route regression and is forbidden.

## 7. Namespace delta card

**Design.** A read of the namespace form returns labels for every exact require
entry plus one typed insertion hole. The model states only add/remove/rename
decisions; the server owns clause spelling, sorting, and old-source guards.

```json
READ -> {"basis":"N3","requires":{"Q1":{"lib":"clojure.string","alias":"str"},"Q2":{"lib":"cheshire.core","alias":"json"}},"insert":"QI"}
WRITE -> {"basis":"N3","require":{"remove":["Q2"],"add":[{"at":"QI","lib":"jsonista.core","as":"j"}]}}
RECEIPT -> {"resolved_effects":[{"label":"Q2","file":"src/demo.clj","owner":"ns","operation":"require-remove"},{"label":"QI","file":"src/demo.clj","owner":"ns","operation":"require-add"}]}
```

**Emission.** A 50–200 token full namespace edit becomes roughly 12–35 tokens.
The model still authors new library and alias identity; it no longer repeats
the namespace form or clause syntax.

**Wrong-subject defense.** Existing-entry labels resolve only inside the exact
namespace form. The insertion hole is a typed structural clause position, not
a line. The server never guesses a library, alias, or remove candidate.

**Cheapest screen and kill.** Re-encode retained namespace edits, expand with
the current require-change compiler, and compare exact future bytes. Kill if
comments or reader conditionals drift, token saving is below 25%, or any label
can resolve outside the namespace owner.

**Support/threat.** Supported by the closed relation/require champion and the
splice audit’s finding that much exemplar echo sat in require clauses.
Threatened by CLJC platform complexity and by comments: unsupported shapes
must omit the card, not canonicalize them speculatively.

## 8. Structural insertion gap

**Design.** A read enumerates every safe structural gap in one owner and gives
each gap a typed label such as before-owner, after-binding, or between-siblings.
The write supplies only the inserted form.

```json
READ -> {"basis":"B7K","gaps":{"G3":{"file":"src/demo.clj","owner":"render","kind":"between-siblings","left_sha256":"sha256:l","right_sha256":"sha256:r"}}}
WRITE -> {"basis":"B7K","insert":{"G3":"(audit! x)"}}
RECEIPT -> {"resolved_effects":[{"label":"G3","file":"src/demo.clj","owner":"render","operation":"insert-between"}]}
```

**Emission.** The request becomes 10–25 tokens plus inserted code, deleting
file/owner/anchor repetition. On a 150-token insertion call with 80 tokens of
new code, the estimate is about 90–105 tokens: 30–40% saved.

**Wrong-subject defense.** The label denotes a gap bounded by two exact
structural siblings inside a named owner. It is not a line or “after” string.
Either neighbor, owner, or file drift invalidates the basis before write.

**Cheapest screen and kill.** Encode retained insertion calls with the nearest
preceding exact read. Require byte-identical expansion. Kill if fewer than 25%
of insertions have a provable gap, if detached comments enter any gap, or if
any duplicated neighbor pair can select two locations.

**Support/threat.** Supported by the external 32.19% hunk / 40.55% byte
insertion share. Threatened by the splice no-go `db937f5`: one textual anchor
was insufficient and `after` semantics were dangerous. Two structural
boundaries are mandatory.

## 9. Closed candidate choice

**Design.** For a caller-supplied mechanical question, the read may enumerate
all exact legal effects and label them. The model chooses one candidate; it
does not reconstruct the effect. The server may enumerate, never rank or
recommend.

```json
READ -> {"basis":"C8","question":"resolve-exact-alias-collision","candidates_complete":true,"candidates":{"C1":{"owner":"parse","effect":"qualify json/read-value"},"C2":{"owner":"parse","effect":"rename local json -> codec"}}}
WRITE -> {"basis":"C8","choose":"C2"}
RECEIPT -> {"chosen":"C2","resolved_effects":[{"file":"src/demo.clj","owner":"parse","operation":"rename-binding"}]}
```

**Emission.** A 100–1,000 token mechanically detailed request becomes 6–20
tokens. The cheap read can be very large because it presents every candidate
with full identity.

**Wrong-subject defense.** Enumeration is complete and each candidate is a
fully compiled effect, not a similarity hint. Choosing `C2` cannot partially
mix with `C1`, and the receipt echoes the full chosen effect.

**Cheapest screen and kill.** Start with one closed existing decision algebra,
enumerate all legal candidates from frozen fixtures, and compare chosen effects
to ordinary explicit requests. Kill if completeness cannot be proved, the
candidate set exceeds a fixed bound, any candidate needs semantic ranking, or
choice adds a turn to a task that already supplied the effect.

**Support/threat.** Supported by constrained JSON decoding and closed operation
algebras. Threatened by the bookkeeping-over-judgment law and `f6ac0b5`:
candidate generation must not become a planner or discovery tax.

## 10. Relation skeleton fill

**Design.** The read recognizes repeated exact decisions and returns a
guard-complete relation skeleton with labeled site groups and null decision
holes. The model fills one value per group instead of restating the decision at
every site.

```json
READ -> {"basis":"L5","relations":{"G1":{"sites":["R1","R2","R3"],"from":"old.ns/name","holes":["to"]}}}
WRITE -> {"basis":"L5","fill":{"G1.to":"new.ns/name"}}
RECEIPT -> {"resolved_effects":[{"label":"R1","file":"src/a.clj","owner":"f","operation":"replace"},{"label":"R2","file":"src/b.clj","owner":"g","operation":"replace"},{"label":"R3","file":"src/c.clj","owner":"h","operation":"replace"}]}
```

**Emission.** The retained 51-effect relation request was 2,871 bytes after a
large compression win. A server-held site skeleton could reduce a 300–1,500
token multi-site call to 20–100 tokens plus new values, potentially 70–95%.

**Wrong-subject defense.** Every site label already holds complete identity;
the relation hole can change only the shared decision. Site membership is not
caller-editable in the bang call, and the receipt expands every resolved site.

**Cheapest screen and kill.** Derive skeletons from retained exact reads and
explicit correct writes, then expand filled values to the existing ordinary
compiler. Kill if any site membership is inferred from similarity, expansion
does not exactly match the explicit effect multiset, median saving is below
40%, or a new discovery turn is required.

**Support/threat.** Supported by the closed-relation 7.35× win and the pure
`replacement_groups` work. Threatened by the declaration-first census:
subjects repeated little (44 distinct / 47 occurrences), so the server must
already need the read for another reason; a label-table turn cannot pay for
itself.

## 11. Whole-owner delete set

**Design.** A forms read labels every deletable whole owner in its declared
universe. The bang contains only a set of delete labels.

```json
READ -> {"basis":"D6","deletable_complete":true,"owners":{"D1":{"file":"src/demo.clj","owner":"legacy-a"},"D2":{"file":"src/demo.clj","owner":"legacy-b"}}}
WRITE -> {"basis":"D6","delete":["D1","D2"]}
RECEIPT -> {"resolved_effects":[{"label":"D1","file":"src/demo.clj","owner":"legacy-a","operation":"delete-owner"},{"label":"D2","file":"src/demo.clj","owner":"legacy-b","operation":"delete-owner"}]}
```

**Emission.** A 30–150 token `delete_owners` request becomes 8–25 tokens. The
larger saving is avoiding exact owner/source reconstruction after a read.

**Wrong-subject defense.** Delete labels are typed only for complete top-level
owners proven by owner-token range. No leaf, namespace, or approximate owner
can enter the delete set. Unknown, duplicate, or mixed-basis labels refuse the
whole transaction.

**Cheapest screen and kill.** Encode every retained multi-owner deletion,
expand, and compare deleted owner-token ranges and future hashes. Kill on any
range overlap, attached-comment loss, non-whole-owner deletion, or under 25%
median token saving.

**Support/threat.** Supported by the existing atomic multi-owner deletion
contract and `b445a8c` identity proof. Threatened by the old label falsifier;
the receipt must name every deleted owner, never only counts or a basis hash.

## 12. Resolved rename/migration card

**Design.** A semantic read resolves one exact Var or binding and returns a
complete migration card: definition, references, exclusions, and a single
new-name hole. The bang supplies only the new name.

```json
READ -> {"basis":"M4","migration":{"M1":{"subject":"demo.core/old-name","definition":"R1","references":["R2","R3","R4"],"complete":true,"hole":"new_name"}}}
WRITE -> {"basis":"M4","fill":{"M1.new_name":"new-name"}}
RECEIPT -> {"resolved_effects":[{"label":"R1","file":"src/core.clj","owner":"old-name","operation":"rename-definition"},{"label":"R2","file":"src/use.clj","owner":"call","operation":"rename-reference"}]}
```

**Emission.** Explicit multi-file migration can cost 500–2,000 tokens. A name
hole plus basis should cost 10–30 tokens, a 90%+ request reduction on large
closures.

**Wrong-subject defense.** The initial semantic subject must be exact and
owner-token anchored. The server returns a complete reference universe or no
migration card. The bang cannot add/remove sites or reinterpret the symbol;
all resolved sites are echoed.

**Cheapest screen and kill.** Use only retained migrations with a frozen
explicit oracle. Compare card expansion to the explicit canonical effect set.
Kill if any reference is missing/extra, any dynamic or unresolved use is
silently admitted, the semantic basis is stale, or the bang can alter closure.

**Support/threat.** Supported by the existing semantic prepare-change and
closed symbol-migration machinery. Threatened by incomplete reference
surfaces and the discovered-vs-supplied crossover; this is valuable only after
the read was already necessary and complete.

## 13. Create-form skeleton holes

**Design.** A read returns neutral code skeletons anchored to exact insertion
gaps. Skeletons contain typed holes for the decisions the model must make—name,
arguments, body, metadata—while the server owns mechanical syntax and placement.

```json
READ -> {"basis":"K2","skeletons":{"K1":{"kind":"defn-after-owner","at":"G5","template":"(defn {{name}} [{{args}}]\n  {{body}})","holes":["name","args","body"]}}}
WRITE -> {"basis":"K2","fill":{"K1.name":"ready?","K1.args":"state","K1.body":"(= :ready (:status state))"}}
RECEIPT -> {"resolved_effects":[{"label":"K1","file":"src/demo.clj","owner":"ready?","operation":"insert-owner","gap":"G5"}]}
```

**Emission.** The model still writes the novel body. Mechanical boilerplate and
placement disappear, plausibly saving 20–60% on small new definitions and less
on large bodies.

**Wrong-subject defense.** The gap is snapshot-fenced. Skeleton kind fixes the
syntactic operation; holes cannot contain file/owner coordinates. The complete
rendered form is parsed, duplicate-owner checked, and echoed before commit.

**Cheapest screen and kill.** Re-encode retained newly inserted definitions
against a fixed small skeleton catalog. Kill if coverage is below 20%, token
saving below 20%, any source formatting/comment is lost, or the catalog needs
semantic template selection rather than caller choice.

**Support/threat.** Supported by cheap read-side skeleton bytes and constrained
hole schemas. Threatened by EDN/tokenizer results and by boilerplate being a
small share of large authored bodies.

## 14. Receipt-addressed undo

**Design.** Every committed label write may return one short undo label bound to
the existing inverse receipt and exact forward-result hashes. A later bang can
request only that undo label.

```json
READ/RECEIPT -> {"undo":{"U1":{"workspace":"same","files":{"src/demo.clj":"sha256:forward"},"resolved_effects":[{"file":"src/demo.clj","owner":"render"}]}}}
WRITE -> {"undo":"U1"}
RECEIPT -> {"undone":"U1","restored_effects":[{"file":"src/demo.clj","owner":"render","operation":"restore"}],"verification_complete":true}
```

**Emission.** A 100–1,000+ token manual diagnosis/recovery sequence becomes
5–12 tokens when exact undo is valid. Frequency is low, but avoided damage and
turns make the tail valuable.

**Wrong-subject defense.** `U1` is not a target selector. It points to one
inverse receipt whose complete files/effects were already committed and
returned. Undo requires every current file to equal its recorded forward hash;
it never merges or blind-overwrites.

**Cheapest screen and kill.** Zero-model apply/undo on duplicate-content and
concurrent-drift fixtures. Kill unless exact original bytes return, any drift
refuses before write, root confinement is exact, and the receipt echoes every
restored identity.

**Support/threat.** Supported by the existing hash-fenced undo receipt and the
returned-effect audit `63952c5`. Threatened by adding a new destructive public
operation; promotion requires a separate safety leaf, not label convenience.

## 15. Label program / compact effect chord

**Design.** For mixed but already enumerated effects, the read returns a typed
label alphabet. The bang emits a compact operation chord. Unlike positional
tuples, each opcode admits only labels of its kind and fixed arity.

```json
READ -> {"basis":"Z1","alphabet":{"replace":["R1","R2"],"delete":["D1"],"insert":["G1"]},"grammar":{"r":"replace(label,value)","d":"delete(label)","i":"insert(gap,value)"}}
WRITE -> {"basis":"Z1","program":[["r","R1","(new)"],["d","D1"],["i","G1","(audit!)"]]}
RECEIPT -> {"resolved_effects":[{"label":"R1","file":"src/a.clj","owner":"f","operation":"replace"},{"label":"D1","file":"src/b.clj","owner":"old","operation":"delete-owner"},{"label":"G1","file":"src/c.clj","owner":"g","operation":"insert"}]}
```

**Emission.** A mixed 300-token request might fall to 60–150 tokens, a 50–80%
payload reduction. Constrained decoding can enforce opcode, arity, and label
kind at the sampler.

**Wrong-subject defense.** Each typed label still resolves through the common
basis; opcodes cannot reinterpret label kind. Expansion occurs completely
before source access and the receipt returns the readable effect ledger.

**Cheapest screen and kill.** Purely encode the retained mixed-write corpus and
round-trip to canonical requests. Kill if token saving is below 35%, any valid
program can lower two ways, the readable receipt exceeds a fixed attention
budget, or a model-free mutation with one wrong-kind label does not refuse.

**Support/threat.** Supported by constrained JSON decoding. Threatened by the
positional-tuple and file-index failures, the wrapped-EDN token reversal, and
grammar discoverability. It ranks low because compact syntax compounds errors
even when the server is safe.

## 16. Extraction/move manifest choice

**Design.** After an already-required dependency read, the server returns
complete extraction manifests and exact destination cards. The model chooses a
manifest/destination pair and supplies only unresolved policy holes.

```json
READ -> {"basis":"E7","manifests":{"E1":{"source":"demo.core","forms":["a","b","c"],"closure_complete":true}},"destinations":{"D1":{"namespace":"demo.extracted","file":"src/demo/extracted.clj"}},"holes":["visibility"]}
WRITE -> {"basis":"E7","extract":"E1","to":"D1","fill":{"visibility":"preserve"}}
RECEIPT -> {"resolved_effects":[{"label":"E1","file":"src/demo/core.clj","owners":["a","b","c"],"operation":"extract"},{"label":"D1","file":"src/demo/extracted.clj","operation":"create-or-insert"}],"verification_complete":true}
```

**Emission.** Complete extraction requests can cost 500–3,000 tokens. A
manifest choice plus policy holes should cost 20–60 tokens. The absolute prize
is large but the operation is rare.

**Wrong-subject defense.** The manifest is a complete frozen dependency
closure with exact ordered owners; destination identity is explicit and
root-confined. The bang cannot edit closure membership, callers, destination
path, or derived namespace effects.

**Cheapest screen and kill.** Replay retained extractions whose explicit
request and future tree are frozen. Require exact manifest expansion and
future hashes. Kill if any caller/visibility decision remains hidden, if a
destination is inferred, if an extra discovery turn is required, or if
complete-wall saving is projected below one turn.

**Support/threat.** Supported by the exact extraction manifest/compiler path
and the large supplied-decision speed wins. Strongly threatened by `f6ac0b5`:
discovery-required Surgeon lost through 32 changes and six files. Never insert
this read into a supplied-decision route merely to earn a short bang.

## Portfolio rules

The designs share enough machinery to become dangerous if implemented as one
generic handle system. They should instead share only the label-basis kernel:

```text
read-specific proof
  -> closed, typed, all-or-none label universe
  -> immutable snapshot basis
  -> tiny operation-specific bang schema
  -> existing ordinary compiler and transaction
  -> readable resolved-effect receipt
```

Each bang schema gets its own eligibility proof and kill screen. There is no
generic `apply(label, payload)`, no fuzzy label lookup, no client-side label
table, no cross-call ordinal promise, and no universal bytecode in the first
slices.

The build order, if the zero-model screens earn it, should be:

1. refusal delta replay, because frequency and 99.6% overlap are already
   measured;
2. prepared-hole bang, because the first slice and live-route fixture already
   exist;
3. copy-slice composition, because it attacks the largest measured byte class
   without using content labels as target authority;
4. managed verification bang, because deleting a turn dominates byte golf;
5. one narrow structural primitive—range or insertion gap—to validate the
   common basis under a new operation;
6. only then the specialized cards and relation/manifests.

Do not start with the generic chord. The point of “think, bang!” is not to make
the model learn another little language. It is to make almost all of the
language arrive for free in the read.

## Cross-cutting preregistration

Every mechanism’s first screen should freeze these common gates before any
model call:

1. **Identity parity:** expansion must produce the identical explicit files,
   owners, operation kinds, exact before bytes, and canonical effect identity.
2. **Wrong-subject falsifier:** duplicate-content owners/files plus wrong-kind,
   wrong-basis, stale, unknown, and coherently different valid labels. Hidden
   pointer drift must be unrepresentable and every resolved identity legible.
3. **All-or-none vocabulary:** dropping one eligible label or mixing caller and
   server labels must refuse before mutation.
4. **Exact round trip:** candidate future bytes and ordinary explicit future
   bytes must match byte-for-byte, including comments, metadata, commas, reader
   conditionals, and line endings.
5. **Tokenizer gate:** count the actual constrained JSON argument spelling with
   the frozen model tokenizer. Byte saving alone does not pass.
6. **Route geometry:** charge every added read or preview turn. A mechanism may
   consume a read that the task already needed; it may not hide preparation in
   another paid boundary.
7. **Complete-turn gate:** measure first mutation validity, refusals, recovery
   actions, fallback, output tokens, correctness, complete verified wall, and
   terminal actions. Do not promote from argument bytes alone.
8. **Kill precedence:** any wrong effect, missing receipt identity, incomplete
   label universe, stale write, correctness loss, or increased recovery kills
   before efficiency is scored.

Only after those zero-model gates pass should one counterbalanced model cohort
compare ordinary explicit requests with the narrow bang. The model arm must
use the same tool catalog and forced prior read exposure so the test measures
consumption, not discovery or routing. The first promoted claim should be
“less caller-emitted output after the same read,” not “models choose Surgeon
more often.” The prepared-request routing sign flip already killed that story.

## Decision

The killer shape is not a universal two-character address. It is a rich,
complete, immutable read result followed by an operation-specific bang whose
only writable fields are the model’s remaining decisions.

The best immediate bet is refusal delta replay. The cleanest product extension
is prepared-hole bang. The deepest general mechanism is copy-slice
composition. The largest complete-task prize is managed verification that
deletes the next turn. All four reuse existing evidence, attack measured cost,
and can be killed cheaply before any model cohort.

That is the practical meaning of “think, bang!”: think against a lavish read;
bang only the delta; receive a receipt that says exactly what happened.
