# MCP vs CLI: what needs the server, what the CLI carries today, and the one build that closes the gap

Written 2026-09-10T03:14Z by forge@anvil from the day's records and Astra's frontiers consult (2026-09-10-astra-frontiers.md, §CLI). Gene's question, verbatim: "how much of the wins can be had with cli?" and "Document MCP vs cli".

## The answer in one line

Every measured speed win of the last two days lives in files, make targets, and seat scripts; none of it needs the MCP server. The server is needed only for the two routed edit classes, and for those the current CLI is a worse door because one of them has no CLI entrance at all.

## The numbers, stated the way the records allow

- 100% of the measured 335-second gate saving is attributable to machinery an MCP-free path can carry.
- For "the Surgeon wins" as a collection, no percentage is defensible: the records mix isolated-gate wall, red-feedback wall, historical candidate clocks and successful ship attempts; preservation and attestation have no measured speed win. Adding deltas would double-count and mix denominators.
- A cloned repo plus the CLI binary does not possess the ship/land package or the parked preservation tool; with the repository gate and correctly packaged seat tools it obtains the generic mechanisms.

## The 2.2× CLI scar, sized correctly

September 2's K arm made 6.0 typed refusals per task against MCP's 2.7, over 19 CLI invocations against 6.7 MCP calls; mean wall 685 s vs 725 s, inside the measured floor (2026-09-02-captains-log-bridge-wall-clock-ideal-program.md:1302). The failure mechanism was help discovery, receipt-path plumbing, duplicated locating and extra calls. It argues against wrapping the old per-form workflow in more shell. It does not show that the direct split CLI must lose, and it predates the whole-intent winners.

## What an MCP-free path gives up, and what it does not

Gives up: model-visible MCP schemas, persistent process caches and prepared semantic state, structured tool results, the exposed alias-migration handler. Does not give up: native patches, bounded structural CLI reads, the exact split, complete cold tests, independent preservation checking, a qualified observer, a trustworthy landing consumer. "No MCP server" is compatible with a test JVM or an independent recorder; "no persistent processes of any kind" also loses the warm feedback treatment.

## The one CLI build worth buying (Astra, adopted)

A single request-file entrance backed by the same executor and receipt contract as MCP. Close the actual hole first, whole-repository alias migration, then route the exact split through the same public contract. No second planner, no shell-to-MCP proxy. Accept the same typed whole-intent data; manage receipt artifacts outside the candidate automatically; emit one bounded machine-readable result plus a transport-correct next action; preserve explicit mutation state, pending proof and typed nonzero refusals; help and examples describe the real accepted schema; expose durable status without replaying a committed mutation. Budget: one day for the bounded adapter, one day for parity, refusal/recovery and cold-entry qualification. Qualification: a fresh caller completes an eligible alias task and the exact split with the server absent, without discovering an inner second interface; compare bytes, protected content, refusal/mutation behaviour, proof obligations and terminal states through both entrances; then compare complete caller and landing clocks with equal native equipment, charging startup and help discovery. The same landing consumer must accept qualifying native and CLI evidence without producer favouritism. Package the seat helpers from versioned sources and test the installation layout; do not copy mutable `~/bin` state and call it a product.

## Forge's read, corrected by Astra

I had said the two routed classes "want the server, and the CLI is a worse door to them." Astra's correction: the split already has a direct CLI entrance to the same executor; the alias migration has none; and the 2.2× figure is a per-task refusal count under an old workflow, not a property of the CLI. The door is missing, not worse.
