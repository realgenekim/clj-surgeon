**How `~/bin/land` reads it, by commit sha:**

```bash
# the run for a commit
gh run list --repo realgenekim/clj-surgeon --commit "$SHA" \
  --workflow mcp-main --json databaseId,status,conclusion,url

# the verdict line
gh run view "$RUN_ID" --repo realgenekim/clj-surgeon --log \
  | grep -o 'receipt sha=.*'

# per-job wall and conclusion, machine-readable
gh run view "$RUN_ID" --repo realgenekim/clj-surgeon --json jobs \
  --jq '.jobs[] | {name, conclusion,
                   wall: ((.completedAt|fromdateiso8601)-(.startedAt|fromdateiso8601))}'
```

Note the `gate=…s` figures in the receipt are the *step* walls the jobs measured themselves; the
`gh run view --json jobs` figures are the *job* walls including setup and cache. Both are in this
document; they differ by ~20 s of runner provisioning and they are not the same meter.

`TMPDIR` is the one non-obvious piece. `clj-surgeon.tmp-leak-support` refuses `/tmp` and
`/dev/shm` **by name**, before it consults `/proc/mounts`, because on this seat `/tmp` really is a
tmpfs. So the composite action points `TMPDIR`/`TMP`/`TEMP` at `$RUNNER_TEMP/clj-surgeon-tmp`,
which is on the runner's ext4 workspace disk and passes both the name check and the fstype check.

## Three findings CI produced on its first two runs

**1 — the executable resolver ignores `$PATH`, and nothing said so.**
`mcp-change-buffer/expand-command` walks five hardcoded directories
(`/opt/homebrew/opt/node@20/bin`, `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin`, `/bin`) and
returns the **bare name** when the binary is in none of them. `setup-clojure` puts clj-kondo in
the runner tool cache — on `$PATH`, in none of those five — so `mcp-change-buffer-test` failed
*"resolved clj-kondo must be an absolute path, not a bare name"* and `mcp-cold-verify-test`'s
admission-timeout branch returned `:clj-kondo-executable-unavailable` instead of the timeout.
Both tests are written to be host-independent and they are; the RESOLVER is not. The seat passes
only because its clj-kondo happens to sit in `/usr/local/bin`. CI works around it by linking
clj-kondo there. **The workaround is in the workflow; the defect is in `src/`, unfixed, and is the
first thing to file** — a resolver that silently degrades to a bare name is a `PATH`-dependent
behaviour wearing an absolute-path assertion.

**2 — `mcp-relation-census-test` asserts the BOX has at least 8 cores.**
`(is (= 8 (:pool_size parallel)))` after requesting `:pool_size 8`, while
`relation-census/effective-pool-size` clamps to `(.availableProcessors (Runtime/getRuntime))`. A
standard GitHub runner has 4, so `pool_size` comes back 4 and two byte-for-byte comparisons also
diverge (the receipt gains a `pool_size_requested` key when request ≠ effective). **This is the
ambient-precondition class: an assertion that reads as a product contract and is really a
statement about the seat's 16 cores.** It is the one red cell, left red deliberately — the
correct assertion is `(min 8 (.availableProcessors …))`, or an explicit
`PRECONDITION: >= 8 cores`, and either is a change to `test/` that belongs to the suite lane, not
to a CI branch.

**3 — `make performance-regression-sentinel-test` has been broken and nobody noticed.**
It dies with `Don't know how to create ISeq from: java.lang.Character` before a single test runs —
its `clojure -M -e` recipe is malformed. **Reproduced byte-for-byte on the seat at `63d317a5`**,
so this is a pre-existing defect, not a CI artifact: CI simply ran a target nobody had run in a
while, which is most of the point of having CI. The intent audit itself passes 49/49, so the job
gates on `bash test/performance_regression_sentinel_intent_test.sh` and keeps the broken target as
a visible, non-blocking **KNOWN RED** step. It is not deleted, because deleting it would make the
sentinel's `clojure.test` namespaces silently unrun — the exact `mcp-formatter-test` orphan the
lane manifest exists to prevent.

## Design notes worth keeping

- **The matrix is read from `clj-surgeon.lane-manifest` at workflow time**, by
  `.github/scripts/lane_matrix.clj` in the `plan` job, and emitted through `fromJSON`. A
  hand-maintained matrix in the YAML would be a second authority whose failure mode is silent: a
  new battery namespace would never run in CI while the suite stayed green. The script carries its
  own `--self-test` and refuses a zero-wide matrix by name, because a zero-wide matrix is a job
  that reports success having run nothing.
- **Each cell runs the PRODUCTION runner** via `-m clj-surgeon.mcp-test-runner --ns <ns>`, so the
  manifest's typed refusal is reachable from CI rather than being dead code a witness keeps alive.
- **`fail-fast: false` everywhere.** For a suite whose spike was about flakiness under contention,
  the other ten cells are the evidence, not the noise. A matrix that cancels its siblings on the
  first red tells you one cell failed and hides whether the other ten did.
- **The bb job calls `make test-bb`, never a bare `bb test/run_all.clj`.** Suite-spike round two
  renamed this lane — `test-fast` used to mean the bb suite and now means the JVM fast lane.
  Calling the Make target means a future rename of what the bb lane runs reaches CI by `git pull`,
  not by someone remembering this file exists.
- **`make mcp-test` and `make test-bb` are two JOBS, not two steps.** They share nothing
  but the checkout — different runtime, different dependency set. As steps their walls add on the
  critical path (209 + 141 = 350 s); as jobs the pair costs `max()` = 209 s. Measured, then chosen.
- **Concurrency:** per-ref group, `cancel-in-progress` for `bridge/**` (an obsolete run of a branch
  you already amended is pure queue) but **never for `MCP/main`** — every trunk commit gets a
  complete, citable receipt, and a cancelled run is indistinguishable from one that never ran.
- **`main` is frozen** and appears in no trigger and no ref check in the file.

## One line of learning

**The parallelism was free and the integrity was not.** Fanning eleven battery namespaces onto
eleven runners took one `plan` job and cost nothing, exactly as round one predicted (2-wide cost
6% of wall because 94% of it is subprocesses blocked on their own JVM startup) — but the same two
runs turned up **three defects the seat could not see**, all of the same class: assertions and
resolvers that encode this box (16 cores, clj-kondo in `/usr/local/bin`, a Make target nobody
runs) while reading as statements about the product. A second machine is not a nicety for a tool
that ships to other people's machines; it is the only instrument that can find this class at all.

## One caveat

**The nightly `schedule` is declared and DORMANT.** GitHub runs scheduled workflows only from the
repository's **default branch**, which here is `main` — frozen, and it will never carry this file.
Until `MCP/main` becomes the default branch, the nightly battery is a `workflow_dispatch` someone
(or `~/bin/land`) has to fire, and **a green history is not evidence the nightly ran.** Secondary
caveat: two runs on shared GitHub infrastructure is enough to name a mechanism, not to state a
rate — the 499 s critical-path cell has an unknown variance, and none of the load-fragile
behaviour round one found under contention was reproduced here, because one namespace per VM is
precisely the condition under which it does not occur.
