Not reached by any lane, so not handled here: `flock /home/forge/tmp/suite.lock` and
`MEMBAT_ROOT` / `PARSER_RED_ROOT` live in `memory-red` / `memory-red-kernel`, which the lane
manifest lists under `excluded`. One job per namespace on its own VM is a stronger isolation than
that lock ever was — the lock existed because one box has one set of cores.

`TMPDIR` is the one non-obvious piece. `clj-surgeon.tmp-leak-support` refuses `/tmp` and
`/dev/shm` **by name**, before it consults `/proc/mounts`, because on this seat `/tmp` really is a
tmpfs and the guard does not re-litigate that per host. So the composite action points `TMPDIR`,
`TMP` and `TEMP` at `$RUNNER_TEMP/clj-surgeon-tmp`, which is on the runner's ext4 workspace disk
and passes both the name check and the fstype check.
