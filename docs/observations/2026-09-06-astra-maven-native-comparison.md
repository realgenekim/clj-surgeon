# Astra: prepared real-repository native comparison

Recorded 2026-09-06T08:15:56.611443+00:00. Exploratory evidence, not a shipped performance guarantee.

The forms executor completed the same real Clojure maintenance task with proof at **1.98× the speed of fresh Sol sessions and 1.82× the speed of fresh Astra sessions**. All ten outcomes passed independent replay. Shared task selection, fixture, dossier and proof preparation took **1035 seconds** before the first dispatch; charging it once to each two-attempt route reduces the first epoch's advantage to **1.028×**. The remaining opportunity is making preparation reusable or unnecessary.

## What changed our thinking

1. A prepared typing-and-proof win persists against actual Astra on this task. The stronger-model routing question deserves measurement; the old Sol-only result cannot settle every new mechanism.
2. Setup dominates a one-off job. Charging 1035 seconds once plus two attempts per route leaves only 1.028× in the first epoch. Faster JVM proof can save seconds but cannot explain away seventeen minutes of preparation.
3. Exact deterministic relations should not need another model. A guarded Surgeon reference rename took about 0.197 seconds before proof. That component timing is not a complete native comparison, but argues for choosing an existing deterministic operation when the relation is already decided.
4. Whole-form output avoids diff quoting/whitespace traps but emits more text. Clojure's syntax can support small bounded transformations and mechanically checked authority. The model should supply judgment; the kernel should preserve unrelated bytes, enforce scope and prove the candidate.
5. Warm verification must bind loaded bytes and runtime generation. A REPL proving old source, retaining a removed Var or sharing mutable state across candidates is false feedback. The first warm prototype deliberately refuses changed generations; repeated-identical-proof latency is not yet per-edit latency.

The earlier five-owner prepared cell's 3.29× result and earlier negative JSON/diff cohorts remain separate evidence. Nothing here proves broad adoption, autonomous proof authoring, twenty-owner scaling or a perfect tool. Next useful slices come from actual refusals and delays, are used immediately, and receive a ledger row; confirmatory cohorts support wider claims only after that usage.
