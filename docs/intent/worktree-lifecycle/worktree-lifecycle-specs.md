# Worktree Lifecycle Controller Requirements

These requirements specify the first repository-owned worktree lifecycle
controller. Status `[ ]` marks a specified, unimplemented gap that requires a
direct red witness. Status `[D]` marks a deferred later slice. This slice
removes one handed-off worktree at a time. It never deletes a branch, tag,
remote ref, observation, issue, archive, or retained result.

## Inventory and Classification

- [ ] **WTL-INV-001**: When `worktree-audit` captures repository state, it shall emit one closed versioned snapshot over the union of Git worktree and Supacode worktree identities and shall bind the repository root, common Git directory, primary worktree, controller worktree, Git object format, every Git registration, a stable Supacode bracket, and one bounded remote-advertisement snapshot per configured remote.
- [ ] **WTL-INV-002**: When the controller decodes an existing target or Supacode identity, it shall require an absolute lexical path equal to its canonical real path, reject every symlink component, apply exactly one strict percent decode to a Supacode ID, and refuse malformed, double-encoded, NUL-containing, non-UTF-8, relative, aliasing, or byte-colliding identities before selecting a worktree; a missing Supacode-only identity shall retain its strictly decoded lexical absolute path and remain audit-only as `missing-prunable`.
- [ ] **WTL-INV-003**: When the adapter inspects a registered target, it shall capture exact HEAD, tree, full branch or detached state, Git lock and reason, prunable reason, tracked and untracked status, checkout linkage, and non-force removal preflight including submodule state; an unavailable, malformed, or unknown safety fact shall remain `unknown` and shall never be converted to clean or removable.
- [ ] **WTL-INV-004**: When the pure compiler classifies one union identity, it shall return exactly one of `active`, `dirty-blocked`, `missing-prunable`, `needs-seal`, or `clean-safe` with precedence in that order and shall include stable reason keywords plus the observed repair facts for every non-safe result.
- [ ] **WTL-INV-005**: The compiler shall classify the primary worktree, controller worktree, focused Supacode worktree, pinned Supacode worktree, agent-locked worktree, and worktree owned by another lifecycle lease as `active`, without using age, process-name matching, branch naming, or unlock state as evidence of inactivity.
- [ ] **WTL-INV-006**: If a Git-registered worktree is authoritatively absent from a successful stable Supacode bracket, the compiler shall preserve it as a valid Git identity with UI state `absent`; if Supacode alone retains the identity or Git registration or checkout linkage is missing or broken, it shall classify the identity `missing-prunable` and grant audit-only authority.
- [ ] **WTL-INV-007**: `worktree-audit` shall never archive, remove, lock, unlock, prune, fetch, push, create or update an issue, change Supacode focus, or mutate a repository ref, and shall report unavailable or contradictory authorities rather than omit their rows.

## Owner Handoff and Lifecycle Lease

- [ ] **WTL-HAND-001**: Given a closed outcome request for an agent-locked target, `handoff-worktree` shall validate the target while the owner lock remains present and shall atomically create one handoff record under the common Git directory binding canonical target, HEAD, tree, owner, outcome-request hash, nonce, and schema; an existing different record or multiple live handoffs for the fingerprint shall refuse.
- [ ] **WTL-HAND-002**: After writing a handoff record, `handoff-worktree` shall return the exact final owner unlock command but shall not release the agent lock itself; apply shall accept the handoff only when the owner lock is absent and every recorded identity remains exact.
- [ ] **WTL-HAND-003**: Before applying one plan, the controller shall acquire one per-target operating-system lock and one create-only lifecycle lease that binds the plan and handoff; a foreign lease, multiple leases, multiple unconsumed plans, or a lease for different bytes shall refuse without external mutation.
- [ ] **WTL-HAND-004**: A lifecycle lease shall remain authoritative until completion, explicit cancellation, or a typed recovery transition; the controller shall release only its matching lease immediately before Git removal and shall reclaim or reconcile only that same lease when recovery proves that removal did not occur.
- [ ] **WTL-HAND-005**: For an unlocked legacy worktree, the controller shall infer no owner consent and shall accept only an explicit single-target `legacy-handoff` request from a different controller worktree; the plan and final receipt shall record legacy mode, and legacy mode shall never authorize bulk apply.

## Terminal Outcome Seals

- [ ] **WTL-SEAL-001**: For outcome `landed`, the compiler shall require the target HEAD to be an ancestor of one caller-supplied full landing ref whose exact remote, remote-URL digest, advertised ref, object, and peeled commit when applicable appear in the captured remote snapshot; a local branch, short hash, default-ref inference, symbolic-only ref, or unpeeled annotated tag shall refuse.
- [ ] **WTL-SEAL-002**: For outcome `negative-experiment`, the compiler shall read one repository-relative UTF-8 observation or Captain's Log blob from the exact advertised breadcrumb ref and shall require exactly one closed negative-experiment EDN seal between the fixed markers; absolute or escaping paths, symlinks, submodules, non-blobs, malformed encoding, multiple seals, or unknown seal fields shall refuse.
- [ ] **WTL-SEAL-003**: A negative-experiment seal shall bind the exact experiment commit and tree, require that commit to be reachable from the advertised breadcrumb ref, require the advertised ref to contain the target HEAD, and require every experiment-commit-to-target-HEAD change to be confined to the seal's explicit canonical observation and receipt path set.
- [ ] **WTL-SEAL-004**: If a negative-experiment declares raw evidence `none`, that declaration shall be present in the published seal; if it declares an archive, the seal shall bind an allowlisted durable receipt authority, full receipt ref and path, content-addressed locator outside the target and ephemeral directories, and archive SHA-256, and planning, pre-removal apply, and finalization shall independently revalidate the locator, receipt, and hash without opening or copying raw content.
- [ ] **WTL-SEAL-005**: For outcome `parked`, the compiler shall require a clean branch-backed target whose local HEAD equals one exact advertised upstream remote/ref/object tuple plus one open issue from the declared Beads store and project with exact issue ID, revision, assigned owner, non-empty single-line next action of at most 512 UTF-8 bytes, and future ISO-8601 expiry.
- [ ] **WTL-SEAL-006**: Before Supacode or Git mutation for a parked plan, apply shall append or verify one idempotent parking-intent record binding the plan hash, target HEAD and tree, upstream ref, owner, next action, and expiry; only that byte-identical controller append may advance the captured issue revision, and a divergent same-key record, unrelated revision drift, issue closure, reassignment, remote movement, or expired clock shall refuse before later mutation when possible and otherwise produce a typed partial outcome.
- [ ] **WTL-SEAL-007**: If no single declared terminal outcome satisfies every required seal and current authority, the compiler shall return `needs-seal` or a typed refusal and shall not compile an applicable close plan.

## Reviewed Plan Contract

- [ ] **WTL-PLAN-001**: Given a dry-run close request, the compiler shall accept only one versioned closed request for one canonical target and exactly one outcome, shall refuse unknown or missing fields and contradictory modes, and shall never infer an outcome from branch name, age, cleanliness, or Supacode state.
- [ ] **WTL-PLAN-002**: A compiled plan shall bind canonical target, HEAD, tree, branch or detached state, status, agent handoff, lifecycle-lease prestate `absent`, the derived expected lease identity for that plan, removal preflight, Supacode identity and state, every outcome-evidence blob and hash, exact remote tuples, and the clean controller commit, tree, and artifact hashes; unrelated worktree creation or removal shall not invalidate it, while an existing foreign or different lease or any other target-specific authority drift shall.
- [ ] **WTL-PLAN-003**: The adapter shall serialize plans as canonical UTF-8 EDN with recursively sorted map keys, ordered vectors, no public sets, and one trailing newline; it shall atomically create an owner-only plan file under the common Git directory using a random UUID and a SHA-256 over every semantic byte except its own hash field and shall refuse an existing UUID with different bytes.
- [ ] **WTL-PLAN-004**: A plan, journal, or receipt shall contain only lifecycle identities, hashes, paths, states, refs, issue identifiers, owner, next action, expiry, commands, and outcomes and shall never contain source bodies, prompts, transcripts, tokens, credentials, remote URLs, or environment dumps.
- [ ] **WTL-PLAN-005**: Apply shall require exactly `PLAN=<absolute-plan-path> APPLY=1`, shall refuse loose outcome fields or `APPLY=1` without a previously written valid plan, and shall create no external mutation before it acquires the target lock and lifecycle lease, revalidates the plan, and durably records the prepared journal state.
- [ ] **WTL-PLAN-006**: A plan shall have no time-only expiry, but every apply or recovery shall require exact target and outcome authority equality and, for parked plans, one newly captured controller clock proving the declared expiry remains in the future; one consumed plan shall not close another target or begin another operation.

## Apply, Recovery, and Finalization

- [ ] **WTL-APPLY-001**: Before external mutation, apply shall acquire the per-target operating-system lock and matching lifecycle lease, re-snapshot the target and every outcome authority, require exact agreement with the reviewed plan, and atomically create and fsync the journal file and parent directory at state `prepared`; drift shall refuse without Supacode, Beads, Git, or ref mutation.
- [ ] **WTL-APPLY-002**: The journal shall advance monotonically through `prepared`, `parking-intent-recorded`, `archive-commanded`, `archive-verified`, `remove-commanded`, `remove-verified`, `final-receipt-written`, and `parking-completion-verified`, using atomic replacement plus file and parent-directory synchronization before the next external step; for a non-parked outcome, each parking transition shall be durably recorded with result `:not-applicable` rather than skipped.
- [ ] **WTL-APPLY-003**: Before commanding Supacode archive, apply shall require an available unambiguous stable list, focus, list bracket for the exact target; it shall accept an authoritatively absent or already archived target as an observed postcondition, otherwise archive in the background and verify archived, not focused, and not pinned, and shall never run Git removal after timeout or ambiguous archive completion.
- [ ] **WTL-APPLY-004**: After archive verification and immediately before Git removal, apply shall re-read Git registration, HEAD, tree, branch, status, handoff and lease, outcome evidence, remote refs, parked issue and expiry when applicable, and archive durability; it shall require non-UI facts to equal the plan and UI facts to equal the planned archived state.
- [ ] **WTL-APPLY-005**: If the post-archive safety gate detects drift, apply shall restore the prior Supacode state when this invocation changed it and shall return a refusal when restoration succeeds or a typed partial outcome with exact remedy when restoration fails; it shall not call Git removal.
- [ ] **WTL-APPLY-006**: To remove a worktree, the controller shall run from a different clean worktree, release only the matching lifecycle lease immediately before the command, invoke `git worktree remove` without `--force`, and shall never delete, move, reset, stash, prune, or mutate a branch, tag, remote ref, observation, issue, archive, or retained result.
- [ ] **WTL-APPLY-007**: If Git removal fails after this invocation archived the Supacode surface, the adapter shall attempt to restore that surface and shall report refusal on successful restoration or typed partial recovery on restoration failure; a locked, dirty, submodule-bearing, malformed, or otherwise non-removable target shall remain for human repair.
- [ ] **WTL-APPLY-008**: After Git removal succeeds, apply shall verify that the target path and Git registration are absent and that the branch, refs, outcome evidence, archive hash, and planned terminal Supacode state remain exact before writing a final receipt; the terminal UI state is `absent` when the reviewed plan began authoritatively absent and otherwise `archived`.
- [ ] **WTL-APPLY-009**: The adapter shall atomically write one immutable final receipt under the common Git directory; for a parked outcome it shall then append and verify one issue completion record containing the receipt hash and write one separate immutable completion marker, and shall report parked success only after that marker exists.
- [ ] **WTL-APPLY-010**: On repeat or recovery, the controller shall validate the original plan, journal, lease, and current postconditions and shall resume only the next incomplete idempotent transition using the plan hash as the Supacode and Beads idempotency key; it shall never compile a replacement outcome, adopt another plan's state, repeat a completed external effect, or treat a recreated target path as success.
- [ ] **WTL-APPLY-011**: A repeat invocation shall return the existing terminal receipt or parked completion marker only when the plan hash matches and all terminal postconditions still hold; a recreated target path shall refuse as `path-reused`, and a missing or broken registration shall remain audit-only rather than authorize prune or force removal.
- [ ] **WTL-APPLY-012**: Every subprocess shall receive an explicit working directory and closed argv, and no lifecycle authority shall depend on shell interpolation, human-readable process text, or an unbounded filesystem scan.

## Public Command and Global Skill Boundary

- [ ] **WTL-CLI-001**: The repository shall expose `make worktree-audit`, `make handoff-worktree REQUEST=<absolute-request>`, dry-run `make finish-worktree REQUEST=<absolute-request>`, apply `make finish-worktree PLAN=<absolute-plan> APPLY=1`, and one focused lifecycle test target, with Make forwarding arguments but containing no lifecycle policy.
- [ ] **WTL-CLI-002**: Every public command shall write one versioned EDN result to standard output, concise progress and remedies to standard error, exit zero only for its declared success, and use stable `:error-type` values plus distinct nonzero exits for invalid request, unavailable authority, refusal, partial recovery, and execution failure.
- [ ] **WTL-CLI-003**: `make help` shall document the closed request schema, outcome-specific seal fields, negative-experiment marker grammar, handoff sequence, dry-run default, apply syntax, non-deletion guarantees, and recovery command without implying that an unlocked worktree is safe.
- [D] **WTL-CLI-004**: After repository validation, Claude Code and Codex lifecycle skills shall invoke the repository-owned commands and may render their results or gather evidence, but shall not duplicate classification, reachability, Supacode, handoff, plan, apply, or recovery policy and shall offer no generic destructive fallback when a repository lacks the controller.
