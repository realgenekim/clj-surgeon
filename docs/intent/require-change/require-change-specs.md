# Standalone require change registry

Ratified by Gene's 2026-09-08 row-3 complete-build brief and Sol's frozen design.
Identifiers are permanent. Active rows require direct code and test witnesses.

- [x] **REQUIRE-CHANGE-001**: When a standalone request is submitted through MCP or CLI, the operation shall admit only its closed explicit-file ordered-policy count-guarded schema without symbol edits.
- [x] **REQUIRE-CHANGE-002**: When a target already has an alias in the ordered policy, the compiler shall reuse that alias without adding a duplicate.
- [x] **REQUIRE-CHANGE-003**: When the target is absent, the compiler shall choose the first policy alias not bound to another library.
- [x] **REQUIRE-CHANGE-004**: When every policy alias is occupied, the operation shall refuse before write with the file and bound aliases.
- [x] **REQUIRE-CHANGE-005**: When inserting a require, the compiler shall splice a whole line at the stable sorted group position with inherited indentation and line endings.
- [x] **REQUIRE-CHANGE-006**: When a candidate changes protected comment, separator or non-target bytes, validation shall refuse publication.
- [x] **REQUIRE-CHANGE-007**: When explicit removal is requested, the compiler shall remove exactly the complete standalone matching libspec line.
- [x] **REQUIRE-CHANGE-008**: When source structure is duplicate, ambiguous or unsupported, the operation shall refuse atomically.
- [x] **REQUIRE-CHANGE-009**: When actual touched-file/add/remove counts differ from expected counts, the operation shall refuse before write with both counts.
- [x] **REQUIRE-CHANGE-010**: When a file is stale, unconfined, symlinked or exceeds the capture bounds, the operation shall refuse before publication.
- [x] **REQUIRE-CHANGE-011**: When publication or verification fails, the operation shall restore the complete snapshot through guarded undo or report recovery-required.
- [x] **REQUIRE-CHANGE-012**: When a transaction succeeds, the receipt shall report bounded counts, alias reasons, collision evidence, hashes, named successful checks and durable undo authority.
- [x] **REQUIRE-CHANGE-013**: When plan-only is requested, the operation shall return the same compiler decisions without publishing or running proof.
- [x] **REQUIRE-CHANGE-014**: When the independent row-3 grader receives a candidate, it shall reject any scope, golden, protected-byte or O5 layout mismatch.

Misreadings: a runner may supply mjson; a collision permits shadowing; comment
preservation permits detachment; sorting permits reordering inherited entries;
removal is inferred from use; a successful write proves unrun checks; byte hashes
alone are durable undo; a refused multi-file request may leave an earlier write.
