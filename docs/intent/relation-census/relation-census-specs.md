# Relation Census Specifications

IDs are stable and must not be reused if a requirement is deleted.

## Scope

- [x] **MCP-OP-CENSUS-001**: When clj-surgeon censuses a Clojure source, it shall treat as one site every call whose head is `conj`, `cons`, `into`, or `concat`, every `(fnil conj …)`, `(fnil cons …)`, or `(fnil into …)` occupying the update-fn position of `update`, `update-in`, or `swap!`, every bare `conj`, `cons`, or `into` symbol in that same update-fn position, and every call whose head is a known identity door, and it shall classify only those sites that occur inside the body of a `defmethod fold-event` arm.
- [x] **MCP-OP-CENSUS-002**: When a site occurs outside every `defmethod fold-event` arm, clj-surgeon shall count it in `outside_arms` and shall not classify it, list it, or include it in the per-class counts.

## Classification

- [x] **MCP-OP-CENSUS-003**: When the head of a site call, or the update fn of the enclosing update form, is a known identity door, clj-surgeon shall classify that site `:door` and shall name the door, before any guard analysis.
- [x] **MCP-OP-CENSUS-004**: When a site that is not a door writes into a set literal, including `(fnil conj #{})`, clj-surgeon shall classify that site `:set` before any guard analysis.
- [x] **MCP-OP-CENSUS-005**: When a recognised guard form dominates a site by containing it in one of that form's branches, and the guard's membership idiom reads the same resolved target collection as the write, and the guard performs a keyword lookup whose keyword also occurs in the written value's expression resolved through single-assignment `let` aliases, and the guard's effective polarity for an append is absence, clj-surgeon shall classify that site `:guarded` and shall report the guard's source line, the guard's location, the matched identity expression, and the polarity.
- [x] **MCP-OP-CENSUS-006**: If a dominating guard matches the target and the written value's identity but its effective polarity is presence, clj-surgeon shall classify that site `:unknown` with reason `:polarity`, and shall classify it neither `:guarded` nor `:raw`.
- [x] **MCP-OP-CENSUS-007**: If a dominating test routes the written value's identity or the target collection through a call this version does not recognise, clj-surgeon shall classify that site `:unknown` with reason `:helper-mediated-guard` and shall name the call; if an enclosing form between the arm body and the write is not recognised, it shall classify the site `:unknown` with reason `:unsupported-container` and shall name the form; if the target expression cannot be resolved, it shall classify the site `:unknown` with reason `:unresolved-target`.
- [x] **MCP-OP-CENSUS-008**: When clj-surgeon has walked a site's complete enclosing chain within its recognised vocabulary and no dominating recognised guard satisfies MCP-OP-CENSUS-005, MCP-OP-CENSUS-006, or MCP-OP-CENSUS-007, clj-surgeon shall classify that site `:raw`; clj-surgeon shall never classify a site `:raw` because analysis was inconclusive.
- [x] **MCP-OP-CENSUS-009**: When clj-surgeon reports a site, it shall carry the write's file, line, arm event type, and one-line source, and, where resolved, the target path expression, the written value expression, the candidate identity expression, the guard source and guard line, the polarity, and the uncertainty reason; clj-surgeon shall state in its tool description and its documentation that the census locates review work, does not prove idempotency, and is not an enforcement gate.

## Plan phase

- [x] **MCP-OP-CENSUS-010**: When clj-surgeon executes the plan phase over more than one file, it shall parse and classify those files on a `com.climate.claypoole` thread pool created and shut down inside one `cp/with-shutdown!` scope, using the eager `cp/upmap`, and shall re-key and order merged results by project-relative path.
- [x] **MCP-OP-CENSUS-011**: When the same census is executed with pool size 1 and with pool size N, the complete ordered site list and the complete published receipt excluding `elapsed_ms` and `phases_elapsed_ms` shall be identical.
- [x] **MCP-OP-CENSUS-012**: If a plan-phase worker throws, clj-surgeon shall refuse the complete census with a typed reason naming the file that failed and shall publish no partial counts.

## Receipt and refusals

- [x] **MCP-OP-CENSUS-013**: When a census succeeds, clj-surgeon shall publish `census_version`, per-file counts by class, the `:raw` sites, the `:guarded` sites with their guard lines, the `:unknown` sites with their reasons, `outside_arms`, `files`, `arms`, `sites`, numeric `phases_elapsed_ms` for each phase that ran (see MCP-OP-CENSUS-023), the pool size, and a `next_action`; the published receipt shall be at most 4096 bytes, shall contain no file text beyond one-line site sources, and shall report when listed evidence was trimmed to fit.
- [x] **MCP-OP-CENSUS-014**: If the workspace root does not resolve to an existing absolute directory, if no scanned file defines `defmethod fold-event` arms, if a scanned file cannot be parsed, or if a supplied door is not a symbol, shadows a collection write head, or is defined in no scanned file, clj-surgeon shall refuse with the corresponding typed reason, shall name the offending workspace, files, or door, shall publish no counts, and shall carry an executable `next_call` when one can be COMPUTED — a call the caller may replay verbatim that is not the request just refused — and otherwise no `next_call` key at all together with a `remedy` naming what it observed and why no narrower call could be computed. This prohibition is GLOBAL: no refusal from any entrance, the `relation_census` tool and the `:relation-census` CLI op alike, shall place a placeholder, caption, or description of an argument — `"<a source under the byte cap>"`, `"<an existing absolute directory>"`, `:dir <a directory with fold arms>` — in any argument position of a continuation, because a caption is not a smaller promise than a call, it is an unexecutable one. EXECUTABLE is not only free of captions: a `next_call` the `relation_census` tool emits, on every refusal shape, shall itself validate against the input schema that tool publishes — a value copied into a continuation unchanged from a caller's request (a malformed `doors` entry included) is not exempt from that schema merely because the value that produced it was never itself the reason for the refusal. A continuation shall further be a faithful NARROWING of the request it answers: it shall carry the `workspace_root` the caller supplied — verbatim when the refusal was computed before routing and no canonical form of it exists yet, canonicalised when the refusal was computed after routing — so that replaying it verbatim censuses the SAME workspace the refused request named. A continuation may narrow WHAT is censused; it shall never change WHERE, and a schema-valid continuation that silently retargets the census to the server's default workspace is a violation of this requirement, not a satisfaction of it. When the supplied `workspace_root` cannot be carried into a continuation the published schema would accept — a value that is not a string — clj-surgeon shall publish no `next_call` key at all and a `remedy` saying why, exactly as it does for every other refusal from which no narrower call can be computed. This faithful-continuation clause binds BOTH entrances BY NAME. At the `relation_census` tool the continuation carries `workspace_root`; at the `:relation-census` CLI op it carries the workspace the caller named — the request's `:dir`, or its `:file` — made ABSOLUTE, and never the fixed `:dir .`: an anchor of `.` names whatever directory the next shell happens to be standing in, so a continuation carrying it replays against a tree the caller never named and reports SUCCESS, which is the same silent-retarget failure this requirement already forbids the tool, spelled in the CLI's own grammar. When the caller supplied a relative anchor, the continuation shall carry its absolute resolution against the working directory it was resolved in AND shall say which working directory that was, so the caller is never left to infer it; that resolution shall be computed without touching the filesystem, because the refusal that carries it is produced by the pass MCP-OP-CENSUS-016 requires to run before any filesystem work. A CLI continuation shall further be SHELL-SAFE: it shall be computed as a vector of argv tokens and published in BOTH spellings — the vector itself, for a caller that execs it, and a rendered command line in which every token that is not composed entirely of the characters `[A-Za-z0-9_@%+=:,./-]` is enclosed in single quotes with each embedded single quote written `'\''`, for a caller that pastes it into a shell — and the two shall denote the same call. A continuation is an EXECUTABLE promise, and this prohibition is the same one this requirement already states for captions, one turn later: a caption in an argument position does not execute, and an unquoted argument executes SOMETHING ELSE. It binds every CLI refusal shape, the narrowing continuations of MCP-OP-CENSUS-027 and MCP-OP-CENSUS-033 included, because the workspace path a continuation carries is CALLER-supplied and a refusal handed to an agent to replay is precisely where a caller-supplied string becomes a command. Every CLI refusal shall additionally publish the anchor it was computed from — the workspace the caller named, made absolute — and shall build any continuation it carries through the ONE anchor-carrying constructor, so that no refusal site can spell an anchor of its own. A continuation shall further carry the caller's PATH BYTES UNCHANGED: no entrance shall trim, pad, case-fold, or otherwise normalise a `workspace_root`, a `:dir`, or a `:file` value on its way into an anchor, a continuation, or a receipt, because a POSIX filename may begin and end with whitespace and an edited path names a DIFFERENT directory — one that may exist, may hold a different number of sources, and will report SUCCESS about them. Absolutizing a relative path against the working directory it was resolved in is the one permitted transformation, and it is the one the caller asked for: it adds bytes and removes none. The EMPTY path is refused rather than resolved, because POSIX gives the empty pathname no meaning and every syscall answers it ENOENT; a whitespace-only path is a legal relative path and shall resolve like any other. When a path argument reaches an entrance carrying U+FFFD — the replacement character the runtime writes for bytes it could not decode in the argv encoding — clj-surgeon shall refuse with a typed reason, `dir-not-decodable` at the `:relation-census` CLI op and `workspace-root-not-decodable` at the `relation_census` tool, shall name the offending argument and that encoding, shall publish NO continuation of any kind, and shall carry a remedy stating that the replacement is lossy, that the path the caller meant therefore cannot be reconstructed, named, or carried, what to do instead, AND that a path which LEGITIMATELY contains U+FFFD is refused by the same rule and why. The refusal is required precisely because the correct bytes are unrecoverable in process: continuing censuses whatever directory the corrupted spelling happens to name, or none at all, and publishes a count about it — the same silent retarget this requirement already forbids, arriving through a decoder rather than through a bare dot. The `max-next-call-bytes` ceiling shall be measured in UTF-8 BYTES, at ONE shared predicate every entrance and every refusal shape calls, because every consumer of a continuation measures bytes — argv is bytes, a JSON request body is bytes, a terminal line is bytes — and a ceiling named in bytes and enforced in Java characters admits a continuation of nearly three times the bound. The remedy that REPLACES an over-long continuation shall state the byte length it MEASURED beside the ceiling it compared against, so the caller is not left to guess how much shorter is short enough. A refusal that computed a narrowing and could not carry it shall not report the absence of one: where a bound refusal chose a subtree from the walk's own aggregates and the rendered continuation exceeded the ceiling, its remedy shall NAME that subtree, state the UTF-8 byte length it measured, state the ceiling, and say that the length of the path and not the size of the subtree is what does not fit — and the remedy for the genuinely different case, where no fully-walked subtree fits at all, shall remain distinguishable from it in the receipt, because a caller told that no narrowing exists narrows the wrong thing. When a source the request NAMED cannot be read — it does not exist, it escapes the project fence, or it is not a regular file — clj-surgeon shall refuse typed on both entrances. At the `:relation-census` CLI op, where the named source IS the request, it shall refuse `file-not-found` naming the path, carrying the anchor every CLI refusal carries, with a remedy and no continuation, and it shall do so from the ENTRANCE before the scan is forced: existence is filesystem work and cannot be decided in the pure pass MCP-OP-CENSUS-016 requires, but a `java.nio.file` exception escaping an inner kernel as an untyped `:invalid-arguments` is not a refusal at all. At the `relation_census` tool, where `files` is a list, the continuation shall be a faithful NARROWING — the same request WITHOUT the entries that could not be read, every other option the caller supplied carried through unchanged — and when removing them leaves no request, or when the unreadable path came from the workspace walk rather than from the request, there shall be no `next_call` key and a remedy saying why. A `next_call` that carries back the entries that caused the refusal is forbidden by this requirement whether it repeats the request verbatim or narrows the request to exactly the rejected entries: both replay into the identical refusal, and a continuation that cannot make progress is not a smaller promise than the request, it is a loop with a receipt.
- [x] **MCP-OP-CENSUS-015**: When clj-surgeon exposes the census, it shall expose it as the read-only `relation_census` MCP tool and as the `:relation-census` CLI op, and neither surface shall write any file.

## Input bounds

- [x] **MCP-OP-CENSUS-016**: When clj-surgeon receives a census request, it shall validate server-side, in one ordered pass — unknown fields, then `doors`, then `files`, then `pool_size` — before any filesystem work, where "before any filesystem work" means before `workspace_root` is canonicalised, `stat`ed, or resolved to a router context, not merely before a scanned source is read, and where the pass that must run first is the ENTRANCE's, not the op body's — at the `:relation-census` CLI op the entrance resolves `.clj-surgeon.edn` by walking the ancestor chain from the request's anchor and READS it, which is filesystem work on a request the tool has not yet agreed to honour, so the shape pass shall run before that load: that no unknown field is present; that `doors` when supplied is an array of at most 32 entries; that `files` when supplied is a non-empty array of at most 512 non-blank strings; and that `pool_size` when supplied is an integer between 1 and 64; and it shall refuse on the FIRST field in that order that violates its check with a typed reason, the offending bound, and an executable `next_call`, never reaching a later field's check, `workspace_root` resolution, or any filesystem call once an earlier field has already refused; when a valid `pool_size` exceeds the box's available processors, clj-surgeon shall run the plan phase on a pool of the available processors and shall publish both the pool it used and the pool that was requested. The ordered pass shall check FIRST OVERALL — ahead of the unknown-field check, ahead of the `:dir` check, and ahead of `doors`, `files` and `pool_size` — that every PATH argument the entrance carries, the CLI op's `:dir` and `:file` and the tool's `workspace_root`, survived decoding, refusing a value that contains U+FFFD before any other row is reached. That check is a string inspection which resolves nothing, canonicalises nothing and stats nothing, so it does not breach this requirement's own prohibition on filesystem work. Its position is a PRECONDITION and not a severity ranking: a continuation is a narrowing of the request it answers, and a request whose path did not decode has no faithful narrowing at all, so every row placed ahead of it answers its own question about a value that no longer denotes anything and publishes a continuation carrying the corrupted spelling. It is not sufficient for the decodability row merely to precede the rows that name a path; it shall precede EVERY row each entrance can express, including the rows whose own violation is unrelated to paths, because those rows compute continuations too. The `:dir` check shall refuse a non-string and the EMPTY string and nothing else: a whitespace-only value is a path, not a missing one.

- [x] **MCP-OP-CENSUS-017**: When clj-surgeon reads a scanned source, it shall test that source for `defmethod` arms as it is read and shall retain the text only of the sources that define arms; it shall refuse a requested source larger than `max-source-bytes` with a typed reason naming the file, its size, and the cap, before reading it; and if any `Throwable` escapes the census, clj-surgeon shall publish a typed refusal — `census-resource-exhausted` for a runtime resource failure and `census-adapter-failure` otherwise — publishing no counts, no `next_call` at all, and a `remedy` stating that the walk's own aggregates were lost with the resource that held them so no narrower call can be computed, together with whatever discovery facts survived; the refusal shall carry no placeholder in any argument position.

- [x] **MCP-OP-CENSUS-018**: When clj-surgeon discovers the files to census, it shall walk the workspace without following symbolic links, shall prune a skipped directory before reading it, shall stop the walk once the scanned-file cap is reached, and shall skip and count in `skipped_outside_root` every discovered path whose real location escapes the workspace root rather than refusing the census.

- [x] **MCP-OP-CENSUS-019**: When clj-surgeon executes the `:relation-census` CLI op, it shall parse `:threads` through the same pool-size kernel as the MCP tool and refuse an out-of-range or non-integer value typed, and it shall make that refusal from a PURE pass the CLI entrance runs before it performs any filesystem work of its own — project-alias discovery and loading included — so that a malformed request costs no `stat`, no config read, and no ancestor walk on either runtime, the JVM CLI and babashka alike, shall validate `:doors` through the same door kernel and refuse a door that shadows a collection write head, and shall bound its scan by the same scanned-file and source-byte caps, refusing a named source above the byte cap. That pure pass shall validate the WHOLE request shape and not one field of it: unknown arguments, `:doors` — that it is one comma-separated string, that it names at most `max-doors` doors, and that every name is a symbol that does not shadow a collection write head — `:file`, that it is a non-blank string, and `:threads`; each refused typed, naming the offending value, before the entrance stats a directory, reads a `.clj-surgeon.edn`, or walks an ancestor chain for one. An argument the op does not accept shall be REFUSED at the CLI, never ignored, because an argument that is silently dropped tells the caller a bound was applied that never existed, which is worse than a refusal. The op shall additionally publish, as a DECLARED set an enumeration witness can read, every typed refusal it can emit once its arguments have been parsed — the post-scan refusals and the filesystem refusals `file-not-found` and `source-too-large` included — so that a refusal added to the op without a probe fails that witness rather than shipping unexercised. Both entrances shall decide these questions from ONE shared refusal table — logical field, violation, the predicate that decides it, and the name each entrance publishes for it — so that neither entrance can accept silently what the other refuses; where the two publish different names for one row, or where one entrance's grammar cannot express a row at all, that mapping and that reason shall be recorded in the table itself and shall be the only permitted difference between them.

- [x] **MCP-OP-CENSUS-020**: When clj-surgeon witnesses that the census answer is pool-size independent, it shall run at least two arm-defining files through the plan phase, and the plan-phase pool shall map every input exactly once, shall use no more threads than the pool size it was given, and shall leave no worker thread alive after the call returns.

- [x] **MCP-OP-CENSUS-021**: When clj-surgeon runs the plan phase from either entrance, it shall run it on the bounded `census_pool` pool whenever a pool larger than one is both requested and available, and the receipt's pool size shall be the pool that actually ran; when the pool that ran is smaller than the pool requested, clj-surgeon shall publish the requested size alongside it.

- [x] **MCP-OP-CENSUS-022**: When clj-surgeon bounds a census receipt, the 4096-byte budget shall hold for the receipt as PUBLISHED, including the workspace root and elapsed time appended after bounding, and clj-surgeon shall trim listed sites first and per-file counts last, marking any trimmed receipt `receipt_truncated`.

- [x] **MCP-OP-CENSUS-023**: When no `doors` are supplied, clj-surgeon shall not run a declaration pass and shall parse each censused file exactly once; when `doors` are supplied, clj-surgeon shall check the door symbols before the census and confirm that each is defined using the declarations the plan phase already returns; and `phases_elapsed_ms` shall name only phases that ran — `discover` only when a tree was walked, `read` for resolving and reading the scan, and `classify` and `merge` from the plan.

- [x] **MCP-OP-CENSUS-025**: When clj-surgeon censuses an arm, it shall count every call inside that arm whose head is neither a modelled form nor an identity door, shall publish that count with up to five named examples carrying file, line, and arm, and when no site is `:raw` and no site is `:unknown` but such calls exist, its `next_action` shall name them and state that a write behind one of them is not a site; clj-surgeon shall never publish `next_action` `none` for a census that could not see inside the arm's own calls.

- [x] **MCP-OP-CENSUS-024**: When clj-surgeon confirms that a supplied identity door is defined, it shall consider the top-level declarations of every scanned file, not only of the files that define arms, and both the MCP tool and the CLI op shall accept a door defined in a scanned helper namespace and refuse one defined nowhere.

- [x] **MCP-OP-CENSUS-027**: While discovering the files to census by walking the workspace tree, when the number of candidate Clojure sources reaches `max-scanned-files`, clj-surgeon shall refuse the census before reading any source with error type `too-many-candidate-files`, shall name the ceiling, the count that fits, the candidate count it observed and that the observed count is a lower bound, shall publish `files_read` 0, no counts and `read_complete` false, and shall carry a continuation COMPUTED from the walk's own per-directory aggregates: the largest fully-walked subtree whose observed candidate count fits under the ceiling, ties broken deepest first and then lexicographically, expressed as a `next_call` — or a `:next-command` at the CLI — that a caller may replay verbatim and that is at most `max-next-call-bytes`; when no fully-walked subtree fits, clj-surgeon shall publish no continuation and shall state in a `remedy` why, including that the walk stopped early and the observed count is therefore a lower bound. Both the `relation_census` tool and the `:relation-census` CLI op shall bound the walk itself rather than enumerating the whole tree and truncating the result, and neither shall hand back the root it has just refused, nor a subtree holding no candidate Clojure source, nor a placeholder in place of an argument — MCP-OP-CENSUS-014 states that last prohibition for every refusal on every entrance.

- [x] **MCP-OP-CENSUS-028**: While discovering the files to census, when a discovered Clojure source is larger than `max-source-bytes`, clj-surgeon shall skip that source without reading it, shall count it in the receipt's `oversized_skipped`, shall name at most `max-listed-files` of them under one bound shared by both entrances, shall publish `oversized_skipped_omitted` stating how many skipped sources it counted but did not name — zero when it named them all — and shall publish `read_complete` false for that census; it shall publish that same evidence on EVERY receipt shape the census can return for that tree, `no-fold-arms-found` and every other refusal included, so that a tree whose only sources were skipped for size is never indistinguishable from an empty one; a source of exactly `max-source-bytes` shall be read and censused, and a census that skipped nothing shall publish `read_complete` true, no `oversized_skipped`, and no `oversized_skipped_omitted`.

- [x] **MCP-OP-CENSUS-029**: When clj-surgeon validates a `relation_census` request server-side, it shall check the request's shape in the fixed order MCP-OP-CENSUS-016 states — `doors` (array-ness, then `max_doors`, then that every entry is a JSON string) before `files` (array-ness, then non-empty, then the file-count maximum, then that every entry is a non-blank string) before `pool_size` (JSON-integer-ness, then range) — and this ordered pass shall run entirely before ANY filesystem work, including before `workspace_root` is canonicalised or `stat`ed, so that a malformed `doors` entry refuses `doors-not-strings` before a request that also names 513 `files` can be refused `too-many-files`, and before an unresolvable `workspace_root` can be refused `invalid-workspace-root`. Within that order: it shall accept for `pool_size` only a JSON integer, exactly as the schema it advertises states, and shall refuse a string, a float, a boolean, a null, or an array with reason `pool-size-not-an-integer`, the offending value, the bound, and an executable `next_call`; and, in the same family, it shall accept for each `doors` entry only a JSON string, exactly as the schema it advertises states, and shall refuse an integer, a float, a boolean, a null, an object, or an array in that position with reason `doors-not-strings`, the offending entry's index and value, and an executable `next_call` carrying no `doors` key, before that entry can reach a branch — such as the oversized-source continuation — that would copy `doors` into a `next_call` unchanged. Both entrances shall validate every row of that table in ONE phase: no row shall be skipped by one entrance and applied by the other, and the ONLY reason an entrance may skip a row is that it cannot express the violation at all. In particular the door-VOCABULARY row — is the name a symbol, and does it shadow a collection write head — shall be decided in the shape pass on BOTH entrances, because both questions are answered against compile-time sets and need no scan, and a pure predicate answered after a walk is not a better answer but the same answer on an entrance the other one no longer matches. Only door DEFINEDNESS, which cannot be answered before a scan, shall be decided after discovery, and it shall be decided after discovery on both entrances and shall carry the discovery facts; a refusal computed before any walk shall publish no scan count.

- [x] **MCP-OP-CENSUS-032**: When clj-surgeon discovers the files to census, both the `relation_census` tool and the `:relation-census` CLI op shall discover through one shared kernel: they shall canonicalise the workspace root before walking it, shall never read a path whose canonical real location lies outside that canonical root, shall count every such path in `skipped_outside_root`, and shall publish the same discovery figures — `files_scanned`, `skipped_outside_root`, `duplicates_collapsed`, and the `oversized_skipped` evidence of MCP-OP-CENSUS-028 — for the same tree, built by one shared kernel and published on EVERY receipt shape that entrance can return: success, `no-fold-arms-found`, and every refusal reached after a walk, under one publication rule for all of them; a figure the walk observed shall never be dropped because the census refused, and `files_scanned` shall be published whenever the walk knows it, zero included.

- [x] **MCP-OP-CENSUS-030**: When a census request names the same source more than once, whether by the same string or by different strings that canonicalise to one real path, or when a walked tree reaches one real source through more than one discovered path, clj-surgeon shall read, classify and count that source exactly once and shall publish `duplicates_collapsed` naming how many repeated entries it collapsed, identically from the `relation_census` tool and from the `:relation-census` CLI op and on EVERY receipt shape — success, `no-fold-arms-found`, and every refusal that followed a walk — so that a collapse is never reported only when the census happened to find arms; a census that reached no source twice shall publish no `duplicates_collapsed`.

- [x] **MCP-OP-CENSUS-033**: While discovering the files to census by walking the workspace tree, clj-surgeon shall count every directory entry it visits — files, directories, and pruned directories alike — against a shared `max-walk-entries` bound, shall stop the walk at one entry past that bound rather than enumerating the rest of the tree, and shall refuse before reading any source with error type `too-many-walk-entries`, naming the bound, the entry count it visited and that that count is a lower bound, publishing `files_read` 0 and no counts, and carrying a continuation COMPUTED from the walk's own per-directory entry aggregates: the largest fully-walked subtree that fits under BOTH the entry bound and the scanned-file ceiling AND holds at least one candidate Clojure source, ties broken by the most candidate sources, then deepest, then lexicographically; a subtree holding no candidate source shall never be offered, because a walk that stopped on a tree of junk would otherwise hand back the junk and the replay would refuse `no-fold-arms-found` on a workspace that has arms. The continuation is expressed as a `next_call` — or a `:next-command` at the CLI — that a caller may replay verbatim, and a `remedy` in place of it when no fully-walked subtree fits; both entrances shall enforce one bound through the shared discovery kernel, and the walk shall charge an entry against that bound before it stats it, so that a directory of 60,000 entries is stopped rather than measured; clj-surgeon shall obtain the entries of a directory one at a time from a streamed listing and shall charge each against the bound as the filesystem yields it, shall never materialise or order a complete directory listing before charging it — ordering only the entries it admitted — and shall publish in the refusal `entries_yielded`, the number of names it obtained from the filesystem, which shall never exceed `max-walk-entries`.

## Published surfaces

- [x] **MCP-OP-CENSUS-026**: When clj-surgeon publishes its tool catalog in prose, that prose shall state five tools, shall name `relation_census` in the README, in CLAUDE.md, and in the clj-surgeon skill reference and its mirror, shall state that the census locates review work rather than proving idempotency, and shall state that the census is the one tool that enumerates the workspace tree; the tool's own description shall state the same.

- [x] **MCP-OP-CENSUS-031**: When clj-surgeon publishes the relation-census low-level design, that design shall name exactly the phases the implementation publishes in `phases_elapsed_ms` — `discover` when a tree was walked, `read`, `classify` and `merge` — shall promise no `parse` phase, and shall state that on the JVM both entrances run the plan phase on the shutdown-bound `census_pool` while babashka runs it at pool size 1 and reports the requested size.

## Falsifiers

| ID | Defensible opposite to test | Required witness families |
|---|---|---|
| `MCP-OP-CENSUS-001` | A textual match on `conj` is a sufficient site finder. | `(fnil disj #{})` contributes no site; a door call is a site; a bare `conj` update fn is a site. |
| `MCP-OP-CENSUS-002` | A helper's write is the arm's write. | The real `conj-once`/`upsert-by` bodies counted, never classified. |
