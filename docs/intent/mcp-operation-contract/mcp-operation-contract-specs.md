 #MCP Operation Contract Specifications

This file is the stable intent registry for the MCP operation-contract leaf.
IDs are never reused. The status marker records whether the current code and
tests witness the requirement.

The admission gate's own intents, `MCP-OP-ADMIT-nnn`, are registered in
[admit-clojure-patch-specs.md](admit-clojure-patch-specs.md) beside the design
that owns them. They are audited from that file by the same coherence gate, so
they are not restated here; ids remain unique across the whole `MCP-OP` prefix.

# #Finalized Results

- [x] **MCP-OP-RESULT-001**: When a public MCP handler produces a successful domain result, clj-surgeon shall publish a finite, non-negative numeric `elapsed_ms` in that result.
- [x] **MCP-OP-RESULT-002**: When a public MCP handler produces a typed refusal, clj-surgeon shall publish a finite, non-negative numeric `elapsed_ms` in that refusal.
- [x] **MCP-OP-RESULT-003**: When clj-surgeon finalizes a domain result, the finalized domain fields shall equal the produced domain fields except for the authoritative top-level `elapsed_ms`.
- [x] **MCP-OP-RESULT-004**: When timing evidence is added to an MCP domain result, clj-surgeon shall preserve the domain outcome's existing MCP success or error classification.
- [x] **MCP-OP-RESULT-005**: If MCP result finalization receives a non-map result or an invalid elapsed interval, then clj-surgeon shall fail the MCP invocation as an unexpected MCP error without publishing a malformed domain result.
- [x] **MCP-OP-RESULT-006**: If MCP summary rendering or result serialization fails, then clj-surgeon shall fail the MCP invocation as an unexpected MCP error without publishing a partial domain result.

# #Timing Boundary and Presentation

- [x] **MCP-OP-TIME-001**: When a public MCP handler is invoked, clj-surgeon shall start its request clock before handler validation and domain execution.
- [x] **MCP-OP-TIME-002**: When public MCP domain execution returns, clj-surgeon shall stop its request clock before summary rendering, serialization, callback scheduling, and transport.
- [x] **MCP-OP-TIME-003**: When a public MCP result is summarized, clj-surgeon shall render its structured `elapsed_ms` with a locale-independent decimal point, exactly two decimal places, and the `ms` suffix.
- [x] **MCP-OP-TIME-004**: Where an existing top-level MCP timer measures a narrower internal phase, clj-surgeon shall preserve that value under a phase-specific field instead of using it as public `elapsed_ms`.
- [x] **MCP-OP-SCHEMA-001**: For every tool in the canonical public MCP registry, clj-surgeon shall require `elapsed_ms` as a non-negative number in that tool's output schema.

# #Asynchronous Verification

- [x] **MCP-OP-ASYNC-001**: While a cold verification job is pending, an MCP launch or inspection result shall omit `job_elapsed_ms`.
- [x] **MCP-OP-ASYNC-002**: When inspection observes a cold verification job that completed after execution began, the MCP result shall contain finite, non-negative `elapsed_ms` and `job_elapsed_ms` values.
- [x] **MCP-OP-ASYNC-003**: When a cold verification result contains `elapsed_ms` and `job_elapsed_ms`, its human summary shall label the corresponding formatted values as `request` and `job`.
- [x] **MCP-OP-ASYNC-004**: If cold verification inspection cannot identify an owned job that began execution, then the typed refusal shall omit `job_elapsed_ms`.
- [x] **MCP-OP-ASYNC-005**: When cold verification inspection reads a job state, clj-surgeon shall publish evidence from exactly that observed state even if the job transitions afterward.

# #Registration and Traceability Gates

- [x] **MCP-OP-COVERAGE-001**: When the canonical public MCP registry changes, `make runtests` shall fail unless the operation witness catalog has exactly the same tool keyset.
- [x] **MCP-OP-COVERAGE-002**: For each canonical public MCP registry entry, `make runtests` shall fail unless the witness catalog exercises exactly the public outcome classes declared by that entry.
- [x] **MCP-OP-TRACE-001**: When `make runtests` executes, it shall fail if an active-gap `[]` MCP operation-contract intent lacks a direct test witness.
- [x] **MCP-OP-TRACE-002**: When `make runtests` executes, it shall fail if an MCP operation-contract implementation or test witness names an unknown intent ID.
- [x] **MCP-OP-TRACE-003**: When `make runtests` executes, it shall fail if an implemented `[x]` MCP operation-contract intent lacks an implementation witness or a direct test witness.
- [x] **MCP-OP-TRACE-004**: When `make runtests` executes, it shall not require implementation or test witnesses for a deferred `[D]` MCP operation-contract intent.
- [x] **MCP-OP-ORACLE-001**: Where a Prolog shadow oracle is retained after finding an independent counterexample, `make runtests` shall execute that oracle as a blocking gate.

# #Compact Root-Scoped Data Edits

- [x] **MCP-OP-EDIT-001**: When one compact literal edit names an explicit non-empty `files` array and `within.root` is true, clj-surgeon shall apply the exact `from` to `to` replacement with the declared match count in every file as one frozen failure-atomic transaction.
- [x] **MCP-OP-EDIT-002**: When a compact literal edit targets an `.edn` file, clj-surgeon shall require root scope and refuse namespace ownership, named-form ownership, and owner deletion before writing.
- [x] **MCP-OP-EDIT-003**: If a grouped compact edit repeats a file, combines `file` with `files`, omits both, uses grouped files outside root scope, or fails its per-file cardinality, clj-surgeon shall refuse the complete request without changing any source.
- [x] **MCP-OP-EDIT-004**: When a root-scoped EDN edit succeeds, clj-surgeon shall parse and read back every future file and preserve all bytes outside the exact replaced subtrees, including comments and metadata.
- [x] **MCP-OP-EDIT-005**: When a compact Clojure edit uses `within.namespace=true`, clj-surgeon shall resolve the file's unique namespace form without requiring the caller to repeat its name, and shall refuse before writing if that owner is not unique.

# #Tolerant Direct-Change Compilation

- [x] **MCP-OP-EDIT-006**: When a direct `changes` request omits top-level aggregate `expect`, clj-surgeon shall derive exact `changes`, `edits`, and distinct `files` counts from the required per-change guards ; when a caller supplies redundant aggregate counts, the compiler shall report and ignore disagreement without weakening any per-change guard.
- [x] **MCP-OP-EDIT-007**: When one `insert_before` or `insert_after` array item contains several complete Clojure forms, clj-surgeon shall deterministically split and insert them in source order ; malformed syntax or detached comments shall still refuse before write at the exact array-item path.
- [x] **MCP-OP-EDIT-008**: The public direct-change description shall state that packed complete forms are accepted, aggregate expectations are optional derived bookkeeping, and callers shall omit `verify` unless the user or repository explicitly requests a configured transaction profile.
- [x] **MCP-OP-EDIT-009**: The public contract shall state that top-level `edits` and `changes` are mutually exclusive ; when one atomic decision contains any insertion, deletion, rename, map-entry insertion, or heterogeneous action, the caller shall encode every action in one `changes` array rather than combine routes.
- [x] **MCP-OP-EDIT-010**: When one packed insertion item is malformed, clj-surgeon shall refuse before write and may return a non-executable `retry_template` that preserves every other request field, replaces only the exact malformed item with a null caller-owned hole, names the hole path, publishes selector and write authority as false, and publishes no executable `next_call` ; the caller-supplied replacement shall pass ordinary validation from zero authority.

# #Injective Compact Location Normalization

- [x] **MCP-OP-EDIT-011**: When a compact Clojure edit omits `within`, the source-blind MCP schema and adapter shall preserve that omission for source-aware normalization and shall not default it to root scope ; an EDN edit shall continue to require explicit `within.root`, and an explicitly malformed or conflicting location shall refuse without normalization.
- [x] **MCP-OP-EDIT-012**: When `within.form` resolves exactly one named owner, clj-surgeon shall preserve that owner as authoritative ; only when it resolves zero named owners and the file has exactly one direct namespace owner whose parsed name exactly equals the supplied string shall clj-surgeon normalize the edit to explicit namespace scope, while duplicate named owners, zero or several namespaces, another namespace name, or reader-conditional ambiguity shall refuse before write.
- [x] **MCP-OP-EDIT-013**: When a compact Clojure edit omits `within`, identifies exactly one file, and supplies complete `from` and `to` namespace clauses with the same recognized clause kind, clj-surgeon shall normalize to explicit namespace scope only if the declared count equals the lossless `from` fingerprint count among direct children of the one namespace and that count also equals the namespace-descendant and whole-file counts ; otherwise, including nested or external lookalikes, detached comments, a stale count, or platform ambiguity, the complete request shall refuse before write.
- [x] **MCP-OP-EDIT-014**: When a compact Clojure edit omits `within`, identifies exactly one file, declares one match, and supplies complete named top-level `from` and `to` forms with the same owner kind and exact name, clj-surgeon shall normalize to explicit named-owner scope only if the frozen file contains exactly one corresponding direct owner whose complete lossless fingerprint equals `from` ; anonymous, renamed, retyped, duplicate, nested-only, reader-conditional, or stale forms shall refuse before write.
- [x] **MCP-OP-EDIT-015**: When compact location normalization succeeds, clj-surgeon shall report bounded edit identity, relation, requested location shape, and emitted explicit location without source bodies, shall compile every normalized edit against one frozen source map through the unchanged generic transaction compiler, and shall grant no partial or retry authority ; if any edit lacks an exact proof, the complete transaction shall remain source-unchanged, and generic direct `changes`, retained-basis changes, extraction, computed programs, and CLI selector semantics shall remain unchanged.
- [x] **MCP-OP-EDIT-016**: Before compact location normalization is activated, permanent witnesses shall replay all eight retained owner-table cohort calls through the real validator and compiler to the exact 51-match, nine-file capsule future hashes, shall preserve every candidate owner and declared count, and shall prove refusals for wrong or duplicate owners, zero or several namespaces, reader conditionals, mismatched clause kinds, nested and external lookalikes, anonymous or renamed owners, malformed file selectors, and stale counts.

# #Injective Compact Edit Field Normalization

- [x] **MCP-OP-EDIT-017**: When one compact edit supplies exactly one complete value pair named `from`/`to`, `old`/`new`, or `before`/`after`, clj-surgeon shall preserve the canonical pair or injectively lower the alias pair to `from`/`to` before location or source compilation, without changing either value.
- [x] **MCP-OP-EDIT-018**: When any compact edit supplies a partial pair, a cross-pair mixture, more than one complete pair, or a canonical pair plus aliases, clj-surgeon shall refuse the complete request before source read or mutation, identify the exact edit path and supplied fields, publish source unchanged and write authority false, and grant no partial normalization or retry authority.
- [x] **MCP-OP-EDIT-019**: The public editor schema shall admit only the three closed complete value-pair spellings while describing `from`/`to` as canonical ; successful alias lowering shall publish bounded requested and emitted field evidence, and a field-pair refusal shall state the exact alias mapping and direct the caller to the exposed `edit_clojure` operation rather than another tool.

# #Closed Compact Relations

- [x] **MCP-OP-EDIT-020**: When an MCP compact request supplies either `symbol_migration` or `require_change`, clj-surgeon shall require both complete closed relation objects, exact row and tuple arity, the same non-empty ordered file vector, `symbol_migration.target_alias` equal to `require_change.add.as`, unique file and migration-row identities, and no sibling request fields except `workspace_root`, `edits`, `delete_owners`, and the compact apply entrance's existing `verify` ; a missing, null, partial, unknown, mismatched, or disallowed decoded field or identity shall refuse the complete request before source capture or write authority, without claiming authority over duplicate raw JSON keys already collapsed by an upstream decoder.
- [x] **MCP-OP-EDIT-021**: When the paired relation request passes source-blind admission, Phase A shall lower every declared symbol row exactly once under `target_rule="preserve-name"` into ordinary owner-scoped compact edits, consume `symbol_migration`, and return pending `require_change` plus the complete ordered file references from generated symbol edits, normalized caller-supplied literal edits, and expanded owner deletions ; Phase A shall perform no filesystem read, canonical path resolution, owner discovery, fuzzy selection, or mutation.
- [x] **MCP-OP-EDIT-022**: When Phase A succeeds, the existing root-confined resolver shall map the complete ordered intent to one unique canonical request file universe, reject root escapes, canonical aliases, and different paired spellings of one file, and capture that universe exactly once ; against only that frozen map, Phase B shall consume `require_change` and emit one complete namespace-scoped clause `from`/`to` edit with `matches=1` per relation file by replacing the sole removed direct libspec with the target, or otherwise removing the exact declared direct libspec and its immediately preceding whitespace-and-comma separator when non-first or its immediately following whitespace-and-comma separator when first and appending `[add.lib :as add.as]` with the last survivor's exact whitespace-and-comma separator, while preserving every unrelated byte. A missing or duplicate removal, target lib or alias already present, add/removal pairs that are not distinct, removal using the target alias, unsupported reader conditional, comment-bearing or ambiguous layout, file-universe drift, Phase B widening, reread, or second capture shall refuse before mutation.
- [x] **MCP-OP-EDIT-023**: When relation lowering succeeds, clj-surgeon shall combine the generated symbol and namespace edits with allowed literal edits and owner deletions through the existing compact-location normalizer and canonical transaction compiler ; every generated and supplied span shall remain disjoint and within the existing request budgets, and any overlap, no-op, stale snapshot, compile failure, verification failure, or rollback failure shall preserve the existing complete-transaction refusal, undo, and recovery laws without partial authority.
- [x] **MCP-OP-EDIT-024**: When either `edit_clojure` or the compact `edits` branch of `apply_clojure_changes` processes a closed relation pair, both entrances shall expose the same relation fields and, on success, publish the complete closed `compact_relation_normalization` keys `version`, `relations`, `target_rule`, `files`, `migration_rows`, `require_files`, `literal_edits`, `deleted_owners`, `declared_matches`, `expanded_edits`, and `edit_ids`, while existing transaction evidence retains ownership of source and future hashes. A relation-admission, path-resolution, require-lowering, or relation-composition refusal shall respectively publish `invalid-compact-relation`, `compact-relation-path-conflict`, `require-change-unprovable`, or `compact-relation-overlap`, one bounded top-level `error`, a closed `compact_relation_diagnostic` with the matching `failed_stage` and optional closed `path= {field,file_index?,row_index?}` whose indexes are zero-based and which is omitted when no single request location owns the failure, `mutation_attempted=false`, `write_authority=false`, and `next_action=correct_request`, with no source body, generated partial request, executable retry, or terminal response ; delegated compact, location, transaction, verification, and rollback outcomes shall retain their existing evidence and error authority and omit the relation diagnostic. Relation lowering shall grant no write or verification authority, and only `apply_clojure_changes` shall retain its existing verifier selection.
- [x] **MCP-OP-EDIT-025**: Before closed compact relations are promoted, permanent witnesses shall prove the retained 51-match, nine-file relation corpus lowers to the exact normalized-flat canonical effect identity and future hashes and shall prove relation-absent flat compact edits, generic changes, programs, retained basis, extraction and planning, CLI, and unsupported CLJC routes never invoke relation lowering. One new immutable same-candidate real-mutation cohort, which shall neither rescore nor splice any retained attempt, shall give normalized-flat `N` and relation `R` the identical relation-capable `apply_clojure_changes` surface, task, model, effort, fixture, project-owned exact verifier, scorer, and canonical-effect law in serial `N R R N` then `R N N R` blocks ; each run shall make exactly one compact `apply_clojure_changes` call with `verify="exact"`, shall retain every post-launch attempt, and shall fail on any missing, incorrect, representation-nonadherent, route-nonadherent, retried, unverified, or task-incomplete run. Block one shall authorize block two only when 4/4 runs are admitted, `R` median `T_emit` is at least 20 percent faster, and `R` median `T_complete_verified` is at least 15 percent faster. The cohort shall not grant verifier selection to `edit_clojure`. It shall promote only when median `T_emit`, measured from turn start through the complete tool-argument event, makes `R` at least 20 percent faster than `N` in each block and pooled, when median `T_complete_verified`, measured from turn start through the completed final response after exact first-call verification, makes `R` lower in each block and at least 20 percent faster pooled, and when `T_apply_verified`, measured through the exact MCP verification completion, remains diagnostic rather than a substitute outcome. Payload-byte reduction alone shall grant no promotion authority.
- [x] **MCP-OP-EDIT-026**: When the closed compact relation parser reads any public field, it shall use closed lexical recognition, shall never evaluate the input, and shall produce no output for a payload that contains reader-evaluation syntax.
- [x] **MCP-OP-EDIT-027**: When the closed compact relation parser classifies symbol tokens, it shall treat `nil`, `true`, and `false` as Clojure literals and shall never admit them as namespace, alias, owner, or migration symbols.
- [x] **MCP-OP-EDIT-028**: When a compact MCP transaction has passed path confinement, exact guard resolution, complete generic compilation, and disjointness proof, clj-surgeon shall derive one versioned canonical effect projection from normalized project-relative files, complete source and result hashes, resolved structural addresses, resolved insert/delete/replace kinds, and the complete exact before and after strings without parsing, formatting, fingerprinting, truncation, or hash substitution inside the projection ; it shall order files and effects only after that proof and shall publish only the closed `canonical_effect_identity={version,sha256,files,effects}` summary without source bodies, replacements, absolute paths, request IDs, receipt paths, or receipt hashes.
- [x] **MCP-OP-EDIT-029**: When two complete compact requests compile against the same frozen source to the same multiset of exact proven-disjoint effects, every caller-order permutation shall produce the same canonical effect projection, SHA-256, future hashes, read-back hashes, file count, and effect count while submitted order, positional diagnostics, generated IDs, receipt vectors, receipt bytes, receipt hashes, and inverse order remain existing provenance ; when any permutation contains an identical or intersecting span, parent and nested edit, deletion containing an edit, same-boundary insertions, missing exact guard, or a transformation that would require a sibling future, the complete request shall refuse before future source, identity, or write authority.
- [x] **MCP-OP-EDIT-030**: When `edit_clojure` or the compact `edits` branch of `apply_clojure_changes` succeeds, it shall project the canonical effect identity derived by the common transaction compiler, including for generated closed-relation edits, without using that identity as receipt, retry, write, verification, or rollback authority ; generic `changes`, programs, extraction, retained basis, planning, CLI, and refused transactions shall preserve their existing result shapes and shall not publish the compact identity in the first slice.
- [x] **MCP-OP-EDIT-031**: When an `edit_clojure` request supplies `create_files`, clj-surgeon shall compile every `{file, content}` pair against the same frozen snapshot as `edits`, `programs`, and `delete_owners`, shall refuse the complete transaction with a typed refusal naming the offending project-relative path when a target path is not a project-relative `.clj`, `.cljs`, `.cljc`, or `.edn` path, escapes the project root, is repeated, or already exists, or when its content does not parse ; it shall admit a create-only transaction, shall write created content verbatim only after every edit has committed and read back, shall remove every file and directory it created when any later stage fails (including receipt-publication failure), and shall publish created files in `read_back_hashes` with a `created` count and a receipt whose inverse deletes them.
- [x] **MCP-OP-EDIT-033**: Until versioned projection work is approved, when a successful `edit_clojure` request contains `create_files`, clj-surgeon shall suppress `canonical_effect_identity` in the terminal receipt. Suppression is intentional and visible: success shall include `canonical_effect_identity` absent and `canonical_effect_identity_suppressed_reason="create-files-present"` until a future versioned identity contract is ratified.
- [x] **MCP-OP-EDIT-034**: For mixed and create-only transactions, if publication to the public receipt channel fails after file writes, clj-surgeon shall atomically rollback all successful edits and file creations, remove created files and all created directories that were newly introduced by the request, and return a typed recovery-required outcome rather than claiming normal completion.
- [x] **MCP-OP-EDIT-035**: After conflict checks and sibling edit commits, clj-surgeon shall create each new file with an atomic create-if-absent publication primitive such that a target path that appears between planning and publish causes a refusal and preserves existing foreign content.
- [x] **MCP-OP-EDIT-036**: Before each create-if-absent publication, clj-surgeon shall revalidate every planned ancestor directory without following newly introduced links (NIO no-follow semantics). Any ancestor that did not exist at planning time, but appears as a symlink, mount hop, or other path that breaks real-path confinement to `workspace_root` shall refuse before any sibling mutation remains committed.
- [x] **MCP-OP-EDIT-032**: When one MCP session commits an `edit_clojure` transaction whose only supplied verb is `create_files`, and that session's immediately previous committed transaction in the same `workspace_root` and inside a ten-minute memo window supplied only edits-side verbs, or the mirror order, clj-surgeon shall publish a `combinable_note` naming the prior `receipt_hash` and stating that one atomic call carrying both edits and `create_files` would have produced one receipt with mutual rollback ; it shall publish no note for a mixed transaction, a repeated shape, a different workspace root, an expired memo, a different session, a preview, or a refused transaction, shall forget the memo when a refusal intervenes, shall bound the memo store and evict the oldest session, shall argue only atomicity and never payload size, and shall never alter `ok`, `committed`, or any other published field.

# #Extraction Planning

- [x] **MCP-OP-PLAN-001**: When `inspect_clojure` receives a valid `plan-extraction` mission, clj-surgeon shall compile the result through the same pure extraction planner used by execution and shall not write or retain mutation authority.
- [x] **MCP-OP-PLAN-002**: When extraction planning succeeds, clj-surgeon shall return the complete bounded structural caller and quoted-Var evidence, exact returned and omitted counts, and no private future-source fields.
- [x] **MCP-OP-PLAN-003**: When extraction planning succeeds, clj-surgeon shall return one ready-to-fill `apply_clojure_changes` call containing the exact planned forms, destination, require policy, workspace root, and frozen source hash while leaving semantic caller decisions to the caller.
- [x] **MCP-OP-PLAN-004**: If a plan-followed extraction supplies a source hash that differs from the executor's fresh source snapshot, clj-surgeon shall refuse before changing any file.
- [x] **MCP-OP-PLAN-005**: When extraction omits aggregate expectations, clj-surgeon shall derive them from the exact forms, guarded caller edits, and affected files ; when explicit expectations are supplied, they remain authoritative and a mismatch refuses.
- [x] **MCP-OP-PLAN-006**: When a remaining source owner will call a moved private form through the destination namespace, extraction planning shall publish that exact form as a required visibility change and shall include it in the snapshot-bound next call without writing source.
- [x] **MCP-OP-PLAN-007**: When extraction apply receives `public_forms`, clj-surgeon shall require every mechanically necessary moved private form, refuse unmoved, already-public, or unsupported declarations, and apply each supported visibility change inside the same parsed, read-back-verified atomic transaction.
- [x] **MCP-OP-PLAN-008**: When extraction apply omits `public_forms`, `caller_changes`, `ignored_caller_files`, and aggregate expectations, and the complete frozen workspace proves that no caller decision remains, clj-surgeon shall derive the required visibility changes and exact counts and commit through the existing extraction transaction in the same request.
- [x] **MCP-OP-PLAN-009**: When extraction apply omits caller decisions and the complete frozen workspace contains any structural or quoted-Var caller candidate, clj-surgeon shall refuse before writing and return the completed snapshot-bound plan plus an exact `genuine_unknowns` vector ; omission shall never account for a discovered caller.
- [x] **MCP-OP-PLAN-010**: When extraction apply explicitly supplies `public_forms` or aggregate expectations, those values shall remain authoritative ; an explicit empty visibility decision or mismatched exact count shall refuse rather than be replaced by mechanical derivation.

# #Exact Repository Verification

These requirements define the project-owned exact-verifier fusion contract.

- [x] **MCP-OP-VERIFY-001**: When an apply request selects `verify="exact"`, clj-surgeon shall resolve only a project-owned `"exact"` profile whose acceptance is `:exact-exit` ; if that profile is absent, process-owned, malformed, or has another acceptance policy, clj-surgeon shall refuse before changing source.
- [x] **MCP-OP-VERIFY-002**: When a project exact profile is validated, clj-surgeon shall require exactly one non-empty string argument vector, no `{files}` placeholder, no hot or cold verifier, and an explicit timeout from 1 through 120000 milliseconds inclusive ; absence or a value outside that range shall refuse before changing source.
- [x] **MCP-OP-VERIFY-003**: When the exact verifier executes, clj-surgeon shall resolve only its executable, preserve every remaining declared argument and its order, use the canonical project root as cwd, inherit the documented server environment with the paved PATH adjustment, and shall not invoke a shell or claim complete environment identity with an external login shell.
- [x] **MCP-OP-VERIFY-004**: When a clj-kondo exact-exit profile executes, clj-surgeon shall not capture or compare a diagnostic baseline and shall not add cache, output, file-scope, or fail-level arguments.
- [x] **MCP-OP-VERIFY-005**: When the exact verifier exits zero after candidate read-back, clj-surgeon shall retain the complete transaction and inverse receipt and return terminal verification evidence containing the project profile name, acceptance policy, stable normalized profile-definition SHA-256, cwd, resolved argv, exit, elapsed time, complete captured-output byte count and hash, and visible-output truncation state ; the selected in-memory profile shall remain execution authority if its project file changes later.
- [x] **MCP-OP-VERIFY-006**: When the exact verifier completes with an ordinary nonzero exit, clj-surgeon shall undo the complete transaction and return the exit, bounded aggregated diagnostics, rollback evidence, and `source_unchanged=true` only when undo read-back succeeds.
- [x] **MCP-OP-VERIFY-007**: If the exact verifier times out, cannot launch, or terminates with a crash-or-signal-style exit, clj-surgeon shall classify the verification as unverified, undo the complete transaction, and return the distinct process outcome plus bounded aggregated diagnostics without claiming an operating-system signal from exit status alone.
- [x] **MCP-OP-VERIFY-008**: If rollback after any exact-verifier non-pass cannot prove restoration of every original and created path, clj-surgeon shall report recovery required and shall not claim `source_unchanged=true`.
- [x] **MCP-OP-VERIFY-009**: When exact verification fails or is unverified, clj-surgeon shall neither auto-fix nor recommend a blind retry ; its remedy shall require correction of the deterministic diagnostics or restoration of verifier authority before a new guarded request.
- [x] **MCP-OP-VERIFY-010**: Before exact-verifier fusion is activated, permanent witnesses shall prove equivalence with the declared external command for canonical cwd, resolved executable, remaining argument order, exit acceptance, and diagnostic meaning across a warning-bearing pass, ordinary lint failure, missing authority, timeout, crash-or-signal-style exit, staged-byte visibility, and complete rollback ; each invocation shall publish its own complete captured-output byte count and hash without requiring identical bytes when verifier output contains nondeterministic timing text, and witnesses shall not claim complete environment identity.

# #Host-Wide Analyzer Admission

- [x] **MCP-OP-ANALYZER-001**: When any Surgeon-owned entrance launches a command whose executable basename is `clj-kondo`, clj-surgeon shall first acquire the shared host admission lock and shall admit at most one such analyzer across threads, JVMs, and repositories.
- [x] **MCP-OP-ANALYZER-002**: When clj-kondo admission waits, lock wait and analyzer execution shall share the caller's existing deadline ; if admission expires, clj-surgeon shall launch no analyzer child and shall report unavailable analyzer authority rather than a semantic diagnostic.
- [x] **MCP-OP-ANALYZER-003**: When admission succeeds, the gate shall make the record-lock descriptor inheritable and exec the resolved analyzer so that the analyzer PID owns authority for its complete lifetime ; clj-surgeon shall record that PID, canonical command CWD, and start time as bounded diagnostic evidence, stale owner text shall grant no authority, and analyzer death shall release the operating-system lock without cleanup by another caller.
- [x] **MCP-OP-ANALYZER-004**: If exact or diagnostic verification cannot obtain clj-kondo admission, the mutation shall follow the existing unverified-verification and rollback law and shall not classify resource unavailability as an ordinary clj-kondo finding.
- [x] **MCP-OP-ANALYZER-005**: Before host-wide admission is installed, permanent witnesses shall prove non-overlap within one JVM and across two processes, bounded waiting, owner-death release, no launch after admission timeout, shared deadline accounting, non-clj-kondo bypass, and compatibility between a JVM-launched gate and the installed direct-shell entrance, including PATH shadowing by that entrance.
- [ ] **MCP-OP-ANALYZER-006**: When a fresh flight-recorder sample is red or critical, or current normalized one-minute load meets the red threshold, the gate shall return typed unavailable analyzer authority before waiting, while waiting, or after lock acquisition, shall launch no analyzer child, and shall record bounded pressure, entrance, scope, CWD, and wait evidence without claiming analyzer causality.
- [x] **MCP-OP-ANALYZER-007**: When analyzer evidence compiles a source mutation, all required analysis shall complete before the first write ; execution shall use exact owners from that frozen plan and shall not reacquire analyzer authority after partial mutation.
- [x] **MCP-OP-ANALYZER-008**: The everyday test runner shall use normalized provenance-bearing analysis fixtures and fake boundary analyzers, while one mandatory sequential analyzer-contract target shall retain real forward-reference, binding-analysis, batched candidate-lint, and diagnostic baseline/future witnesses ; the complete milestone suite shall launch no more than five real analyzers.
- [x] **MCP-OP-ANALYZER-009**: The repository-owned analyzer contract runner may use one internal test-mission lease over the existing physical analyzer gate only when exact owner PID, canonical CWD, scope/profile hash, five-launch count, and five-minute time budget are bounded ; every child shall release admission, each subsequent child shall require a fresh pressure observation taken after the previous child exits, and an interactive waiter shall run before the next mission child. # #Exact Terminal Response

# #Deferred Surface

Transport-level exception envelopes, cancellation, deadlines, queue time
correlation IDs, internal phase telemetry, and CLI/MCP receipt convergence are
outside these requirements. They require their own reviewed intent before this
leaf expands to cover them.

Exact read correction authority, executable retries, explicit clue resolution
and declarative read missions remain deferred. Stateless hash guards and inline
successful-sibling continuation are the active bounded slice ; they preserve
proved read work without granting selector, retry, or write authority.
