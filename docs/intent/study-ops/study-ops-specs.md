# Study operations at the MCP read entrance — specifications

IDs are stable and must not be reused if a requirement is deleted.

## Entrance and operations

- [x] **MCP-OP-STUDY-001**: When a caller submits `inspect_clojure` with top-level `mode="ls-tree"`, clj-surgeon shall scan the requested workspace-confined directory through the one `clj-surgeon.study/ls-tree` kernel and shall return a bounded receipt carrying `dir`, `grep`, `format`, `limit`, `project_count`, `file_count`, `returned`, `omitted`, `truncated`, and either `tree` (text) or `files` (edn); it shall introduce no new public MCP tool.
- [x] **MCP-OP-STUDY-002**: When an `inspect_clojure` request item declares `operation="deps"` with a project-relative `file`, clj-surgeon shall return the intra-namespace call graph produced by `clj-surgeon.study/deps` for that file's snapshot; when the item also declares `form`, it shall return only that owner's adjacency row.
- [x] **MCP-OP-STUDY-003**: When an `inspect_clojure` request item declares `operation="topo"` with a project-relative `file`, clj-surgeon shall return the `sorted`, `cycles`, and `has_cycles?` result produced by `clj-surgeon.study/topo` for that file's snapshot.
- [x] **MCP-OP-STUDY-004**: When an `inspect_clojure` request item declares `operation="ls-deps"` with a project-relative `file` and an exact `form`, clj-surgeon shall return the transitive dependency tree produced by `clj-surgeon.study/ls-deps`; `form` shall be required for this operation.
- [x] **MCP-OP-STUDY-005**: When an `inspect_clojure` request item declares `operation="ls-extract"` with a project-relative `file` and an exact `form`, clj-surgeon shall return the minimal extractable closure produced by `clj-surgeon.study/ls-extract`; `form` shall be required for this operation.

## Confinement

- [x] **MCP-OP-STUDY-006**: If an `ls-tree` request supplies a `dir` that is absolute, contains a parent-traversal or NUL segment, resolves outside the canonical workspace root through a symlink, does not exist, or is not a directory, clj-surgeon shall refuse before scanning with a typed `error_type`, `source_unchanged=true`, `read_complete=false`, and an executable `next_call`; it shall publish no file listing, no host-absolute path, and no partial tree.

## Bounding

- [x] **MCP-OP-STUDY-007**: Every study receipt shall be bounded to `limit` payload characters, refusing above 16384; the default shall be 8192 for `mode="ls-tree"` and 4096 for an atomic study operation (**AMENDED 2026-09-04, O2/PF-5**: the shared 4096 was calibrated on the atomic operations, and `format="text"` — the rendering `ls-tree` selects by default once `grep` is present — returned 2 of the 10 files of a real ten-file `src` at it, so a caller's first call answered almost nothing; a table of contents that needs a second call is not a table of contents); when the complete result does not fit, clj-surgeon shall return whole rows only, set `truncated=true`, report `returned` and `omitted`, and set `read_complete=false`; it shall never return a partially serialized row or a cut payload. It shall emit an executable `next_call` only while raising `limit` can still advance the receipt; at the maximum limit it shall emit `next_action="narrow_scope"` and a remedy and no executable call, because a narrower scope is a caller judgment and a continuation identical to the call just made is a loop. This applies equally to an atomic result that refuses with `study-output-limit` rather than truncating, and to an `ls-tree` refusal whose proposed continuation would repeat the request just made.

## One kernel

- [x] **MCP-OP-STUDY-008**: For every study operation, on identical bytes and an untruncated receipt, the MCP receipt payload shall equal the JSON normalization of the `clj-surgeon.study` kernel result, which shall equal what the CLI handler returns; no entrance shall hold a second implementation of any study operation.

## No write authority

- [x] **MCP-OP-STUDY-009**: The MCP read entrance shall expose no write operation. `:mv`, `:rename-ns!`, and `:fix-declares!` shall not appear in the `inspect_clojure` operation vocabulary or mode vocabulary, `inspect_clojure` shall remain annotated read-only, and a study request shall leave every file byte unchanged.

## Refusals

- [x] **MCP-OP-STUDY-010**: If a `deps`, `ls-deps`, or `ls-extract` request names a `form` that is not a top-level owner of the file, clj-surgeon shall refuse that request with `error_type="study-form-not-found"`, the bounded factual owner vocabulary, and an executable `next_call` whose `form` hole must be replaced; the owner list shall carry no selection authority. If the requested file cannot be parsed, clj-surgeon shall refuse with the kernel's typed parse error rather than an empty result.

## Safety of discovery

- [x] **MCP-OP-STUDY-013**: When `ls-tree` discovery reads a `deps.edn`, `bb.edn`, or `project.clj` to learn a project's source paths, clj-surgeon shall READ that file and shall never evaluate it: EDN build files shall be read with `clojure.edn/read-string`, `project.clj` shall be read with `*read-eval*` bound false, and a build file that cannot be read shall fall back to the documented default source paths without executing any part of it.

- [x] **MCP-OP-STUDY-014**: `ls-tree` discovery shall be confined to the canonical realpath of the scanned directory: every path a directory walk produces shall be dropped unless its own realpath resolves inside that root, and every source directory a build file declares shall be lexically normalized and dropped unless it stays inside that root; a directory that cannot be canonicalized shall refuse with `error-type=:dir-not-found` rather than scan. No file outside the root shall appear in `tree`, `files`, or `file_count`, and no such file shall be opened. **EXTENDED by MCP-OP-STUDY-035 (2026-09-03):** the `-P` walk that makes this true also makes a declared `:paths` entry that IS a symlink yield nothing; that skip is now named in the receipt rather than left as a silent false negative.

- [x] **MCP-OP-STUDY-015**: `ls-tree` shall bound the work it does BEFORE any receipt bound applies. Discovery shall list file names without parsing any file and shall refuse with `error_type="study-tree-too-large"` — naming the discovered count, the cap, and the remedy — when it finds more than `max_files` source files (default 2000, caller-settable up to 20000). The claim that this bounded discovery's work was FALSIFIED: the cap was compared against a count already materialised in full, and overlapping projects walked and counted the same files repeatedly; MCP-OP-STUDY-021 states what the cap must actually do. Outlining shall then parse only as far as the receipt's byte budget reaches, in bounded-parallel batches, so the number of files parsed never exceeds the number returned by more than one batch.

- [x] **MCP-OP-STUDY-016**: Every study receipt shall report the source it actually read and shall keep every key it returns inside `limit`. `source_character_count` shall equal the character count of the file snapshot the request was evaluated against, and shall be a REPORT only — the falsified half of this requirement was the assumption that a count of source READ could also serve as the charge against a budget on source RETURNED; see MCP-OP-STUDY-020. `topo` shall count and budget `cycles` alongside `sorted`, so an all-cycle file reports a non-zero `form_count`; `ls-extract` shall charge its closure's non-`forms` keys to the same budget; and an atomic single-row result (`deps` with `form`, `ls-deps`) that does not fit shall refuse with `study-output-limit` rather than be returned over budget.

- [x] **MCP-OP-STUDY-017**: The `format="text"` payload's trailing total line shall agree with the receipt it travels in: it shall report the true discovered `file_count`, and when the receipt is truncated it shall also report how many files were shown and how many omitted, and shall omit the form total, which is unknowable for files that were never parsed. A complete receipt's total line shall be unchanged.

- [x] **MCP-OP-STUDY-018**: A bounded row payload shall charge the serialized array's own brackets and separators to `limit`, so a kept payload is never larger than the limit it was bounded by; the empty array's two characters are the floor below which no bound can go.

- [x] **MCP-OP-STUDY-019**: The `ls-tree` branch shall validate its own parameters server-side, because it never reaches `validate-inspect-params`. An unrecognized top-level key shall refuse with `error_type="unknown-parameter"` naming the unknown keys and the complete vocabulary; a `format` outside `{names, text, edn}` shall refuse with `error_type="invalid-format"` naming what was rejected and what is supported, and its continuation shall drop the rejected value rather than echo it.

## Budgets, discovery, and continuations (re-review round three)

- [x] **MCP-OP-STUDY-020**: The per-request source budget shall be charged against the source a result RETURNS, never against the source it read. `outline` and every study operation return a derived structure and no source, so they shall succeed with `ok=true` and `read_complete=true` on a file of any size the per-request RESULT budget can carry, while still reporting `source_character_count` as the characters read (MCP-OP-STUDY-016). A result that does return source shall still refuse when that returned source exceeds the budget. **AMENDED by MCP-OP-STUDY-034 (2026-09-03):** "return a derived structure and no source" was false of `outline`, which returns each form's arglist verbatim from the file; the charge was zero only because the budget's walk knew one key name.
- [x] **MCP-OP-STUDY-021**: `ls-tree` discovery shall identify a source file by its canonical path and shall hand each distinct file to exactly one project, so an overlapping declaration (`:paths ["."]` beside a nested project, or many siblings each declaring `:paths [".."]`) is counted once, listed once, and its directory walked once per scan. `max_files` shall be applied DURING accumulation and shall stop the walk: no candidate after the one that passes the cap shall be listed, and a discovery halted with candidates remaining shall say its reported count is a floor. **AMENDED by MCP-OP-STUDY-033 (2026-09-03):** "during accumulation" was implemented as per-CANDIDATE, not per-file — a single project of 3000 files at `max_files 10` was walked and canonicalised whole before its count met the cap, and then reported 3000 as an exact total. The bound is now per file, so this requirement's "no candidate after the one that passes the cap" is the weaker half of what holds. `total-file-count` shall count distinct files.
- [x] **MCP-OP-STUDY-022**: `ls-tree` shall compile `ns_grep` ONCE, under a guard, and shall refuse an uncompilable pattern with `error_type="invalid-ns-grep-pattern"`, `read_complete=false`, `source_unchanged=true` and a next action, never a raw regular-expression exception. It shall type-check `dir`, `grep`, `ns_grep`, `format`, `limit`, and `max_files` server-side beside the `format` enum, refusing a wrongly typed value with `error_type="invalid-parameter-type"` naming the parameter, the expected type and the type received, and a continuation that drops the rejected value. No refusal shall place a value in the receipt that contradicts the tool's own output schema.
- [x] **MCP-OP-STUDY-023**: An `ls-tree` continuation shall carry every field the request carried unless an override replaces it, `limit` included, so that the identical-call check of MCP-OP-STUDY-007 holds whether or not the caller spelled a value that equals a default.
- [x] **MCP-OP-STUDY-024**: A `format="text"` per-project header shall report the files DISCOVERY found for that project, not the subset the receipt carries: `── beta (50 files, 71 forms)` when it carries them all and `── beta (50 files; 9 shown)` when it does not, the form total omitted because it is unknowable for files never parsed. Every project counted by `project_count` shall appear in the body, including one the byte budget reached no file of, which reads `0 shown`.
- [x] **MCP-OP-STUDY-025**: An `ls-tree` refusal that rejects a caller-supplied `grep` or `ns_grep` shall name the rejected pattern and shall serve a continuation with that pattern REMOVED — the treatment `invalid-format` already had — while keeping the scope the caller chose. A continuation that hands a rejected value straight back is an executable call that fails identically.
- [x] **MCP-OP-STUDY-026**: An `ls-tree` refusal message shall name the directory the CALLER asked for — the scan-relative `dir` — never the canonical scan root. No `ls-tree` refusal's `error` shall contain a host-absolute path, which MCP-OP-STUDY-006 already forbids publishing; the CLI refusal golden is therefore frozen byte-for-byte with no workspace-root substitution.
- [x] **MCP-OP-STUDY-027**: An atomic study result shall serve an executable continuation only while raising `limit` can actually SUCCEED: `required` must fit under the study ceiling as well as exceed the current limit. A result needing more characters than the ceiling shall return `next_action="narrow_scope"`, a remedy, and no executable call, at any limit.
- [x] **MCP-OP-STUDY-028**: The JVM read entrance shall outline through the bounded-parallel strategy `clj-surgeon.parallel/bounded-map`, and that shall be pinned by a witness that fails when the entrance parses through serial `map`. The strategy shall change only the order work is done in: for every partial `n`, `outline-take` under `bounded-map` shall equal `outline-take` under `map`.
- [x] **MCP-OP-STUDY-029**: Every command clj-surgeon RENDERS for a caller to run shall end option parsing with `--` before a caller-supplied pattern, exactly as the commands it runs itself do; a pattern is never handed back spelled as a flag.
- [x] **MCP-OP-STUDY-030**: Each `ls-tree` format's empty-receipt FLOOR shall be documented and asserted: `names` and `edn` bottom out at the empty array's two characters (MCP-OP-STUDY-018), and `text` bottoms out at its own trailing total line — `36 + 2 x digits(file_count)` characters, since `shown` is 0 and `omitted` equals `file_count`, so the count is spelled twice: 38 for a one-digit tree, 40 for two, 42 for three, 46 at the 20,000 ceiling — which is larger than `limit 1` by construction because a receipt that showed nothing must still report how much it omitted. **SUPERSEDED in part by MCP-OP-STUDY-032 (2026-09-03):** "its own trailing total line" was written as if the floor held no project headers, which contradicted MCP-OP-STUDY-024's "every project counted by `project_count` shall appear in the body" — and the implementation followed this clause, rendering the `returned=0` receipt from an empty project vector. STUDY-024 wins: the `text` floor is the trailing total line PLUS one `0 shown` header per project whenever discovery found more than one. The single-project floor is unchanged, which is why no witness caught the contradiction. The `target` prune rule shall be documented as matching by NAME at any depth — hiding a real source namespace under `src/app/target/` as well as compiled output under `target/` — and a frozen golden shall hold both cases.

## Match cost, empty receipts, and unresolved paths (executed re-review round four)

- [x] **MCP-OP-STUDY-031**: While an `ls-tree` scan filters by a caller-supplied `ns_grep`, when the regular-expression engine's character reads across the whole filtering pass exceed `ns-grep-scan-budget` — the per-file term of `ns-grep-match-steps-per-file`, evaluated at the length of the LONGEST relative path the pass will test, multiplied by the number of files discovery found — clj-surgeon shall abandon the scan and refuse with `error_type="ns-grep-match-budget-exceeded"` — naming the rejected pattern and the exhausted budget, `read_complete=false`, `source_unchanged=true`, no file opened, and a continuation that drops `ns_grep` while keeping the caller's `dir`. The budget shall be enforced INSIDE the match, by counting the characters the engine reads, because no wall-clock deadline can interrupt a running `java.util.regex` matcher; and it shall be pooled across the pass rather than spent per match, so the bound is on the scan and not on one subject. **AMENDED (2026-09-03, round-4 re-review fix 1):** the original per-file term was a flat constant calibrated on this repository's own ~36-character paths; `.*a.*b.*`-shaped patterns cost quadratically in subject length, so the flat term refused an honest pattern over an ordinary monorepo tree with materially longer paths. The per-file term shall never fall below a floor calibrated on short paths (`ns-grep-match-steps-floor`) and shall grow at least quadratically with the longest relative path length in the pass, so a call is never charged less than the floor and never miscalibrated against paths longer than this repository's own. A pattern whose match costs exactly the budget shall be answered; the next character read shall refuse.

- [x] **MCP-OP-STUDY-032**: While an `ls-tree` `format="text"` receipt carries no file at all, when discovery found more than one project, clj-surgeon shall still render one `── <project> (<n> files; 0 shown)` header for every project `project_count` counts, above the trailing total line. The empty receipt shall be rendered from the projects discovery found, never from an empty project vector, so the smallest receipt is bound by the same rule as every larger one.

- [x] **MCP-OP-STUDY-033**: While `ls-tree` discovery accumulates candidate projects, when a single candidate's directory walk reaches `max_files + 1` distinct source files, clj-surgeon shall stop that walk there rather than materialise the candidate, so the canonicalisation syscalls one refusal costs are proportional to the cap and not to the tree. A refusal whose count was taken where a walk stopped shall carry `observed_at_least=true` and shall say "at least" in its message, because that count is a floor and not the tree's size.

- [x] **MCP-OP-STUDY-034**: The per-request source budget shall charge every string of VERBATIM file source a result returns, under whichever key it returns it — `outline`'s per-form arglists included — and the set of such keys shall be enumerated in one place rather than assumed from a naming convention. A request whose verbatim source exceeds the budget shall refuse with `error_type="inspect-output-limit"` and `scope="request_source"`, never be truncated and never be scored as a result overrun, because a caller cannot make an outline smaller and the two scopes name different remedies.

- [x] **MCP-OP-STUDY-035**: While `ls-tree` discovery resolves a project's declared source directories, when one of them is itself a symbolic link — which the `-P` walk required by MCP-OP-STUDY-014 will not descend — clj-surgeon shall record it as a typed skip and shall report it in the receipt as `paths_unresolved`, each entry naming the project, the declared path, and the reason. The skip shall be reported on a SUCCESSFUL receipt as well as on a refusal, and a `no-clojure-files` refusal caused by such a skip shall carry a remedy naming the path rather than "scan a directory that contains Clojure sources".


## Table-of-contents rendering

- [x] **MCP-OP-STUDY-011**: `ls-tree` shall support `format="names"`, whose per-file entry shall be exactly `{file, ns, form_count, line_count}` and no other key; when an `ls-tree` request declares no `format`, clj-surgeon shall render `format="names"` by default when `grep` is absent from the request, and `format="text"` by default when `grep` is present; `format="text"` and `format="edn"` shall remain available on explicit request regardless of `grep`.
- [x] **MCP-OP-STUDY-012**: `ls-tree` shall support an `ns_grep` parameter that filters files by each file's project-relative path (which the Clojure require convention keeps in lockstep with its declared namespace — path segment vs. ns segment, `_` vs. `-`), never by file contents; it shall compose with `grep` (an existing content match) to narrow further, and shall be documented as distinct from `grep`, which matches file bodies via ripgrep and can match comments, strings, and unrelated substrings.

## One call must be sufficient in the text a client renders (O2 / PF-5, 2026-09-04)

- [x] **MCP-OP-STUDY-036**: An `ls-tree` response's TEXT content shall carry the rows the receipt carries, not a header describing them. For `format="text"` it shall render the bounded `tree` verbatim — the per-project headers, and per file the project-relative path, its line and form counts, its `ns`, its requires summary, and one row per named top-level form with that form's arglist and line span; for `format="names"` and `format="edn"` it shall render the bounded `files` payload as compact JSON. The rows shall be exactly the bounded payload, so the text is bounded by the same `limit` and the two renderings can never disagree. When the receipt is truncated the text shall additionally spell, in the text, the executable continuation whenever `next_call` exists — as `next call: <tool> <key>=<value> …` in a fixed argument order until MCP-OP-STUDY-045 SUPERSEDED that clause (2026-09-04) with the verbatim compact JSON argument object, and otherwise the `remedy`; a receipt at the ceiling shall spell the remedy and no continuation, because a continuation identical to the call just made is a loop. *Field evidence (E6-Lb, PF-4, `/home/forge/tmp/arms/e6/pf4/c2.json`): `content[0].text` was 146 characters — a header, a truncation notice, and an arrow — while 14,956 characters of table of contents sat in `structuredContent.tree`. A text-only client was handed the shape of an answer, none of its content, and no way to know what to send next.*

- [x] **MCP-OP-STUDY-037**: One `ls-tree` call at the default limit shall be sufficient for a small tree: a ten-file, thirty-form tree shall return `read_complete=true` with every one of its namespaces and at least twenty-two form rows inside 8 KB of TEXT content, without the caller naming a limit, a format, or a continuation. The default that makes this true shall be a named constant the receipt reports back, and shall be witnessed against a tree the previous default truncated, so the raise is load-bearing rather than decorative.

- [x] **MCP-OP-STUDY-038**: The `limit` ceiling shall remain a typed boundary rather than a target: a tree whose complete rendering fits shall return complete, and the next file over shall return `truncated=true`, `read_complete=false`, `next_action="narrow_scope"`, and a remedy naming what to do instead — witnessed AT the boundary, on N files that fit and N+1 that do not, never asserted about the constant alone.

## The public MCP result is text and structure together (O2 round 2, 2026-09-04)

- [x] **MCP-OP-STUDY-040**: The COMPLETE public MCP result of `inspect_clojure` — the `content[0].text` block and the `structuredContent` receipt together, in the shape a client is handed — shall never exceed the declared public output budget, in EVERY mode. A result that would exceed it shall first be bounded by a typed truncation of the text: the text shall render the longest WHOLE-ROW prefix that fits (whole rendered lines for `format="text"`, whole payload entries for `format="names"`/`"edn"`, never a cut mid-row and never a cut mid-JSON-object), shall declare in the text how many of how many rows it rendered, shall name `structuredContent` as the place the complete receipt is, and shall carry the remedy. A receipt whose `structuredContent` ALONE exceeds the budget shall be a typed refusal naming the measured bytes, the budget, the remedy, and the next action, because no rendering choice can save it. The fit shall measure the FINAL published envelope — the result the publisher publishes, with its clock and in whatever shape its envelope takes — and nothing shall be added to the result after the fit, so no reserve is held back and the fit's target is the declared budget itself; a substitute the gate builds from scratch shall carry the envelope of the result it replaces. *Field evidence (Sol O2 round-3 review, 2026-09-04, section 5): the fit ran before the clock stopped, measured with `elapsed_ms` zeroed, and held back a 64-byte `publish-reserve` to cover the difference — but the envelope's clock contract accepts any finite non-negative number and a `1.0E308` interval renders 309 characters, so four near-boundary receipts published 32,860 / 32,841 / 32,912 / 32,996 bytes against the 32,768-byte budget. A constant taken from one observation is not a bound on the publisher.* *Field evidence (O2 re-review, 2026-09-03): rendering the `ls-tree` payload into the text — the MCP-OP-STUDY-036 fix — roughly DOUBLES the result on the wire; `ls-tree dir=src grep=defn limit=16384` over a real 25-file tree measured 34,042 bytes against a declared 32,768, and `enforce-result-budget` covered only `prepare-change`, `basis-view`, and `plan-extraction`, so `ls-tree` and every typed study read fell to `:else raw-result` and nothing refused, trimmed, or warned. A budget three of nine modes obey is a number in a docstring.*

- [x] **MCP-OP-STUDY-041**: EVERY `inspect_clojure` mode's TEXT block shall carry the rows its receipt carries, in receipt order, and never a count of them: `deps` and `ls-extract` shall render each form with its type, its line, and its dependencies; `topo` shall render the sorted order and every cycle member; `ls-deps` shall render every node of its tree depth-first; `outline` shall render every form with its line range and its arglist; `forms` and `match` shall render each row's verbatim source when the receipt returns it; `xray` shall render its value. The rows shall come from ONE per-mode enumeration that the renderer prints and a witness can compare against the receipt, so a rendered row set can never disagree with the receipt's. The set of modes this holds for shall be derived from the tool's PUBLISHED schema rather than from a hand-written list, and every published `operation` and every published `mode` shall be either witnessed rendering its rows or explicitly classified as witnessed elsewhere, so an operation or mode added to `inspect_clojure` cannot reach a client rendering a count. The evidence shall be bounded — rows dropped WHOLE and only from the tail — and a text block that dropped a tail shall say how many of how many rows it rendered, shall name where the complete receipt is, and shall never claim `terminal evidence · read_complete=true · next action none`. A result whose receipt is truncated shall spell its `next_call` in the text, as arguments a caller can retype, or name where it lives when it is too large to retype. **RETIRES the "source-free companion" contract (2026-09-04):** the rule that MCP `content` carries "only a concise human summary", stated in `docs/plans/typed-mcp-inspect-entrance.md` ("Successful result" and "deterministic normalization and concise source-free summaries"), in `docs/high-level-design.md` ("concise human presentation"), and in `README.md` ("the bounded text result is an ordinary transcript summary"), is retired by this intent and by MCP-OP-STUDY-044. It never carried an EARS id, which is exactly why round two could reverse it in code and tests while every one of its three prose statements stood; all three now carry a dated retirement notice naming the superseding ids, and `the-retired-source-free-companion-contract-stays-visibly-retired` fails if one of them is quietly restored or the notice is quietly removed. The reversal is a real behavioural change for a consumer that logged or displayed only the formerly source-free text channel. *Field evidence (O2 re-review, 2026-09-03): O2 closed this on `ls-tree` and left it standing on eight modes from one function — `request-1: deps · 27 of 27 rows` in 241 characters of text with all 27 rows in `structuredContent` only; `outline` naming the first and last of 28 forms; `forms` rendering "131 source characters" instead of the 131 characters; `match` reporting `7 matches`, dropping 3,529 characters of match source, and still saying the read was terminal.*

- [x] **MCP-OP-STUDY-042**: EVERY `inspect_clojure` refusal's TEXT block shall name, in the text, what `structuredContent` names: its `error_type` and its `reason` where the two differ, the `:error` cause string verbatim, the value of every enumerated refusal detail a caller must act on (`path`, `missing`, `unknown`, `supported`, `expected`/`actual`, `maximum`, `scope`, `required`/`limits`, and the rest of an enumerated set a new field is added to the day it is created), the `available_owners` the receipt lists — bounded, and declaring how many of how many it printed — the `remedy` when the receipt carries one, and the `next_action` or the spelled `next_call`. The sentence explaining how to USE a list of owners shall print under exactly the condition that prints the list, never under a different one. The default shall be to RENDER: every key a refusal carries that is not named in an explicit set of structurally-rendered keys shall print as a bounded `key: value` line, so a NEW refusal field travels into the text the day it is added and only a deliberate, reviewable entry in that set can keep it out. *Field evidence (O2 re-review, 2026-09-03): `ls-deps form=no-such-form-xyz` carried the cause and 27 `available_owners` in `structuredContent`; the TEXT carried neither and printed "All listed owners are real snapshot evidence; ranking is non-authoritative…" over a list of nothing, because the list sat inside a `diagnostic?` guard a study refusal never satisfies while the sentence was guarded only by the list being non-empty. The generic branch never printed `:error` for any mode: `missing-fields`, `unknown-fields`, and `invalid-xray-expression` all reached a client as a category name and an arrow.*

- [x] **MCP-OP-STUDY-044**: An `inspect_clojure` result's `content[0].text` shall be a SUPERSET of every `structuredContent` leaf value, in EVERY mode and for every refusal: for each leaf of the receipt in the JSON shape a client is handed, the text shall carry that value verbatim — a string as its own characters (every non-blank line of a multi-line string), and a number, boolean, or rendered keyword as the characters `structuredContent` spells it with. The rows a mode renders structurally shall satisfy it where they can, and EVERY remaining leaf shall print as a bounded `path: value` line naming the JSON pointer it is read back from, so a receipt field added tomorrow travels into the text the day it is added. There shall be exactly ONE exclusion mechanism: an explicit, enumerated, frozen set — never an implicit projection of selected row fields, never a shape the receipt walker declines to yield, and never a value the carriage predicate declares rendered without looking at the text — and each member shall carry, at its definition, the reason it is kept out. An EMPTY map or vector shall be a leaf. A leaf whose value is indistinguishable from absence in a text block — `null`, `{}`, `[]`, and a blank string — shall be carried by its LABEL: it shall appear as `<json pointer>=<spelling>` (`results=[]`, `probe.nil_value=null`, `probe.blank=""`), because `""` matches at every index of every text and `{}` matches any object rendering, so nothing else about such a leaf can be found and attributed to it. One predicate shall serve both the renderer that guarantees the property and the witness that checks it, so the two cannot drift; and the witness shall walk the parsed `structuredContent` of every published mode over one fixture. Every rendering allowance shall be DERIVED from what the public output budget leaves after the envelope, never a fixed constant: the complete rendering shall travel whenever it fits, and an elision shall happen only when the complete rendering would not. Where the output budget forces the text to drop rows or facts, the text shall declare how many of how many it rendered, shall NAME each dropped leaf by its JSON pointer, shall name where the complete receipt is, and shall never read as terminal. *Field evidence (Sol O2 round-3 review, 2026-09-04, sections 2 and 4): the frozen set `#{:workspace_root}` was one of THREE exclusion mechanisms and the only one written down — `receipt-leaf-pairs` yielded no leaf at all for `{}` or `[]` (`empty_map spelling="{}" present=false label_present=false`), and `leaf-rendered?` returned true for `null` and blank strings without inspecting the text; the product predicate reported zero misses only because it shared both loopholes with the renderer. And the refusal renderer spent a FIXED 8,192-character fact allowance regardless of the budget, so a 21,847-byte result under a 32,768-byte budget dropped its `error`, its `path` and four more leaves with 10,921 bytes unspent — `uncarried_count= 6 … hypothetical_one_copy_public_bytes= 31869 hypothetical_fits= true`.* *Field evidence (Sol O2 round-2 review, 2026-09-04, section 3): the round-2 renderer projected SELECTED row fields, which is enough for the narrower row strings MCP-OP-STUDY-041 asserts and is not the criterion — `forms` dropped every `source_anchor` range and both hashes (12 row leaves), `outline` dropped every `platforms` entry (28), `match` dropped every `hash` and `preorder` (20), `ls-deps` dropped every `leaf?` (18), and all nine modes dropped their top-level metadata: 182 uncarried leaves in total, not one of them named anywhere as deliberately excluded.*

- [x] **MCP-OP-STUDY-045**: Wherever an `inspect_clojure` text block spells a continuation, it shall spell the VERBATIM executable request — `next call: <tool> <compact JSON argument object>` — and that object shall parse to exactly the arguments `structuredContent`'s `next_call` carries, in EVERY mode that emits one, so a caller can paste the line and replay it. **SUPERSEDES the `next call: <tool> <key>=<value> …` clause of MCP-OP-STUDY-036 (2026-09-04):** the fixed-argument-order prose rendering was retypeable guidance rather than an executable request, and it made `ls-tree` the one mode whose continuation could not be pasted. - [x] **MCP-OP-STUDY-046**: The set of `inspect_clojure` refusal reasons shall be ENUMERATED in one place and enforced where refusals are CONSTRUCTED — a refusal whose reason is absent from the enumeration shall be refused at construction, not merely detected — and the witness shall derive the set it checks FROM THE RUNTIME, driving one fixture per reason through the public entrance and asserting that the set of reasons OBSERVED equals the set enumerated. ## Proving the connection, per arm

- [x] **MCP-OP-STUDY-039**: A clj-surgeon MCP server shall emit one `session.start` telemetry event the FIRST time it serves each distinct workspace root, carrying a content-free `workspace_key` (a stable digest prefix of the canonical root) in every telemetry mode, the `workspace_root` itself only in `:full` mode, and a `client_run_id` when the caller supplied one. `server.start` records that a PROCESS started and `tool.call` records that SOME caller called; neither distinguishes one client session from another when one server serves several, so an adoption number measured against such a server is credible rather than proven. *Field evidence (E6-Lb): three free-choice arms shared one server on 7909; their telemetry held only `server.start`, so a silent connection failure and a deliberate decline were indistinguishable in the record.*

- [x] **MCP-OP-STUDY-043**: The identity of a client session shall be the PAIR (workspace root, client run), never the root alone: `session.start` shall be emitted once per distinct pair in a server process, so two arms sharing one worktree and one client reconnecting each leave their own event.
